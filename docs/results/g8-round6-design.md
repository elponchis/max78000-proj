# 라운드 6 설계 — 로그를 어떻게 되찾을 것인가 (설계만, 2026-09-29)

**전제**: `g8-round5.md` 4.5절의 가설 — "대역 분해는 NPU 로 옮겼고(D-1),
남은 격차는 거의 로그 압축이다" — 가 `①-log72` 로 확정된 경우.

⚠️ **log72 결과를 보기 전에는 착수하지 않는다.** log72 가 `①-cbrt` 쪽에
머물면 원인이 로그 법칙이 아니라 다른 것이고, 아래 설계는 전제가 무너진다.

두 안은 **서로 배타적이지 않다.** (a) 는 로그를 NPU 안으로 넣으려는 시도이고
(b) 는 로그가 하는 일 중 **음량 불변성만** CPU 에서 싸게 사 오는 우회로다.
논문에는 둘 다 "가속기 제약 아래 압축을 되찾는 두 경로" 로 대조해 실을 수 있다.

# (a) NPU 안에서 로그 근사 — 구간선형 오목 함수

## a.1 구성

로그는 오목(concave)이다. 오목 구간선형 함수는 **기울기가 단조 감소하는
ReLU 의 음의 가중합**으로 정확히 쓸 수 있다.

```
f(v) = a·v − Σ_k c_k · ReLU(v − t_k)        c_k > 0,  t_1 < t_2 < ... < t_K
```

`t_k` 를 지나면 기울기가 `c_k` 만큼 줄어든다. `t_k` 를 로그 곡선의 마디에
두고 `c_k` 를 맞추면 로그를 근사한다.

MAX78000 지원 연산만으로 만들면 이렇게 된다 (D-1 의 1층 뒤에 삽입):

| # | 층 | 연산 | 채널 | 하는 일 |
|---|---|---|---|---|
| L0 | `voice_conv1` | Conv1d k=1 + **Abs** | 128 → 100 | 대역 크기 (현행 D-1) |
| **La** | **knot** | **Conv1d k=1 + ReLU**, per-channel bias | **100 → 100K** | `ReLU(v_c − t_k)` |
| **Lb** | **sum** | **Conv1d k=1, 활성화 없음** | **100K → 100** | `a·v − Σ c_k·(...)` |
| L1.. | `voice_conv2` 이하 | 현행 그대로 | 100 → 96 … | |

- `La` 의 가중치는 **블록 대각**이다: 출력 `(c,k)` 는 입력 `c` 만 본다.
  나머지는 0 으로 학습 시작하고, 학습으로 풀어 줄지(자유롭게) 고정할지는
  선택이다. 고정하려면 마스킹이 필요하고 ai8x 에 그 기능이 없다 →
  **자유롭게 두고 초기화만 블록 대각**으로 한다.
- `Lb` 는 `a·v` 항을 위해 `La` 의 첫 K 채널 중 하나를 `t=0` (항등)으로 둔다.
- `t_k` 는 **출력 채널 바이어스**다 → `--use-bias` 가 필요하다.

⚠️ **왜 depthwise 를 못 쓰는가**: MAX78000 은 depthwise separable conv 를
지원하지 않는다 (CLAUDE.md 3장, MAX78002 에서 추가). 채널별 독립 연산을
full 1×1 conv 로 흉내 내야 하므로 가중치의 99% 이상이 0 인 낭비가 생긴다.
**이 낭비 자체가 "가속기 제약이 파이프라인 설계를 강제한다" 는 논문 주장의
사례**라서, 비용을 숨기지 말고 그대로 싣는다.

## a.2 비용 — 442KB / 512KB 안에 들어가는가

`K` = 마디 수. 현재 모델은 가중치 165,376 B (37.4%).

| K | La 가중치 | Lb 가중치 | 추가 | 총계 | 442,368B 대비 |
|---:|---:|---:|---:|---:|---:|
| 2 | 100×200 = 20,000 | 200×100 = 20,000 | 40,000 | 205,376 | **46.4%** |
| 3 | 30,000 | 30,000 | 60,000 | 225,376 | **51.0%** |
| **4** | **40,000** | **40,000** | **80,000** | **245,376** | **55.5%** |
| 6 | 60,000 | 60,000 | 120,000 | 285,376 | 64.5% |
| 8 | 80,000 | 80,000 | 160,000 | 325,376 | 73.6% |

전부 들어간다. **K=4 (55.5%) 를 기본으로 제안**한다 — 로그를 4구간 선형으로
근사하면 42dB 구간에서 오차가 작고, 1.5× 채널 스윕(80.6%)과도 공존한다.

**바이어스 메모리**: `La` 출력이 100K 개이고 각각 바이어스가 필요하다.
MAX78000 의 바이어스 메모리는 **2,048 B 전부**다 (합성 로그 확인).

| K | La 바이어스 | 2,048B 대비 |
|---:|---:|---:|
| 4 | 400 | 19.5% |
| 8 | 800 | 39.1% |
| **20** | **2,000** | **97.7% ← 상한** |

K=4 는 여유롭다. ⚠️ 단 `voice_conv1` 등 다른 층도 bias 를 켜면 함께 먹는다
(9층 전체 bias ≈ 637 B). K=4 + 전 층 bias = 1,037 B → 50.6%. 괜찮다.

**데이터 메모리**: HWC 는 **채널당 8,192 px** 가 한계다 (채널 수 무관).

| 텐서 | 채널 × 길이 | 채널당 px | 총 바이트 |
|---|---|---:|---:|
| L0 출력 | 100 × 128 | 128 | 12,800 |
| **La 출력 (K=4)** | **400 × 128** | **128** | **51,200** |
| Lb 출력 | 100 × 128 | 128 | 12,800 |

채널당 128 px 는 한계의 1.6% 다. 핑퐁 버퍼 기준 동시 최대는
`La(51,200) + Lb(12,800) = 64,000 B` 로 512KB 의 **12.5%**. 여유롭다.

**연산량 — 여기가 진짜 비용이다.**

| | MAC |
|---|---:|
| 현행 전체 | 8,341,248 |
| La (K=4) | 100×400×128 = 5,120,000 |
| Lb (K=4) | 400×100×128 = 5,120,000 |
| **합** | **18,581,248 (2.23배)** |

**추론 사이클이 대략 2.2배 된다** (현행 71,718 → 약 160,000 추정, 100MHz 에서
0.72ms → 약 1.6ms). hop 250ms 의 0.6% 이므로 **실시간 제약에는 여유가 있다**.
그러나 **에너지가 2.2배**가 되므로 G3·G9·G10 의 수치가 전부 바뀐다.
→ 정확도 이득이 이 비용을 넘는지가 채택 기준이다.

⚠️ 위 사이클 수는 MAC 비례 **추정**이다. 확정은 `ai8xize.py` 합성 결과
(`Total ... cycles`) 로 한다 (CLAUDE.md 10장).

## a.3 합성 가능 여부 — 확인해야 할 것 셋

1. **1×1 Conv1d 두 개를 연속으로 놓을 수 있는가.** kws20-v3 yaml 이 이미
   1층에서 `kernel_size: 1` 을 쓰므로 연산 자체는 지원된다. 채널 100→400→100
   의 다중 패스(64 프로세서 초과)가 걸리는지만 보면 된다.
   → `synthesis/safesound-fb-hwc.yaml` 에 두 층을 끼워 `ai8xize.py` 로 확인.
2. **`activate: None` 중간층**. `Lb` 는 활성화가 없어야 오목 합이 보존된다.
   yaml 의 `activate: None` 은 마지막 MLP 에서 쓰고 있으나 **중간 Conv 층에서
   되는지 확인**해야 한다. 안 되면 ReLU 를 두고 **출력에 상수 오프셋**을 주어
   항상 양수가 되게 설계한다 (대역 크기는 비음수라 어렵지 않다).
3. **출력 시프트와 포화.** `Lb` 가 음의 가중합이라 중간값이 int8 범위를
   벗어나기 쉽다. ai8x 의 `output_shift` 로 맞춰야 하고, **QAT 중 포화가
   과하면 근사가 깨진다**. `tools/` 에 활성화 분포 점검을 추가할 것.

## a.4 ★ 가장 큰 위험 — 로그를 **너무 늦게** 건다

L0 의 출력은 이미 **int8** 이다. 즉 대역 크기가 선형으로 int8 양자화된 **뒤에**
로그를 건다. 1 LSB 아래로 내려간 대역은 이미 0 이고, 로그를 걸어도 돌아오지
않는다. 반면 ① 은 **float 로 로그를 건 뒤** int8 로 양자화한다.

→ (a) 가 회복할 수 있는 것은 "1 LSB 위에 남아 있는 값들의 **모양**" 뿐이다.

이 위험이 얼마나 큰지는 라운드 5 가 이미 부분적으로 답한다: `①-cbrt` 가
동적 범위를 24dB 더 담고도 회복하지 못했다 → 손실이 주로 **양자화 바닥**
때문은 아니라는 신호다. 그렇다면 (a) 에도 승산이 있다.

**그래도 사전 확인을 붙인다 (학습 전, 비용 0):**
`①` 의 로그 멜을 취해 **"선형 양자화 → 로그 복원"** 을 시뮬레이션하고
(즉 대역 크기를 int8 로 깎은 뒤 로그를 거는 것), 그 입력으로 ① 모델을
**평가만** 한다. 이 상한이 ① 에 가까우면 (a) 에 승산이 있고, ①-lin 에
가까우면 (a) 는 원리적으로 안 되는 것이다. → `tools/sim_late_log.py`.
**이 확인 없이 학습을 돌리지 않는다.**

## a.5 대안 — 마디를 층이 아니라 **채널 쌍**으로

`La` 의 낭비(99% 0)를 줄이는 방법. L0 를 **100 → 400 채널**로 바로 늘리고
(같은 필터를 K번 복제, 서로 다른 출력 시프트), Abs 뒤에 바로 `Lb` 만 둔다.
- 장점: La 의 5.12 M MAC 이 사라진다 (L0 가 128×400×128 = 6.55 M 로 늘지만
  전체는 더 작다)
- 문제: 마디 `t_k` 는 **Abs 이후의 바이어스**여야 하는데 L0 의 바이어스는
  Abs **이전**에 적용된다. `|x − t|` 는 `ReLU(|x| − t)` 가 아니다.
  → **성립하지 않는다.** 기록만 해 두고 쓰지 않는다.

# (b) CPU 경량 음량 정규화 + D-1

## b.1 발상

로그가 하는 두 일 중 **음량 불변성만** 싸게 산다. 대역 크기를 로그로 바꾸는
대신, **입력 파형의 레벨을 맞춰** 버린다. FFT 가 필요 없으므로 ① 의 전처리
비용(64×512 FFT)과는 자릿수가 다르다.

## b.2 CLAUDE.md 7장 정책 — **개정 완료 (2026-09-29 승인)**

> 정규화는 학습과 펌웨어에 **비트 단위로 같은 구현**일 때만 허용하고,
> **적용 위치(int8 변환 전/후)를 명시**한다.

원래 금지 근거였던 *"실기기 경로에 정규화가 없다"* 는 펌웨어에도 같이 넣으면
사라진다. 금지해야 할 것은 정규화 자체가 아니라 **한쪽에만 넣는 것**이었다.
데이터 의존 전역 통계와 파일 단위 peak 정규화는 **여전히 금지**다 — 펌웨어가
창 하나만 보고 재현할 수 없다.

동시에 잃는 것이 있다:
- `--floor-zero`(int8 0 비율 하한)와 랜덤 게인 ±12dB 의 근거가 바뀐다.
  정규화가 레벨을 맞추면 게인 증강의 역할이 줄어든다 — **빼지는 말고**
  정규화 상한 위/아래 동작을 덮도록 유지한다.
- dBFS 가 절대 레벨을 뜻한다는 성질을 창 안에서는 잃는다. 데이터 준비 단계
  (창 선택·채움)는 정규화 **이전**이므로 그대로다.

## b.2.5 ★ 두 단계로 나눈다 — int8 위의 정규화는 **정밀도를 되찾지 못한다**

`y = sat8(x · g)` 에서 `x` 가 **이미 int8** 이면, 게인은 **양자화 계단을 함께
키울 뿐**이다. 조용한 소리가 int8 로 깎이면서 잃은 정보는 돌아오지 않는다.

```
원본 float  ──to_int8──▶  int8 (계단 1 LSB = -42.1dBFS)  ──×4──▶  int8 (계단 4 LSB)
                              ↑ 여기서 이미 잃었다            ↑ 계단만 커진다
원본 float  ──×4──▶  float  ──to_int8──▶  int8 (계단 1 LSB, 실효 해상도 +12dB)
                                                ↑ 이쪽이어야 정밀도가 산다
```

펌웨어는 `MicReadChunk()` 가 **int16 을 int8 로 줄이기 전**에 정규화할 수 있다
(CLAUDE.md 7장 "실기기 스케일": `sample >> 14` 뒤 `×4/256` 앞). 즉 **실기기는
좋은 쪽을 할 수 있다.** 그런데 **우리 샤드는 int8 로 저장돼 있다.**

→ 그래서 둘로 나눈다.

| 단계 | 무엇을 | 무엇을 검증하나 | 비용 |
|---|---|---|---|
| **1 (지금)** | 기존 int8 샤드 위에서 **2의 거듭제곱 게인 정규화**. 학습·펌웨어 동일 | **음량 불변성 가설만.** 정밀도 이득은 **없다** | 학습 2회 |
| **2 (효과 있으면)** | 샤드를 int16 으로 재생성하고 **int8 변환 전**에 정규화 | 음량 불변성 + **정밀도** | 재집계 + 학습 |

⚠️ **1단계 결과를 "정규화의 효과" 라고 적으면 안 된다.** 정확히는
**"int8 위에서의 음량 불변성만의 효과"** 이고, 정밀도 몫은 빠져 있다.
1단계가 개선을 보이지 않아도 2단계가 실패라고 말할 수 없다 — 반대로
1단계가 개선을 보이면 그건 **하한**이다.

⚠️ 1단계에서 **2의 거듭제곱 게인을 기본으로 쓰는 이유가 하나 더 생긴다.**
int8 값에 2ⁿ을 곱하는 것은 **정확한 시프트**라 반올림 오차가 없다. 임의 게인
(예 ×2.7)은 int8 위에서 반올림 오차까지 얹어 두 번 깎는다. 1단계에서는
2의 거듭제곱만 돌리고, 임의 게인은 2단계로 미룬다.

## b.3 연산 정의 (학습·펌웨어 공통)

```
peak = max |x[n]|                     n = 0..16383,  x 는 int8 파형
g    = clamp( TARGET / max(peak, 1), 1, GMAX )      # 증폭만, 감쇠 없음
y[n] = sat8( round( x[n] * g ) )
```

| 상수 | 제안값 | 근거 |
|---|---:|---|
| `TARGET` | 96 | 풀스케일 127 대비 −2.4dB. 포화 여유를 둔다 |
| **`GMAX`** | **4 (=+12dB)** | **조용한 창의 잡음을 키우지 않기 위한 상한.** 랜덤 게인 범위와 같은 12dB 로 맞춘다 |
| 감쇠 | **하지 않음** (g ≥ 1) | 큰 소리를 줄이면 이미 포화된 정보가 돌아오지 않는다. 줄여야 할 만큼 크면 그건 클리핑 문제이지 정규화 문제가 아니다 |

**1단계에서는 `g` 를 2의 거듭제곱으로 내림한다** — `g ∈ {1, 2, 4}`.

```
g_pow2 = 2 ** floor(log2(clamp(TARGET / max(peak,1), 1, GMAX)))
y[n]   = sat8( x[n] << log2(g_pow2) )        # 시프트. 반올림 오차 없음
```

int8 위에서 곱하는 것이라 **정확한 시프트가 아니면 반올림으로 한 번 더 깎인다**
(b.2.5). 임의 게인 변형은 int16 샤드가 생기는 **2단계로 미룬다.**
6dB 단위라 ±12dB 변동의 대부분을 흡수한다.

**피크 대신 RMS?** RMS 는 과도음(glass, 0.3초)에서 창 대부분이 조용하므로
게인이 크게 잡혀 **피크가 포화**한다. 피크 기준이 안전하다. RMS 변형은
`GMAX` 를 낮춰 따로 볼 수 있으나 우선순위를 뒤에 둔다.

## b.4 M4F 예상 사이클 — 두 번 훑는다

16,384 샘플, Cortex-M4F 100MHz. **전부 추정치다** (CLAUDE.md 10장, 확정은 DWT).

**1패스: 피크 탐색** — int8 배열을 `int32` 로 4개씩 읽어 SIMD 처리.
`__SSUB8`/`__SEL` 조합 또는 단순 언롤 비교.

| 방식 | 샘플당 | 16,384 샘플 |
|---|---:|---:|
| 단순 루프 (`ldrsb`, `abs`, `cmp`) | ~4 cyc | ~65,500 |
| 4배 언롤 + 워드 로드 | ~1.5 cyc | ~24,600 |
| SIMD (`__USUB8`+`__SEL`, 4샘플/명령) | ~0.8 cyc | ~13,100 |

**2패스: 스케일링**

| 방식 | 샘플당 | 16,384 샘플 |
|---|---:|---:|
| 정수 곱 + `__SSAT` | ~3 cyc | ~49,200 |
| **시프트만 (2의 거듭제곱 변형)** | **~1 cyc** | **~16,400** |
| SIMD 시프트+포화 (`__SSAT16` 쌍) | ~0.5 cyc | ~8,200 |

**합계 추정**

| 변형 | 사이클 | 100MHz 환산 | NPU 추론(71,718) 대비 |
|---|---:|---:|---:|
| 임의 게인, 단순 구현 | ~115,000 | 1.15 ms | **1.6배** |
| 임의 게인, 언롤 | ~74,000 | 0.74 ms | 1.0배 |
| **2의 거듭제곱, 언롤** | **~41,000** | **0.41 ms** | **0.57배** |
| 2의 거듭제곱, SIMD | ~21,000 | 0.21 ms | 0.29배 |

**비교 기준**: ① 의 CPU 전처리는 64프레임 × 512점 실수 FFT + 멜 + 로그다.
`arm_rfft_fast_f32(512)` 가 **수천 사이클/프레임** 수준이므로 64프레임이면
수십만 사이클이 된다 (정확한 값은 보드에서 측정).
→ **(b) 는 ① 전처리보다 한 자릿수 이상 싸다.** 이것이 (b) 의 존재 이유다.

⚠️ 위 수치는 전부 추정이다. **보드에서 DWT 로 실측하기 전에는 논문에 쓰지
않는다.** 표에는 `TBD` 로 두고 이 문서를 근거로 인용한다.

## b.5 학습 쪽 구현

`datasets/safesound.py` 의 `__getitem__` 에 한 단계 추가. 순서가 중요하다.

```
샤드 읽기 → 재절단 shift → 랜덤 게인 ±12dB → (MSnoise) → **음량 정규화** → int8
                                    ↑ 증강은 정규화 **이전**
```

증강을 정규화 앞에 두는 이유: 랜덤 게인은 **실기기의 레벨 변동을 흉내 내는
것**이고, 실기기에서도 정규화는 그 변동을 받은 뒤에 일어난다. 뒤에 두면
정규화가 게인을 그대로 되돌려 증강이 무의미해진다.

⚠️ **테스트셋에도 적용한다** (증강은 아니고 전처리다). 펌웨어가 하는 일이므로
평가 경로에도 있어야 한다. `--config` 에 `wave_fb_norm` 을 추가해 기존
체크포인트 평가와 섞이지 않게 한다.

## b.6 판정 항목 — 정확도만 보면 안 된다

| 항목 | 어떻게 | 왜 |
|---|---|---|
| macro-F1 @300/h, @1000/h | `cmp_all.sh` | 기본 |
| **조용한 배경음 쿼터의 오경보** | `eval_threshold.py` 출처별 표에서 **조용한 창 15%**(`--bg-quiet-frac`)만 따로 | **핵심 위험.** 정규화가 조용한 창의 잡음을 GMAX 배까지 키운다 → 배경음이 이벤트처럼 보일 수 있다 |
| 일반 배경음 vs 하드 네거티브 분리 | 기존 출처별 자체 오탐률 | 어느 쪽에서 늘었는지 |
| 게인 분포 | 학습셋에서 `g` 의 히스토그램 | `g`가 대부분 `GMAX` 에 붙어 있으면 `TARGET` 이 너무 높다 |
| `g = GMAX` 로 잘린 창 비율 | 클래스별 | 상한이 실제로 작동하는지 |

**기각 조건 (미리 정한다)**: 조용한 배경음 쿼터의 자체 오탐률이 기준선 대비
**1.5배를 넘으면**, macro-F1 이 올라도 채택하지 않는다. G7(무인 8시간 구동)이
직접 깨지기 때문이다.

## b.7 실행 계획

**1단계 (지금)** — int8 샤드 위, 2의 거듭제곱 게인만.

| # | 이름 | 데이터셋 | 변형 |
|---:|---|---|---|
| 1 | `safesound-fbnorm2-v1` | `SafeSoundNorm2` | `g ∈ {1,2,4}`, TARGET 96, GMAX 4 |
| 2 | `safesound-fbnorm2-v1-s2` | 〃 | 시드 2 (1번이 잡음을 넘으면) |

모델은 `ai85safesoundnet_fb` + `fb-init-k1`, LR 0.0003 + ft 스케줄 (D-1 과 동일).
**비교 대상은 D-1 (0.4944, 3시드)이다.** 실행당 약 25분.

⚠️ D-1(√)(제곱근 가중치)가 현재 최고(0.5209)이므로, 정규화는 **D-1 기준**으로
먼저 재고 채택되면 D-1(√)와 조합한다. 한 번에 둘을 바꾸면 분리가 안 된다.

**2단계 (1단계가 효과를 보이면)** — int16 샤드 재생성 후 int8 변환 **전** 정규화.
임의 게인 변형도 이때 함께. 비용은 b.2.5 표.
