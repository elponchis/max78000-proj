# 상한선 점검 — 데이터가 어려운가, 모델이 부족한가 (2026-09-30)

**묻는 것**: ① 로그 멜의 @300/h **0.673** 이 낮은 이유가 *데이터 자체가
어려워서* 인가, *모델·학습이 부족해서* 인가. 발표에서 "절대 수준이 왜 이런가"
라는 질문에 답할 참조점을 만든다.

**방법**: AudioSet 2M 클립으로 사전학습된 **PANNs CNN14** 를 같은 테스트셋에
그대로 태운다. 우리가 데이터 필터링에 쓴 **바로 그 체크포인트**다
(`Cnn14_16k_mAP=0.438.pth`, 16kHz 판이라 리샘플이 없다).

## 2. 해석

### 2.1 판정 규칙대로: **데이터 자체가 어렵다**

미리 정한 규칙은 *"PANNs 가 0.8 미만이면 데이터가 어렵다"* 였다.
**@300/h 에서 0.7867 로 0.8 미만**이다 (@1000/h 는 0.8002 로 경계선).

→ **① 을 상한 대비 %로 표기한다.**

| | @300/h | 상한 대비 |
|---|---:|---:|
| PANNs zero-shot (참조 상한) | 0.7867 | 100% |
| **① log-mel** | 0.6733 | **85.6%** |
| D-1(√) | 0.5209 | 66.2% |
| ④ 기준선 | 0.3590 | 45.6% |

AudioSet 2M 클립으로 사전학습한 **80M 파라미터** 모델이 0.79 에 그친다.
우리 ① 은 **157K 파라미터(1/500)** 로 그 85.6% 에 도달했다.
→ ① 의 0.673 은 "모델이 형편없어서" 가 아니라 **태스크 자체의 난이도**가
상당 부분을 설명한다.

### 2.2 ★ 그런데 argmax 로는 ① 이 PANNs 를 **이긴다**

| 지표 | PANNs | ① | 차이 |
|---|---:|---:|---:|
| @300/h | 0.7867 | 0.6733 | PANNs +0.113 |
| **argmax macro-F1** | 0.6665 | **0.7126** | **① +0.046** |
| **원본 다수결 macro-F1** | 0.6476 | **0.7183** | **① +0.071** |
| argmax 오경보/h | **37.5** | 1,167 | PANNs 가 31배 적다 |

**PANNs 의 우위는 이벤트 변별력이 아니라 _배경음 거부·보정_ 에 몰려 있다.**
argmax 오경보가 37.5회/h vs 1,167회/h 로 31배 차이다. 고정 오경보 지점으로
동작점을 맞추면 그 이점이 PANNs 쪽 재현율로 환산되어 나타난다.

→ 논문에서 쓸 수 있는 문장: **"우리 모델에 부족한 것은 표현력보다 _배경음에
대한 보정_ 이다."** 이는 G7(무인 구동 오탐률)과 직접 연결되고, 클래스
가중치(제곱근 실험)·하드 네거티브 구성이 손댈 지점이라는 뜻이다.

### 2.3 클래스별 격차 — **`siren` 이 데이터 문제 후보다**

@300/h 기준 (PANNs − ①):

| 클래스 | 격차 | 읽기 |
|---|---:|---|
| **`siren`** | **+62.6pp** | **압도적. 데이터 문제 1순위** |
| `dog_bark` | +19.3pp | |
| `scream` | +16.4pp | |
| **`glass`** | **−14.5pp** | **① 이 PANNs 를 이긴다** |

**`siren` 이 데이터 문제 후보다.** 근거가 맞물린다.

- CLAUDE.md 4장: `siren` 의 **고유 원본이 202개**(train 137)뿐이다. US8K
  929슬라이스의 고유 원본은 74개다. 우리가 가진 것은 "사이렌 소리" 가 아니라
  **몇 개 녹음의 사이렌**이다.
- PANNs 는 AudioSet 의 방대한 사이렌 표본을 봤고, 사이렌은 음높이 궤적이
  뚜렷해 대규모 데이터에서 잘 배워지는 클래스다.
- 제곱근 가중치 실험에서도 `siren` 만 −4.7pp 로 손해를 봤다 — **원본 다양성이
  부족한 클래스가 가장 먼저 무너진다**는 같은 이야기다.

→ v2 데이터셋에서 **`siren` 원본 확보**가 가장 남는 장사다.

`glass` 에서 ① 이 이기는 것도 의미가 있다. glass 는 **태거 편향이 가장 약한**
클래스이고(임계값 0 = 태거 미사용), 우리가 청취로 `Shatter` 보유 클립만
남긴 클래스다. **라벨 품질에 공들인 클래스에서 우리가 앞선다.**

### 2.4 ⚠️ 편향 — 상한이 과대추정일 수 있다

**테스트 창 선별에 PANNs 판정이 쓰였다** (`prepare_safesound.py` 의 태거
필터, `DEFAULT_TAG_THR`). PANNs 가 이벤트라고 본 창이 이벤트 클래스에 더 많이
남아 있으므로, **PANNs 에 유리한 쪽으로 기울어 있다.**

편향의 세기는 클래스마다 다르다 — 그 자체가 위 해석의 보강이다.

| 클래스 | 태거 임계값 | 편향 | 격차 |
|---|---:|---|---:|
| `siren` | 0.10 | **강함** | +62.6pp |
| `dog_bark` | 0.10 | 강함 | +19.3pp |
| `scream` | 0.025 | 중간 | +16.4pp |
| **`glass`** | **0.0 (미사용)** | **약함** | **−14.5pp** |

**편향이 강한 클래스일수록 PANNs 가 앞서고, 편향이 없는 클래스에서는 진다.**
→ `siren` 의 +62.6pp 는 **데이터 부족과 태거 편향이 함께** 만든 값이고,
둘을 지금 가를 수 없다. 논문에는 두 가능성을 함께 적는다.

→ 따라서 **0.7867 은 상한의 과대추정일 가능성이 크다.** ① 의 "85.6%" 는
**하한으로 읽어야 한다** (진짜 상한이 더 낮으면 그 비율은 더 높다).

### 2.5 (B) linear probe — 하지 않았다

`--mode probe` 를 넣어 두었으나 **구현 전**이다. zero-shot 만으로 판정 규칙
(0.8 미만 → 데이터가 어렵다)이 결정됐고, probe 는 편향 문제를 해소하지 못한다
(같은 테스트셋을 쓰므로). 우선순위를 뒤로 미룬다.
