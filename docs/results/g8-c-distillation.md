`dog_bark` 라고 한다.

## 2. 원인 — 교사의 소프트 타깃이 소프트하지 않았다 (실측)

`tools/diag_soft`(스크래치) 실측, 테스트 창 256개:

```
교사 로짓: |값| 평균 1435, 최대 9255, 클래스 간 간격(최대−차순) 평균 1112

     T     최대확률      엔트로피   유효 클래스수
     1      0.9998      0.0009        1.00
     4      0.9976      0.0058        1.01   ← 우리가 쓴 값
    20      0.9908      0.0199        1.03
   100      0.9618      0.0921        1.12
   300      0.8779      0.3245        1.46
  1000      0.5961      1.0503        3.00
  3000      0.3421      1.5067        4.53
(균등분포 기준: 0.2 / 1.6094 / 5.00)

교사 정확도(argmax) 0.891
```

**T=4 에서 최대확률이 0.998 이다.** 소프트 타깃이 사실상 one-hot 이었다. 즉 증류가
"교사의 부드러운 확률 분포" 가 아니라 **"교사의 하드 라벨"** 을 주었고,
`--kd-distill-wt 0.7` 로 그것이 손실의 70%를 차지했다. 교사가 argmax 89.1%
정확도이므로 **나머지 약 11%의 창에서 확신에 찬 오답을 강요**했고, 정답 라벨의
몫은 0.3 뿐이라 그것을 이길 수 없었다.

왜 로짓이 이렇게 큰가: ①은 **QAT 체크포인트인데 `act_mode_8bit` 없이 추론**된다.
ai8x 의 `output_shift` 스케일링이 적용되지 않아 pre-softmax 값이 그대로 커진다.
①을 평가할 때는 argmax 가 스케일에 무관해 문제가 되지 않았지만, **증류에서는
스케일이 전부**다.

## 3. 내가 빠뜨린 검사

`tools/kat_teacher.py` 가 교사↔① 일치는 확인했고 로짓 크기까지 출력했지만
(`로짓 크기: |①| 평균 1332`), **소프트 타깃의 첨예도는 재지 않았다.**
"교사가 ①과 같은가" 만 묻고 "교사가 증류에 쓸 만한 소프트 타깃을 내놓는가" 는
묻지 않은 것이다. 로짓 크기를 눈으로 보고도 연결하지 못했다.

→ **KAT 에 첨예도 검사를 추가했다**: 학습에 쓸 온도에서 **유효 클래스 수
(exp(엔트로피))가 1.5 미만이면 실패**로 판정한다. 1.0 은 one-hot, 5.0 은 균등이다.

## 4. 재시도 방안 (설계 결함이 아니라 스케일 문제다)

둘 중 하나. **어느 쪽이든 KAT 의 첨예도 검사를 먼저 통과해야 한다.**

1. **교사 로짓을 정규화한 뒤 T=4~8.** 위 표에서 유효 클래스 3.0 이 나오는 지점이
   T≈1000 인데, 그 숫자를 논문에 쓰면 재현·서술이 모두 어색하다. 교사 로짓을
   표준편차로 나누고(또는 배치별 z-정규화) 통상적인 T 를 쓰는 편이 낫다.
   구현은 교사 어댑터 `forward` 끝에 나누기 한 줄이다.
2. **교사를 `act_mode_8bit` 로 추론**해 ai8x 의 정상 스케일을 적용한다. 로짓이
   int8 도메인으로 내려와 T=4 가 의미를 갖는다. 다만 어댑터가 학생의 입력 모드를
   따라가므로 손이 더 간다.

⚠️ 재시도 전에 **`--kd-distill-wt` 를 낮추는 것만으로 고치려 하지 말 것.**
소프트 타깃이 one-hot 인 채로 비중만 줄이면 "교사 하드 라벨을 약하게 섞는" 것이
되어 원리적으로 증류가 아니다.
