# 데이터 품질 진단 (2026-09-30)

`siren` 학습 곡선(양)과 게인 스윕(단서)이 **모델 쪽** 질문이라면, 이 문서는
**데이터 쪽** 질문이다: 라벨이 맞는가, 클래스가 애초에 가를 수 있는가.

네 갈래로 나눈다. 1·2·3 은 실행 도구가 있고, 4 는 **조사만**이다.

---

## 1. PANNs linear probe

**묻는 것**: AudioSet 2M 으로 학습한 임베딩(2048차원)을 고정하고 **선형
분류기만** 얹으면 우리 5클래스를 얼마나 가르는가.

- zero-shot 은 "AudioSet **라벨**을 우리 5클래스로 접은 것" 이다.
- probe 는 "임베딩 **공간**이 우리 5클래스를 선형으로 가르는가" 다.

둘의 차이가 "라벨 매핑이 문제인가, 표현이 문제인가" 를 가른다.

| 항목 | 값 |
|---|---|
| 임베딩 | PANNs CNN14 16kHz, `output_dict["embedding"]` (2048) |
| 학습 | v1 **train** 13,007창, 선형층 1개, AdamW 30에폭 |
| 클래스 가중치 | **①과 동일** (`class_weights()` v1 상수) |
| 표준화 | **학습셋 통계로만** (테스트 정보를 쓰지 않는다) |
| 평가 | ①과 같은 경로 — @300/h, argmax macro-F1, 클래스별 F1 |

### ★ 해석 규칙 (결과 보기 전에 박는다)

| probe @300/h | 해석 |
|---|---|
| **≥ 0.9** | **데이터 양호. 소형 모델이 병목이다.** |
| **≤ 0.8** | **데이터 모호성·라벨 오류 의심.** 2·3번 청취로 확인 |
| 0.8 ~ 0.9 | 둘 다 기여. 클래스별로 갈라 본다 |

⚠️ **편향 문구 유지**: 테스트 창 선별에 PANNs 판정이 쓰였다
(`prepare_safesound.py` 태거 필터). probe 에도 같은 편향이 실려 있어
**과대추정**일 수 있다. `glass` 는 태거 임계값이 0(미사용)이라 그 클래스만
편향이 약하다 (`ceiling-check.md` 2.4).

**결과**: 실행 중 (`tools/ceiling_check.py --mode probe`).

## 2. 블라인드 청취 감사 세트 — **준비 완료**

**묻는 것**: 우리 테스트 라벨 자체의 오류율.

| 항목 | 값 |
|---|---|
| 표본 | 테스트 창 **클래스당 40개 = 200개** |
| 추출 | 무작위, **원본 ID 중복 없이** (고유 fsid 200/200 확인) |
| 블라인드 | 파일명이 `001.wav` … `200.wav` 뿐 — **라벨·예측 없음**, 순서도 셔플 |
| 정답 | `_key_DO_NOT_OPEN.csv` 에 분리. **채점할 때만** 연다 |
| 기입 | `audit.csv` 의 `heard`(6지선다 + unknown), `confidence`(1~3), `memo` |

위치: `data/audit/blind/`

채운 뒤:
```bash
python3 tools/listen_audit.py --score data/audit/blind/audit.csv
```
→ 클래스별 **라벨 오류율**과 **원본 단위 부트스트랩 95% CI**.
블라인드 세트는 원본 중복이 없으므로 창 수 = 원본 수다.

⚠️ 원본 중복을 없앤 이유: 같은 녹음에서 두 창을 뽑으면 판정이 종속되어
CI 가 실제보다 좁아진다.

⚠️ **판정자 1인**이고 일치도를 재지 않는다 (CLAUDE.md 8장 한계 2).
`confidence` 1~3 을 받는 이유가 그것이다 — 확신도 낮은 판정을 빼고 다시
계산해 민감도를 볼 수 있다.

## 3. 의심 창 목록

**묻는 것**: 여러 모델이 **한목소리로** 라벨과 다르게 판정하는 창.
그러면 모델이 아니라 **라벨 쪽**을 의심할 근거가 된다.

| 항목 | 값 |
|---|---|
| 모델 | ① 3시드 + D-1(√) 3시드 = **6개** |
| 조건 | **여섯 전부** 예측이 라벨과 다르다 |
| 정렬 | 평균 마진 `logit[예측] − logit[정답]` **내림차순** (확신하며 틀린 순) |
| 개수 | 상위 **30** |
| 부가 | 여섯 모델이 **같은** 오답을 냈는가(`모델일치`) 를 함께 기록 |

위치: `data/audit/suspect/`, 판정 칸 `verdict`(라벨맞음 / 라벨틀림 / 모호).

⚠️ 6개 모델이 두 계열(①·D-1√)뿐이라 **상관이 있다.** "여섯이 다 틀렸다" 가
독립 증거 여섯 개는 아니다. 그래도 표현(멜 vs 파형)이 다른 두 계열이 함께
틀린 것은 의미가 있다.

**상태**: 로짓 덤프 진행 중.

⚠️ 아래 수치는 **아직 확인하지 않았다.** 네트워크 접근 승인 후 채운다.
지금 적는 것은 **무엇을 어떻게 확인할지**와 **왜 그게 중요한지**다.

| 합성 여부 | MIVIA 는 **배경에 이벤트를 합성**해 만든 세트로 알려져 있다 | **TBD** |

⚠️ **합성 데이터의 위험**: 배경 + 이벤트를 인위적으로 섞은 것이면 우리
`--fill-mode background` 채움과 성격이 비슷하고, 실환경 분포와 다르다.
**테스트셋에는 넣지 않는다** — 학습 보강용으로만 검토한다.

⚠️ **라이선스가 신청 기반이면 논문 재현성에 불리하다.** 독자가 같은 데이터를
못 받으면 재현 절차가 끊긴다. CC 데이터(Freesound)를 우선한다
(`siren-data-sufficiency.md` 2.4).

### 4.3 판단 순서

1. **논문·README 로 출처 비율 먼저** 확인 (다운로드 없이 가능)
2. FSD50K 파생 비율이 높으면 → **기각**, Freesound 직접 검색으로
3. 새 원본이 유의미하면 → 라이선스 확인 → 소량 표본 다운로드 → **청취 검증**
4. 청취 통과분만 매니페스트에 편입, **원본 ID 단위 전역 분할 재실행**
   (CLAUDE.md 5장 규칙 1 — 새 원본이 들어오면 분할을 다시 해야 한다)

⚠️ 4번이 큰 비용이다. 새 원본을 넣으면 **train/test 분할이 바뀌고 기존
모든 실험과 비교가 깨진다.** v2 데이터셋으로 묶어 한 번에 해야 한다
(`event-level.md` 11절 V-1~V-6 과 함께).
