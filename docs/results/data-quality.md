# 데이터 품질 진단 (2026-09-30)

`siren` 학습 곡선(양)과 게인 스윕(단서)이 **모델 쪽** 질문이라면, 이 문서는
**데이터 쪽** 질문이다: 라벨이 맞는가, 클래스가 애초에 가를 수 있는가.

네 갈래로 나눈다. 1·2·3 은 실행 도구가 있고, 4 는 **조사만**이다.

---

## 1. PANNs linear probe

**묻는 것**: AudioSet 2M 으로 학습한 임베딩(2048차원)을 고정하고 **선형
분류기만** 얹으면 우리 5클래스를 얼마나 가르는가.

- zero-shot 은 "AudioSet **라벨**을 우리 5클래스로 접은 것" 이다.
- probe 는 "임베딩 **공간**이 우리 5클래스를 선형으로 가르는가" 다.

둘의 차이가 "라벨 매핑이 문제인가, 표현이 문제인가" 를 가른다.

| 항목 | 값 |
|---|---|
| 임베딩 | PANNs CNN14 16kHz, `output_dict["embedding"]` (2048) |
| 학습 | v1 **train** 13,007창, 선형층 1개, AdamW 30에폭 |
| 클래스 가중치 | **①과 동일** (`class_weights()` v1 상수) |
| 표준화 | **학습셋 통계로만** (테스트 정보를 쓰지 않는다) |
| 평가 | ①과 같은 경로 — @300/h, argmax macro-F1, 클래스별 F1 |

### ★ 해석 규칙 (결과 보기 전에 박는다)

| probe @300/h | 해석 |
|---|---|
| **≥ 0.9** | **데이터 양호. 소형 모델이 병목이다.** |
| **≤ 0.8** | **데이터 모호성·라벨 오류 의심.** 2·3번 청취로 확인 |
| 0.8 ~ 0.9 | 둘 다 기여. 클래스별로 갈라 본다 |

⚠️ **편향 문구 유지**: 테스트 창 선별에 PANNs 판정이 쓰였다
(`prepare_safesound.py` 태거 필터). probe 에도 같은 편향이 실려 있어
**과대추정**일 수 있다. `glass` 는 태거 임계값이 0(미사용)이라 그 클래스만
편향이 약하다 (`ceiling-check.md` 2.4).

### 결과 (2026-09-30)

| 구성 | @300/h | @1000/h | argmax macro-F1 | 원본 다수결 |
|---|---:|---:|---:|---:|
| **probe (역빈도 = ①과 동일)** | **0.7465** | 0.8154 | 0.7988 | 0.8311 |
| probe (가중치 없음) | 0.7351 | 0.8123 | **0.8181** | **0.8398** |
| probe (제곱근) | 0.7454 | 0.8130 | 0.8122 | 0.8357 |
| PANNs zero-shot | **0.7867** | 0.8002 | 0.6665 | 0.6476 |
| ① log-mel | 0.6736 | 0.7220 | 0.7210 | 0.7254 |

클래스별 @300/h (역빈도 판): siren 78.9% / **glass 31.7%** / scream 48.9% /
dog_bark 87.9%.

### ⚠️ "probe < zero-shot @300/h → 라벨 불량" 은 **단정할 수 없다**

세 설명이 가능하고, 지금 가른 것은 하나뿐이다.

| # | 설명 | 상태 |
|---|---|---|
| (i) | **선별 편향** — 테스트 창 선별에 zero-shot 태거가 쓰여 고정 오경보 지점에서 zero-shot 이 유리하다 | **가르지 못했다** |
| (ii) | **가중치** — probe 가 역빈도(bg 0.27)로 학습돼 배경 꼬리에서 과검출한다 | **기각됨** ↓ |
| (iii) | 라벨 품질 | 미확정 — 청취 감사로 |

**(ii) 는 기각됐다.** 가중치를 없애거나(0.7351) 제곱근으로(0.7454) 바꿔도
@300/h 가 역빈도 판(0.7465)보다 **오르지 않는다**. 오히려 가중치 없음이 가장
낮다. 배경 가중치가 원인이 아니다.

**(i) 은 남는다.** `glass` 는 태거 임계값이 0(미사용)이라 편향이 약한데,
그 클래스에서 probe 가 **31.7%** 로 가장 낮다 — 편향만으로는 설명되지 않는
부분이 있다는 뜻이기도 하다.

### ★ 결론 — "전반적 라벨 불량" 이 아니다

**우리 라벨은 분리 가능하다**: probe 의 argmax macro-F1 **0.7988**,
원본 다수결 **0.8398** 로 zero-shot(0.6665 / 0.6476)을 크게 앞선다.
임베딩 공간에서 우리 5클래스가 선형으로 잘 갈린다는 뜻이다.

무너지는 곳은 **고정 오경보 지점**, 즉 **배경음 경계**다. 그리고 클래스로는
**`glass`** 다 (2M 클립 사전학습 + 선형층으로도 31.7%, ①의 45.7% 보다 낮다).

> **결론: 전반적 라벨 불량이 아니라 _배경 경계와 `glass` 가 어렵다_.**
> 그 어려움이 **라벨 오류**인지 **클래스 정의**인지는 청취 감사(2·3번)로
> 판정한다.

⚠️ 편향 문구 유지: 테스트 창 선별에 PANNs 가 쓰였다. probe 에도 같은 편향이
실려 있어 **과대추정**일 수 있다.

## 2. 블라인드 청취 감사 세트 — **준비 완료**

**묻는 것**: 우리 테스트 라벨 자체의 오류율.

| 항목 | 값 |
|---|---|
| 표본 | 테스트 창 **클래스당 40개 = 200개** |
| 추출 | 무작위, **원본 ID 중복 없이** (고유 fsid 200/200 확인) |
| 블라인드 | 파일명이 `001.wav` … `200.wav` 뿐 — **라벨·예측 없음**, 순서도 셔플 |
| 정답 | `_key_DO_NOT_OPEN.csv` 에 분리. **채점할 때만** 연다 |
| 기입 | `audit.csv` 의 `heard`(6지선다 + unknown), `confidence`(1~3), `memo` |

위치: `data/audit/blind/`

### ⚠️ 청취 순서: **blind 먼저 → suspect 나중**

두 세트는 **fsid 10개**가 겹치고 그중 **4개는 완전히 같은 창**이다
(`data/audit/*/OVERLAP.txt`). 재추출하지 않고 **순서로** 해결한다.

- `suspect` 를 먼저 들으면 "여러 모델이 틀린 창" 이라는 정보와 **라벨이
  노출**되어 blind 판정이 오염된다.
- `blind` 를 아무 정보 없이 먼저 하면 오염이 없다. `suspect` 는 **원래
  라벨 공개 세트**라 나중에 해도 순서 영향이 없다.

겹친 4창(suspect #2/#11/#27/#29 = blind 50/175/161/132)은 **같은 창을 두 번
판정**하게 되므로 **판정자 자기 일관성** 확인에 쓴다:

```bash
python3 tools/listen_audit.py --consistency
```

blind 에서 들은 것이 정답과 같으면 suspect 에서 `라벨맞음`, 다르면
`라벨틀림` 이 나와야 일관적이다(`모호` 는 모순이 아니므로 일관으로 센다).
**판정자 1인 한계(CLAUDE.md 8장 한계 2)를 부분적으로나마 재는 유일한
수단**이다. ⚠️ n=4 라 비율의 신뢰구간이 매우 넓다 — **경향만** 본다.

채운 뒤:
```bash
python3 tools/listen_audit.py --score data/audit/blind/audit.csv
```
→ 클래스별 **라벨 오류율**과 **원본 단위 부트스트랩 95% CI**.
블라인드 세트는 원본 중복이 없으므로 창 수 = 원본 수다.

⚠️ 원본 중복을 없앤 이유: 같은 녹음에서 두 창을 뽑으면 판정이 종속되어
CI 가 실제보다 좁아진다.

⚠️ **판정자 1인**이고 일치도를 재지 않는다 (CLAUDE.md 8장 한계 2).
`confidence` 1~3 을 받는 이유가 그것이다 — 확신도 낮은 판정을 빼고 다시
계산해 민감도를 볼 수 있다.

## 3. 의심 창 목록

**묻는 것**: 여러 모델이 **한목소리로** 라벨과 다르게 판정하는 창.
그러면 모델이 아니라 **라벨 쪽**을 의심할 근거가 된다.

| 항목 | 값 |
|---|---|
| 모델 | ① 3시드 + D-1(√) 3시드 = **6개** |
| 조건 | **여섯 전부** 예측이 라벨과 다르다 |
| 정렬 | 평균 마진 `logit[예측] − logit[정답]` **내림차순** (확신하며 틀린 순) |
| 개수 | 상위 **30** |
| 부가 | 여섯 모델이 **같은** 오답을 냈는가(`모델일치`) 를 함께 기록 |

위치: `data/audit/suspect/`, 판정 칸 `verdict`(라벨맞음 / 라벨틀림 / 모호).

⚠️ 6개 모델이 두 계열(①·D-1√)뿐이라 **상관이 있다.** "여섯이 다 틀렸다" 가
독립 증거 여섯 개는 아니다. 그래도 표현(멜 vs 파형)이 다른 두 계열이 함께
틀린 것은 의미가 있다.

**상태**: 로짓 덤프 진행 중.

# ★ 혼합 증강 (chain14, 2026-10-01) — **미채택**

되돌리기:포화 = 50:50 으로 게인 증강을 바꿔 ①·④ 각 1시드 재학습.
`SafeSoundMelMix50` / `SafeSoundMix50`, `clip_prob=0.5`.

## 판정 — 사전 등록 규칙 (둘 다 만족해야 채택)

| 기준 | ① | 판정 |
|---|---|---|
| **1. 포화 판 +12dB 낙폭 감소** | −0.0343 → **−0.0080** (+0.0263) | **통과** |
| **2. 0dB ≥ 0.6610** (① sd 0.0049 의 −2sd) | **0.6604** | **실패 (−0.0006)** |

> ### → **미채택.** AND 조건이므로 1번만으로는 부족하다.

⚠️ **0.0006 은 ① sd 의 0.12배다.** 규칙은 통과시키지 않지만, 이 숫자를
**"혼합 증강이 0dB 성능을 떨어뜨렸다" 의 근거로 쓸 수도 없다.** 실제로
관측된 것은 **"기준 2가 이 설계로는 판정 불가"** 다 — 단일 시드이고 결손이
0.12 sd 다.

**규칙을 사후에 고치지 않는다.** 바꿔야 한다면 **다음 실험을 설계할 때**
바꾸고, 그때 바꾼 이유와 바꾸기 전 결과를 함께 적는다.

## 그래도 분명한 것 — ④ 쪽

④ 는 사전 등록 기준이 ① 기준으로 쓰여 있어 형식적 판정 대상이 아니지만,
수치는 ① 보다 훨씬 또렷하다.

| | 0dB | +12dB | 낙폭 |
|---|---:|---:|---:|
| ④ 기준 | 0.5210 | 0.4217 | **−0.0992** |
| ④ mix50 | 0.5611 | 0.5011 | **−0.0601** |

0dB 가 **올랐고**(0.5210 → 0.5611, ④ sd 0.0238 의 1.7배) +12dB 낙폭이
**4%p 줄었다.** ④ 기준이 +12dB 에서 0.42 까지 무너지던 것이 0.50 에서
멈춘다.

⚠️ **단일 시드다.** ④ 계열 sd 가 0.0238 이라 0.5611 은 ④ 5시드 분포
(0.5079~0.5627)의 **상단과 겹친다** — "증강 효과" 와 "좋은 시드" 를 가를 수
없다. 판정하려면 ④ mix50 도 시드 3개 이상이 필요하다.

## 판정 — 사전 등록 규칙 (둘 다 만족해야 채택)

| 기준 | ① | 판정 |
|---|---|---|
| 1. 포화 판 +12dB 낙폭 감소 | −0.0343 → −0.0080 (s1) | **통과** |
| **2. 0dB 가 기준 시드 분포 하한 이상** | **−0.0121 [−0.0241, −0.0002]** | **실패** |

> ### → **미채택 확정.**

**chain14 와 달라진 점**: 그때는 "판정 불가"(결손 0.0006 = sd 의 0.12배)
였고, 지금은 **검출됐다**. 3시드 Welch t 가 CI 상한 −0.0002 로 0 을
간신히 밖에 둔다. 즉 **혼합 증강은 ① 의 0dB 성능을 약 0.012 떨어뜨린다.**

⚠️ CI 상한이 −0.0002 로 **0 에 거의 붙어 있다.** "확실히 해롭다" 가 아니라
**"3시드로 겨우 검출되는 크기만큼 해롭다"** 가 맞다. 효과 크기는 ① sd 의
2.5배이고, 기준 1의 이득(+0.0263)보다 **작다**.

## 그래서 남는 트레이드오프 — 논문 한계에 적는다

혼합 증강은 **큰 소리에서의 train/serve 불일치를 줄이는 대신 0dB 성능을
깎는다.** 사전 등록 규칙은 후자를 허용하지 않으므로 미채택이지만,
**버리는 것도 공짜가 아니다**:

| 선택 | 얻는 것 | 잃는 것 |
|---|---|---|
| **미채택 (현재)** | ① 0dB **0.6708** | 포화 판 +12dB 에서 **−0.0343** (④ 는 −0.0992) |
| 채택 | +12dB 낙폭 −0.0080 (④ −0.0601) | ① 0dB **−0.0121** |

⚠️ **펌웨어는 포화한다** (CLAUDE.md 7장, MSDK 랩어라운드를 우리는 고친다).
학습은 되돌리기다. 따라서 **큰 소리에서 분포가 어긋난다는 사실은 미채택
상태에서 그대로 남고, 논문 한계 절에 위 표로 적는다.**
