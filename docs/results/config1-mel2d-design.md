# 구성 ① — 로그 멜 + 2D CNN (G8 대조군)

설계 2026-09-26 · **구현 완료 2026-09-26** (학습 대기).

G8(전처리 오프로드 스펙트럼)의 최소 버전은 ①과 ④ 두 점 비교로 성립한다
(`CLAUDE.md` 8장). ④(raw 파형 1D CNN)는 이미 기준선이고, 여기서 정의하는 것은
**①: 전처리를 M4 CPU 가 전부 하고 NPU 는 2D CNN 만 하는 구성**이다.

핵심 원칙: **입력 표현만 다르게 하고 나머지는 전부 같게 한다.** 클래스 손실
가중치, 증강, 에폭 수, 스케줄, QAT 정책, 평가 스크립트, 원본 단위 분할이 모두
동일해야 "전처리 위치가 정확도에 미치는 영향" 이라는 결론이 성립한다.

**①은 ④의 병목이 입력 표현인지 데이터인지 가리는 실험이기도 하다.** 그래서 ④의
기준선 결과(오경보 수천 회/h)를 고치기 전에 돌린다 — ①도 같이 낮으면 데이터·라벨
쪽이고, ①만 잘 나오면 raw 파형 표현이 병목이라는 뜻이다.

## 1. 특징 표현 — `datasets/melfeat.py`

| 항목 | 값 | 근거 |
|---|---|---|
| STFT | n_fft 512 (32ms), hop 256 (16ms), Hann(주기형), `center=False` | 2의 거듭제곱이라 M4 FFT 에 유리 |
| 패딩 | reflect 128 샘플 양옆 | 프레임 수를 64에 맞추면서 **④와 같은 16,384 샘플만** 본다 |
| 프레임 수 | **64** | (16384+256−512)/256 + 1 |
| 멜 | n_mels **64**, 20~8000Hz, **HTK** 식, 면적 정규화 없음 | 식이 한 줄이라 고정소수점 이식이 단순. 빈 밴드 0개 (KAT 검증) |
| 압축 | `10·log10(mel_power + 1e-12)` | dB. **DCT 는 걸지 않는다** (1.1) |
| 기준점 | 풀스케일 사인파 = 0dB | 실측 −0.75dB (1kHz 가 필터 꼭대기와 안 겹침) |
| 양자화 | `TOP_DB 0` / `SPAN_DB 70` → int8, **포화** | 1.2 |
| 입력 텐서 | **1 × 64 × 64 int8** | 4,096 바이트 |

⚠️ **정규화를 하지 않는다** (CLAUDE.md 7장). 창 단위도 파일 단위도 아니다.
KAT 가 이것을 직접 검사한다 — 입력을 6dB 줄이면 출력 dB 도 6.0dB 준다.

### 1.1 MFCC 가 아니라 로그 멜을 쓰는 이유

1. **DCT 는 CNN 에 손해다.** 켑스트럼 역상관은 GMM-HMM 시대의 요구이고, 2D CNN 은
   멜 축의 국소 상관을 오히려 특징으로 쓴다. DCT 를 걸면 ① 의 정확도가 내려가고,
   그러면 "④가 낫다" 는 대조가 우리에게 유리하게 왜곡된다.
   **대조군에는 최선의 구성을 준다.**
2. **비용 논거가 흔들리지 않는다.** ① 의 CPU 비용을 지배하는 것은 FFT 이고 DCT 는
   그 일부다. 지연 비교의 결론은 바뀌지 않는다.
3. DCT 까지의 CPU 비용은 **펌웨어에서 따로 잰다** (DCT on/off 두 측정).
   논문에는 "로그 멜까지 / MFCC 까지" 두 값을 병기한다.

→ `CLAUDE.md` 8장 G8 표를 이에 맞게 고쳤다 (2026-09-26).

### 1.2 dB → int8 구간은 **양쪽 끝이 물리적으로 유도된다**

`tools/mel_range_sweep.py` 실측 (`docs/results/mel-range-sweep.md`).

| 끝 | 값 | 유도 |
|---|---|---|
| 위 | **0dB** | 풀스케일 사인파. 이벤트 클래스 멜 빈의 **0.004%** 만 포화 |
| 아래 | **−70dB** | **int8 파형의 양자화 잡음 바닥보다 아래.** ±1 LSB 만 든 창의 멜 dB 는 저역 −64.7 ~ 고역 −53.5 (중앙값 −58.6). 저역 최악값에 5.3dB 여유 |

→ 1 LSB = 70/255 = **0.275dB**. 이벤트 멜 빈의 16.7%가 바닥에 붙지만 **그것들이
곧 양자화 잡음 구간**이라 잃는 정보가 없다. glass 가 특히 많은 것은 0.3초
과도음이라 창의 대부분이 조용한 것이 정상이기 때문이다.

바꾸면 **학습·KAT·펌웨어 세 곳을 함께 재생성**해야 한다.

## 2. 증강을 어떻게 같게 유지하는가

파형 모델의 증강은 둘이고 **둘 다 파형 영역**에 정의돼 있다 (shift ±100ms 재절단,
랜덤 게인 ±12dB + 피크 클램프 + int8 0 비율 재추출).

### 미리 계산할 수 없는 이유

게인은 로그 영역에서 상수 덧셈처럼 보이지만 실제로는 아니다 — **피크 클램프와
int8 포화가 비선형**이다. 미리 계산한 멜에 상수를 더하면 클리핑이 일어나는 큰
소리에서 학습 분포가 ④와 갈라지고, "입력 표현만 다른 비교" 가 깨진다.

### 채택안 — 상속 + 즉석 계산, 테스트셋만 캐시

`SafeSoundMel` 은 `SafeSound` 를 **상속**한다. `_crop` / `_rand_gain` /
`_mix_noise` / `_shard` 를 그대로 쓰고 마지막 표현 단계만 덮어쓴다.
증강 코드를 복제하지 않는 것이 핵심이다 — 복제하면 두 구성이 조용히 갈라진다.

- 비용: 창당 약 1ms. `--workers` 로 흡수된다
- 테스트셋은 증강이 없으므로 `build_cache()` 로 memmap 캐시 (노트북 셀 17).
  **증강이 켜진 split 에 캐시를 붙이면 예외가 난다** (KAT 가 검사한다)

⚠️ 설계안 단계에서 "shift 해상도가 16ms 격자로 떨어진다" 고 적었으나 **틀렸다.**
파형에서 먼저 자른 뒤 멜을 만들므로 shift 는 ④와 똑같이 **샘플 단위**다. 격자에
묶이는 것은 미리 계산 방식이었을 때의 이야기이고, 즉석 계산을 택하면서 사라졌다.
즉 ①과 ④의 증강은 **완전히 동일하다**.

## 3. 모델 — `models/ai85net-safesound-mel.py`

지원 연산은 Conv2d **3×3 / 1×1 만**, MaxPool/AvgPool, element-wise 다.
depthwise separable 은 MAX78000 에서 **미지원**이다 (`CLAUDE.md` 3장).

| # | 연산 | 출력 | 중간 텐서 |
|---|---|---|---:|
| in | — | 1×64×64 | 4,096 B |
| 1 | Conv2d 3×3, 1→32 | 32×64×64 | **131,072 B (25.0%)** |
| 2 | MaxPool2 + Conv2d 3×3, 32→32 | 32×32×32 | 32,768 B |
| 3 | MaxPool2 + Conv2d 3×3, 32→64 | 64×16×16 | 16,384 B |
| 4 | MaxPool2 + Conv2d 3×3, 64→64 | 64×8×8 | 4,096 B |
| 5 | MaxPool2 + Conv2d 3×3, 64→128 | 128×4×4 | 2,048 B |
| 6 | MaxPool2 + Conv2d 1×1, 128→128 | 128×2×2 | 512 B |
| 7 | FC 512→5 | 5 | — |

**가중치 157,535 params = 442KB 의 34.8%** (④ 165,457 = 36.6%).
학습 로그에는 distiller 가 `Params: 157472` 로 찍는다 — 양자화 대상 가중치만
세기 때문이며 442KB 판정에는 차이가 없다.
 distiller 는 학습 로그에  로 찍는다 (양자화 대상 가중치만 센다).
**데이터 메모리 최대 131KB = 512KB 의 25.0%.** 둘 다 제약 안이다.
채널 스윕: 0.5× 40,143 (8.9%) / 1.5× 352,239 (77.8%).

⚠️ 위 수치는 파라미터·텐서 기준 추정이다. **확정은 `ai8xize.py` 합성 결과로
한다** — 합성 yaml 은 ④와 함께 학습 후 작성한다 (`TASKS.md` Phase 3).

**BatchNorm 을 쓰지 않는다.** ④가 `FusedConv1dReLU`(BN 없음)이기 때문이다.
정규화 유무는 구조 선택이고 한쪽에만 주면 비교가 오염된다. ①이 학습되지 않으면
그때 **양쪽에 동시에** 넣는다. Dropout 0.2 의 위치·비율도 ④와 맞췄다.

## 4. 같게 맞춘 것 / 다를 수밖에 없는 것

**같게** — 코드 수준에서 강제했다.

| 항목 | 어떻게 |
|---|---|
| 데이터 | **같은 샤드 경로**를 읽는다. KAT 가 `meta` 동일성을 검사한다 |
| 클래스 가중치 | `safesound.class_weights()` 를 그대로 import |
| 증강 | `SafeSound` 상속 — 같은 메서드가 실행된다 |
| 스케줄·QAT·에폭·시드 | 노트북 셀 18 이 셀 8과 같은 인자를 쓴다 |
| 평가 | 같은 스크립트에 `--config mel` 만 추가 |

**다를 수밖에 없는 것** — 논문에 명시한다.

1. 모델 구조 (1D vs 2D). 파라미터 수를 맞춰 완화하되 동일하지 않다 (−4.8%)
2. 학습 시간 (멜 계산분 추가)
3. **실기기 전처리 오차**: M4 고정소수점 FFT 결과가 PC float 과 다르다.
   ④에는 이 항목이 **없다** — 전처리가 옮겨 담기뿐이기 때문이다.
   → **G4(온디바이스 vs PC 괴리)가 ①에서 더 크게 나올 것으로 예상**되고,
   그 대조 자체가 G8 의 결과 중 하나다. 허용 오차는
   `tools/kat_vectors/README-mel.md` (현재 ±2 LSB ≈ 0.55dB, **가안**)
