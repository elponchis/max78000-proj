# 데이터셋 v2 설계안 — 조건부 승인 (2026-10-05) → **채택 (2026-10-06, 9절)**

작성 2026-10-05. 근거: `external-eval.md` (외부 세트 낙폭 0.23~0.31),
`external-drop-diagnosis.md` (혼합음이 낙폭의 약 80% 를 재현, 코덱은 0).
승인 전에는 다운로드·전처리·학습을 시작하지 않는다 (CLAUDE.md 13장).

**2026-10-05 승인 내용**: 1단계만. 재학습 대상은 ④, 간격 400, 후보 가, 후보 다,
①′. AudioSet 학습 분할은 1단계 학습에 쓰지 않는다. 실행 전에 8절을 커밋한다.
1~7절과 8절이 다르면 **8절이 우선**이다.

## 0. 한 줄 요약

> **v2 = v1 데이터 그대로 + 학습 시 배경 혼합 증강.** 외부 데이터 추가(AudioSet
> strong 학습 분할)는 **2단계로 미루고**, 1단계 결과를 본 뒤 결정한다.

이유: 진단이 가리킨 원인은 "학습 데이터에 혼합음이 없다" 이고, 그것은 **이미
가진 데이터로** 고칠 수 있다. 새 데이터를 같이 넣으면 무엇이 효과였는지
분리되지 않고 (규칙 6 의 MSnoise 때와 같은 이유), 다운로드·라벨 검증에
4주 일정의 며칠을 쓴다.

## 2. 배경 혼합 증강 — 구체안

- **위치**: `datasets/safesound.py` 의 `_mix_noise` 후크 (지금은 비어 있다).
  멜 계열도 같은 파형 경로를 타므로 한 곳만 고치면 된다.
- **식**: 진단과 같다. `y = clip(round(e + g·b))`, 이벤트 레벨은 그대로 두고
  배경을 스케일한다 (절대 레벨 정책 유지, 7장).
- **배경 풀**: **train split 의 background 창만.** test 배경은 쓰지 않는다
  (규칙 1 — 같은 split 안에서만. 진단 실험은 test 안에서 섞었고 학습에
  쓰지 않았다). int8 0 비율 > 0.5 인 창은 풀에서 뺀다.
- **SNR**: 창 RMS 기준 **0~+20 dB 균등**, 전 클래스 같은 범위 (클래스별로
  다르면 그 차이가 단서가 된다 — 규칙 6).
  ⚠️ glass 는 과도음이라 창 RMS 기준 0 dB 가 매우 세다 (진단에서 외부보다
  더 떨어졌다). 그래도 범위를 클래스별로 바꾸지 않는다. 대신 SNR 정의를
  **"이벤트 구간 RMS 기준"** 으로 바꾸는 안을 3-(나)로 둔다.
- **적용 확률 0.5**: 나머지 절반은 v1 과 같은 깨끗한 창이다. 시험셋(깨끗한
  창) 성능을 잃지 않으려는 것이다.
- **background 클래스 창에는 적용하지 않는다** (배경 + 배경은 배경이다.
  레벨 분포만 바뀐다). ⚠️ 이러면 "혼합 여부" 가 클래스 단서가 될 수 있다 —
  3-(다)에서 본다.
- **순서**: 자르기 → 게인 → **혼합** → (int8 0 비율 하한 재확인). 게인 뒤에
  섞어야 SNR 이 게인과 독립이 된다.
- 시험셋은 무증강 그대로다.

## 3. 사전 등록할 것 (승인 시 고정)

**(가) 주 비교**: 구성마다 v1 대 v2, 같은 시드 수 (④ 5, 나머지 3).
- 외부 세트 macro-F1 (v1 정의, 시험셋 @300/h 문턱값 고정): **v2 − v1 의
  95% CI 가 0 을 넘으면 "혼합 증강이 외부 성능을 올린다"**.
- 기존 시험셋 macro-F1 @300/h: **v2 − v1 의 CI 하한 ≥ −0.02 면 "시험셋
  성능을 잃지 않는다"** (지금까지 쓴 허용 폭과 같다).
- 둘 다 충족해야 v2 를 채택한다. 하나만이면 결과를 그대로 적고 v1 을 유지한다.
- ⚠️ **외부 세트로 구성·하이퍼파라미터를 고르지 않는다.** SNR 범위·확률은
  이 문서의 값으로 한 번만 돌린다. 외부 세트를 보고 다시 맞추면 시험 전용이
  아니게 된다.

**(나) SNR 정의 (선택, 1회 추가 학습)**: 창 RMS 대 이벤트 구간 RMS. ④ 3시드로만
비교한다. 주 비교가 끝난 뒤 여유가 있을 때.

**(다) 지름길 점검**: v2 모델에 "배경만 두 개 섞은 창" 을 넣어 이벤트로
발화하는 비율이 원래 배경 발화율보다 높아지지 않는지 본다 (혼합 흔적을
이벤트 단서로 배웠는지).

**(라) 순위**: v2 에서도 구성 순위(①′ > 간격 400 ≈ 다 > 가 > ④)가 유지되는지.
"정확도 대 에너지" 결론이 증강에 의존하는지를 본다.

## 5. 2단계 — AudioSet strong 학습 분할 (1단계 결과를 보고 결정)

**넣는 조건**: 1단계 뒤에도 외부 세트 낙폭이 절반 이상 남을 때.

- 규모안: 클래스당 300~500구간 (v1 의 train 원본 137~788개와 같은 자릿수),
  배경 1,000구간. strong 학습 분할은 약 10만 구간이라 양은 충분하다.
- 비용: 유튜브 다운로드 (외부 세트 889구간에 수 시간, 유효율 85%) →
  2,500구간이면 **하루 이상**. 사전 확인 필요 (13장).
- ⚠️ **넣으면 생기는 문제**
  1. **외부 세트가 "다른 출처" 가 아니게 된다.** 같은 AudioSet·같은 유튜브다.
     분할(train 대 eval)은 다르지만 출처 차이를 재는 세트로서의 뜻이 약해진다.
  2. 라벨이 청취 검증 전이다. v1 은 청취로 걸렀다 (glass 72% 등).
  3. 오디오 재배포 금지 — 재현 절차가 "ID 목록 + 각자 다운로드" 가 된다.
  4. 영상 ID 단위 분할과 Freesound ID 단위 분할을 함께 관리해야 한다.
- 권고: **4주 안에는 하지 않고 논문의 향후 과제로 적는다.** 1단계로 낙폭이
  충분히 줄면 필요 없고, 안 줄면 그 자체가 "혼합음만으로는 설명되지 않는다"
  는 결과다.

## 8. 사전 등록 (2026-10-05, 학습 시작 전에 커밋. 실행 후에는 바꾸지 않는다)

### 8-a. 혼합 순서와 int8 변환

학습 창 하나에 대해 순서는 다음과 같다 (`datasets/safesound.py`).

1. **자르기** (시간 이동 ±100 ms) — v1 과 같다.
2. **랜덤 게인 ±12 dB** — v1 과 같다. 피크 초과 시 되돌리기, int8 0 비율 하한
   재추출까지 v1 그대로 끝낸 **int8 창 e** 가 나온다.
3. **배경 혼합** (확률 0.5, background 클래스 창은 제외):
   `y = np.clip(np.round(e + g·b), −128, 127)`
   - b 는 train split 배경 창 (저장 행의 가운데 1초, 게인 증강 없음. int8 0
     비율 > 0.5 인 창은 풀에서 뺀다).
   - **int8 변환은 `np.clip` 포화만 쓴다. 섞은 뒤 창 전체를 다시 스케일하지
     않는다** (피크가 넘어도 줄이지 않는다). 실기기는 포화이고, 창 전체를 줄이면
     이벤트의 절대 레벨이 혼합 여부에 따라 달라진다.
   - 2단계의 "피크 초과 시 되돌리기" 는 **이벤트 단독**에만 적용되는 기존
     동작이고 건드리지 않는다 (v1 과의 차이를 혼합 하나로 유지).
4. (해당 구성만) 음량 정규화 — v2 대상 구성에는 없다.
5. 특징 계산·텐서 변환 — v1 과 같다.

게인을 **먼저** 하는 이유: SNR 이 게인과 독립이 된다 (게인은 이벤트의 절대
레벨을, SNR 은 이벤트 대 배경의 비를 정한다). 순서를 바꾸면 혼합물 전체가
±12 dB 움직여 SNR 은 같지만 배경의 절대 레벨 분포가 달라진다 — 어느 쪽도
틀리지 않으나 **이 순서로 고정**한다. 혼합 뒤 0 비율 하한은 다시 보지 않는다
(섞으면 0 은 줄기만 한다).

### 8-b. SNR 정의 — **창 전체 RMS** (1초 창, int8 영역)

`g = rms(e) / (rms(b) · 10^(SNR/20))`, rms 는 16,384 샘플 전체. SNR 은 창마다
**0~+20 dB 균등**, 전 클래스 같은 범위, 적용 확률 0.5.

이벤트 구간 RMS 를 쓰지 않는 이유.
1. **진단과 같은 단위다.** "외부 낙폭이 +5~+10 dB 혼합과 같은 크기" 는 창 전체
   RMS 로 잰 값이다. 정의를 바꾸면 그 수치로 범위를 정한 근거가 사라진다.
2. **이벤트 구간을 모른다.** FSD50K 는 약라벨이라 구간 경계가 없다. 에너지로
   추정하면 문턱이 새 하이퍼파라미터가 되고, 추정이 클래스마다 다르게 틀려
   **실효 SNR 이 클래스별로 달라진다** (규칙 6 이 막으려는 것).
3. **glass 에 더 세진다.** glass 는 창 전체 RMS 0 dB 에서 외부 세트보다 더
   떨어졌다 (재현 비 1.36~1.74). 이벤트 구간 RMS 는 창 전체 RMS 보다 크므로
   (과도음일수록), 같은 명목 SNR 에서 배경이 **더 커진다** — glass 의 과한
   혼합을 줄이는 방향이 아니라 늘리는 방향이다.

glass 에 대한 처리: 범위의 0 dB 쪽이 glass 에는 외부 세트보다 센 조건임을
**알고 그대로 둔다.** 클래스별로 범위를 달리하지 않고 (규칙 6), 대신 (가) 창의
절반은 혼합 없이 남고 (나) 8-c 에서 glass 를 따로 감시한다. 설계안 3-(나)의
"이벤트 구간 RMS 비교 실험" 은 **하지 않는다** (이 절로 대체).

### 8-c. 보고 항목

- **채택 판정** (3-(가) 그대로): 구성마다 v2 − v1 의 Welch 95% CI.
  외부 세트 macro-F1 (v1 정의, 시험셋 @300/h 문턱값 고정)의 CI 가 0 을 넘고
  **그리고** 기존 시험셋 macro-F1 @300/h 의 CI 하한 ≥ −0.02.
  ⚠️ 외부 세트의 v2 − v1 은 **시드 간 Welch CI** 로 본다 (구성당 3~5시드).
  구간 부트스트랩 CI 는 구성별 절대값에만 붙인다.
- **채택 단위**: 5개 구성 중 **과반(3개 이상)이 두 조건을 모두 충족**하면 v2
  채택. 구성별 결과는 전부 표로 낸다.
- **조건을 못 채웠을 때의 표현** (2026-10-05 추가, 학습 시작 전): 시드 3개의
  CI 가 0 을 포함해 채택 조건을 못 채우면 **"효과 없음" 이 아니라 "이 표본
  크기로 확인하지 못함"** 으로 적는다. CI 전체가 0 아래일 때만 "낮아졌다" 고
  쓴다. **판정 규칙 자체(채택/기각)는 바꾸지 않는다** — 문구만 그렇다.
- **클래스별 표** (판정과 별도): 구성 × 클래스의 recall 과 F1 을 v1 대 v2 로,
  기존 시험셋과 외부 세트 각각. 시드 평균과 v2 − v1 의 Welch 95% CI.
- **클래스 경고 표시**: 기존 시험셋에서 어느 클래스든 recall 의 v2 − v1 CI
  **하한이 −5pp 미만**이면 ⚠️ 로 표시하고 본문에 따로 적는다 (채택 판정을
  뒤집지는 않는다. glass 를 특히 본다).
- 지름길 점검 3-(다), 순위 유지 3-(라).

### 8-d. 논문 반영

- **채택되면**: 논문 본 표·그림의 정확도는 v2 수치로 바꾸고 v1 은 부록으로
  둔다. 지연·에너지는 구조가 같으므로 그대로다 (합성·비트 일치는 v2
  체크포인트로 다시 확인한다).
- **기각되면**: v1 을 유지하고 v2 는 부정 결과로 적는다 (진단과 함께).

### 8-e. 시험 전용 원칙

외부 세트는 시험 전용이다. **문턱값·SNR 범위(0~+20 dB)·적용 확률(0.5)을 외부
세트 결과를 보고 다시 맞추지 않는다.** 한 번 돌리고 그 결과를 보고한다.

"v2 가 외부 세트에서 더 잘 가린다" 고 말할 수 없고, "시험셋 문턱값에서 더 많이

적는다.

반면 **혼합 시험셋**(배경 창 불변, 같은 오경보)에서는 recall 이 전 구성에서

(`external-drop-diagnosis.md` 2.6절).

### 9.4 지름길 신호와 원인 (지시 3)

배경끼리 섞은 창(`diag/bgbg`, 시험셋 배경 + 시험셋 배경, SNR 0~20)에서 v2 의
발화율이 **2.7~3.9%** 로 원래 배경(2.06%, 고정)보다 높다. v1 은 1.5~2.0% 로
낮았다. 외부 오경보 증가와 같은 방향이다.

**원인 — 코드로 확인.** `datasets/safesound.py` 의 `_mix_noise()` 는
`target == background` 면 창을 그대로 돌려보낸다 (294행). `tools/kat_mix.py` 5번
항목이 `mix_prob=1` 에서도 배경 창이 바뀌지 않음을 확인했다 (통과). 즉 **v2
학습에서 배경 클래스 창에는 혼합이 적용되지 않았다.** 학습 중 "두 소리가 겹친
창" 은 전부 이벤트 라벨이었다.

> **가설**: 이벤트에만 혼합 → 혼합 흔적(겹침)이 이벤트 단서가 됨. 그래서 (a)
> 배경끼리 섞은 창에서 더 발화하고, (b) 유튜브 배경처럼 여러 소리가 겹친 외부
> 배경에서 오경보가 는다.

확인은 `dataset-v2.1-design.md` (배경 창에도 혼합)로 한다. **새 학습은 아직
하지 않았다.**
