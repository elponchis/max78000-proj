### 1.2 클래스 정의 — v1 기본, 실사용 태그 유지

v1 정의(`build_class_manifest.classify`)를 AudioSet strong 라벨에 **그대로** 옮기면 한 군데가
어긋난다. **FSD50K 어휘 200개에는 `Siren` 만 있고 하위 종류(Civil defense·Ambulance·Police·Fire
engine)가 없다** (`FSD50K.ground_truth/vocabulary.csv` 확인). 즉 FSD50K 의 사이렌은 종류와
무관하게 전부 `Siren` 이었다. AudioSet strong 은 조상 라벨을 붙이지 않아 "`Civil defense siren`
만 있고 `Siren` 은 없는" 구간이 생긴다 (train_v2 siren 그룹 347개 중 **121개**). 이것을 v1
문자열 규칙대로 음성으로 두면 v1 의 **뜻**(사이렌이면 양성)과 어긋난다.

→ **v1 동등 정의** (D1):

| 클래스 | v1 동등 (학습 라벨) | 실사용 태그 (index.csv `note` 에 보관, 학습에 안 씀) |
|---|---|---|
| siren | `Siren` **또는** 하위 4종 | 같음 |
| glass | `Glass shatter` | 같음 |
| scream | Screaming·Yell·Shout 중 하나 **이고** v1 군중 목록 없음 | `Screaming` 만 |
| dog_bark | `Bark` 또는 `Dog` | `Bark` 만 |
| background | 위 라벨이 전혀 없는 구간 (목록의 background 그룹) | 같음 |
| **배경 하드 네거티브** | Screaming·Yell·Shout **이고** 군중 목록 있음 → `background`, note `hard_neg:scream_crowd` (v1 규칙 그대로) | 실사용으로는 scream 양성 |

뒤집는 것이라 **이번에는 하지 않는다**. 태그만 남겨 두고, 정의 비교는 별도 실험이다.

### 1.3 가공 — `prepare_safesound.py` 경로와 같게

| 단계 | v1 (FSD50K) | v3 AudioSet 부분 | 근거 |
|---|---|---|---|
| 리샘플 | `resample_poly` 16 kHz | 이미 16 kHz 모노 wav (`download_clips.py --mono16k`, ffmpeg) | 외부 세트와 같은 경로. 리샘플러 차이는 외부 세트에도 있다 (external-set.md 9.1) |
| int8 | `to_int8` ×127 + `np.clip` 포화 | **같은 함수 import** | 정규화 없음 (CLAUDE.md 7장) |
| 창 선택 | 격자 + 에너지 필터 + PANNs 태거 | 격자 + 에너지 필터 + **강한 라벨 시각** (태거 대신) | 2절 |
| 절대 하한 | 이벤트 int8 0 비율 ≤ 0.95, 배경 없음 | **같음** | 규칙 동일 적용. 탈락 수는 2절 표 |
| 디지털 0 채움 | 16샘플 이상 0 런을 같은 split 배경 베드로 | **같은 함수**, 베드 풀 = train_v2 **배경 창** (같은 split·같은 출처) | 아래 |
| 저장 | 1.224초(창 + 양옆 100 ms), 가장자리는 `left_margin`/`right_margin` 축소 | **같음** | shift 증강 호환 |
| 태거·청취 | PANNs 임계값 + 청취 | **없음** (라벨은 strong 라벨 그대로) | 한계 10절 |

**디지털 0 (집계).** 정확히 0.0 인 런(≥16샘플)이 2,362구간 중 **638구간**에 있다 (배경 228,
glass 185, scream 97, dog_bark 66, siren 62). 런 8,759개, 길이 중앙 1.7 ms, 90% 27.5 ms, 최대
8.7초. 100 ms 이상 499개, 1초 이상 132개 (영상의 무음 구간). v1 규칙대로 **채운다**. 베드 풀을
train_v2 배경으로 두는 이유는 FSD50K 배경을 유튜브 창에 깔면 두 출처가 한 창에 섞이기
때문이다 (라벨에는 영향 없지만 출처 단서가 된다). 채움 내역은 v1 과 같이 note 에 남긴다.

**짧은 파일.** 2,362개 중 **367개가 10초 미만**(최소 1.02초) — 영상이 구간 끝보다 먼저 끝난
경우다. 창 규칙이 실제 오디오 길이로 판정하므로 따로 처리하지 않는다. 1.024초 미만 1개(glass)는
창이 나오지 않는다.

### 1.4 webm 폴백 54개 — **포함** (D2)

| 근거 | 집계 |
|---|---|
| 앞 9.967초 절단이 성립하려면 구간 시작이 10초 이상이어야 한다 (프리롤이 꽉 차야 한다) | **54개 전부 start ≥ 10초** |
| 오프셋은 external_v1 에서 **독립 기준 51건**으로 검증됐다 (평균 9.967초, sd 0.018초, 범위 9.899~9.972) | 최악 오차 **68 ms** — 창 1.024초, 겹침 규칙(≥0.5초)의 여유 안 |
| 오프셋은 yt-dlp 구간 다운로드 + Opus 프리롤의 성질이지 영상 고유값이 아니다 | 51/51 이 73 ms 안에 모였다 |
| 그룹 | background 35, glass 9, siren 4, dog_bark 4, scream 2 — 이벤트는 **19구간, 최대 38창 (이벤트 창의 2%)** |
| 파일 길이 | 10초 53개, 8초 1개 (이벤트 끝이 파일 밖인 것 1개 → 창 규칙이 자동으로 뺀다) |

제외하면 잃는 것은 2% 뿐이지만, **m4a 가 없는 영상**이라는 집단을 통째로 빼는 것이라 표본
선택이 하나 더 생긴다. 포함하고 index.csv note 에 `webm_trim=1` 을 남겨 나중에 빼고 볼 수
있게 한다. train_v2 안에서의 직접 검증(상호상관)은 하지 않았다 — 하고 싶으면 외부데이터
세션이 이벤트 19구간만 `webm_audit.py --retry --full` 로 돌리면 된다 (필수 아님).

### 1.5 저장 구조와 로더

```

  MANIFEST.json                 tag dataset-v3, 창 수·원본 수, 규칙 파라미터
  train/<cls>/index.csv         v1 행 그대로 + AudioSet 행 (shard 번호 100부터)
```

- index.csv 열은 v1 과 같다. `clip_id` = `segment_id`, `fsid` = `yt:<ytid>` (문자열 —
  `_fsid_unit` 은 해시라 상관없다), `start_sample` = 구간 안 창 시작, note =

  `SafeSoundMelU1000V3`, `SafeSoundMelU800V3`, `SafeSoundMelIncV3` — 전부 `mix_prob=MIX_PROB,

- **클래스 가중치는 v3 창 수로 다시 계산**한다 (`class_weights(root)`; `V3_TRAIN_COUNTS`

## 2. 창 추출 규칙과 클래스별 창 수

**규칙 (실행 전 고정).**

1. 후보 격자: 모델 창 1,024 ms(16,384샘플), hop 250 ms, 구간 전체. 가장자리는 저장 여유를
   줄여 쓴다 (v1 과 같음).
2. **양성 판정 (이벤트 구간)**: 그 구간의 strong 라벨 중 해당 클래스 mid 의 시각 구간들과
   창의 **겹침 길이 ≥ min(0.5초, 그 구간의 이벤트 총 길이)**. 즉 0.5초보다 짧은 이벤트는
   **통째로** 창 안에 있어야 하고, 긴 이벤트는 창의 절반 이상을 차지해야 한다. 이벤트가
   없는 창은 양성 구간에서도 **쓰지 않는다** (배경으로도 쓰지 않는다 — 같은 영상의 다른
   순간은 라벨이 약하다).
3. 에너지 필터: 이벤트 창은 int8 0 비율 ≤ 0.95 (v1 `--floor-zero`). 배경은 하한 없음.
4. 선택: 겹침 길이 내림차순 → RMS 내림차순으로 **서로 겹치지 않게** 구간당 최대 **2개** (D3).
   배경은 RMS 내림차순 (v1 배경 정책과 같음). `scream_crowd` 하드 네거티브는 비명 구간과
   겹치는 창을 고른다 (헷갈리는 소리가 들어 있어야 하드 네거티브다).
5. 디지털 0 채움은 선택 뒤에 (1.3).

  소수) / 11,967 ≈ **35%**. external-set.md 10.4 의 "20배 차이" 가 섞이는 결과다. 시험셋 배경
  (49.9% 하드 네거티브) 오경보에 영향이 있을 수 있어 6절 조건 C 로 지킨다.

## 4. 평가

둘 다 낸다. **외부 세트로 아무것도 고르지 않는다** (문턱값·SNR·확률·창 상한 전부 시험셋과
사전 등록으로만 정한다).

| 세트 | 무엇 | 문턱값 | 비고 |
|---|---|---|---|
| 기존 시험셋 (FSD50K, 5,207창) | macro-F1 @300/h, 클래스별 recall·F1, 배경+배경 혼합 창 발화율 | 시험셋 자체 @300/h | v1·v2.1 과 같은 채점 (`eval_v2.py`) |
| 외부 세트 external_v1 (v1 정의: 양성 326 = siren 84·glass 74·scream 81·dog_bark 87, 배경 264) | (a) **시험셋 문턱값 고정** macro-F1·클래스별 recall·배경 발화 창 수 | 시험셋 @300/h | 조건 1 과 같은 지점 |
| 〃 | (b) **외부 오경보를 맞춘 비교** — 외부 배경 @300/h (= 5창) **과** 외부 배경 10% (= 26창) 두 지점의 macro-F1·recall | 외부 배경에서 정함 | 5창 지점은 v2.1 과 이어지는 보고용, 26창 지점은 분해능 때문에 추가 (6절) |
| 〃 | (c) **문턱값 무관**: 클래스별 AP (양성 = 그 클래스, 음성 = 외부 배경 264, 점수 = 로짓 차 `l_c − l_bg`) 의 평균 mAP | 없음 | 재현율과 오경보를 한 수로 본다 |

**문서·논문에 반드시 적는 문장.** *"v3 부터 외부 세트는 '다른 출처' 가 아니다. 학습에 넣은
AudioSet strong **train** 분할과 **같은 출처**(유튜브, 같은 라벨 체계, 같은 손실 압축)이고
**영상만 다르다** (영상 ID 겹침 0, 3절). 따라서 v3 의 외부 점수 향상은 출처 이동에 대한
일반화가 아니라 **같은 출처의 보지 못한 영상에 대한 성능**이다. v1·v2.1 의 외부 점수는 출처
이동 조건의 값이고, v3 와 같은 축에서 읽으면 안 된다."* 또한 v3 뒤에는 학습에 쓰지 않은
출처의 평가 세트가 **없다** — 10절.

비교는 전부 **v3 − v2.1, 같은 시드(1~3)끼리**, Welch 95% CI. v1 은 참고열.

### 6.2 조건 (간격 400 과 ④ 각각 판정, v3 − v2.1 시드 1~3)

| # | 조건 | 통과 기준 | 분해능 근거 |
|---|---|---|---|
| **A** | 외부 macro-F1 (v1 정의, 시험셋 @300/h 문턱값 고정) | **CI 하한 > 0** | 반폭 0.045 → 실제 +0.05 이상이어야 통과. 이보다 작은 향상은 이 설계로 **못 가린다**고 미리 적는다 |

- **1단계 통과(= 2단계로 확대)**: 간격 400 과 ④ **둘 다** A·B·C·D·E 충족. 하나만 충족하면
  "구성에 따라 다르다" 로 적고 **확대하지 않는다** (결정은 사용자).
- **최종 채택(본 표 v3)**: 돌린 5개 구성의 **과반(3개 이상)** 이 A·B·C·D·E 충족. 아니면 본 표는
  v2.1 그대로, v3 는 부록.
- 5창 지점(외부 배경 @300/h)은 **보고만** 한다 — 조건으로 쓰지 않는다. 26창 지점도 보고만.

### 6.3 "얼마나 올라야 하는가" — 클래스별 재현율과 macro-F1 의 목표치

조건 A·B 는 "확인된 향상" 이다. **"해결"** 은 더 세게 정한다 (논문 문장이 달라진다).

| 지표 (간격 400 기준, v2.1 값) | v2.1 | "향상 확인" (A·B) | **"해결"** 선언 기준 | 판정 가능성 |
|---|---:|---|---|---|
| 외부 macro-F1 (시험셋 문턱값) | 0.435 | +0.05 이상 (CI 하한 > 0) | **≥ 0.57** — 시험셋 F1(0.709) 과의 격차 0.274 를 **절반** 이상 닫음 (+0.137) | 반폭 0.045 의 3배 |
| 외부 recall scream | 17.3% | — | **점 추정 +10 pp 이상** (≥ 27%) | sd 2.3 pp → 평균 차 표준오차 1.9 pp, +10 pp = 5σ |
| 외부 recall siren | 20.7% | — | **점 추정 +10 pp 이상** (≥ 31%) | sd 3.7 pp → 표준오차 3 pp, +10 pp = 3.3σ |
| 외부 recall glass / dog_bark | 22.4 / 37.7% | — | **내려가지 않음** (점 추정 ≥ −3 pp) | sd 3.4 / 6.2 pp |

④ 에도 같은 식(격차 절반: 0.548 − 0.285 = 0.263 → 외부 F1 ≥ 0.417)을 적용한다. scream·siren 을
고른 이유: 외부 recall 이 가장 낮은 두 클래스이고 (17~21%), v1 → v2.1 에서도 가장 덜 올랐다.
"해결" 을 못 채우고 A·B 만 통과하면 논문에는 **"같은 출처 영상에서 향상 확인, 격차는
남는다"** 로 적는다. 어느 경우에도 격차의 나머지는 코덱·라벨 정의·청취 미검증(10절)로
설명하되 **분리해 재지 않았다**고 쓴다.

### 6.4 바꾸지 않는 것

외부 세트를 보고 창 상한·겹침 규칙·정의·문턱값을 고치지 않는다. 시드를 늘리지 않는다.
증강은 v2.1 그대로. 한 번 돌린다. 1단계 결과를 보고 2단계 **대상**을 바꾸지 않는다 (확대는
"5개 전부" 아니면 "안 함").

- DNS 일시 실패 2건(external-set.md 10.2)은 재시도하면 받아질 가능성이 높다 — 같은 요청에

  달라져 비교가 깨진다. 못 받으면 추가 없이 간다 (설계는 그대로 성립한다).

## 8. 다시 재지 않는 것 (지연·에너지·비트 일치)

가중치만 바뀌고 구조·합성 설정·펌웨어가 같다. v2.1 에서 다섯 구성 모두 합성 사이클·가중치
메모리가 v1 과 같았고 지연도 같았다 (`synthesis-check.md` 15절). 따라서:

- 지연·에너지·손익분기표는 **재지 않는다**. 본 표의 지연·에너지 열은 v2.1 실측 그대로.
- **최종 채택 뒤** 시드 1 체크포인트로 `scripts/synth_v21.sh` 와 같은 절차(prefix `_v3`)로 합성하고
  **NPU 비트 일치만** 확인한다: 5개 구성 + CMSIS-NN(④ v3 가중치 재추출) = **보드 재연결 6회**.
  전처리 KAT 는 가중치와 무관하므로 하지 않는다.
- v3 가 채택되지 않으면 보드 작업은 없다.

   코드 상수로 고정하고 커밋.
2. `datasets/safesound.py`: `V3_TRAIN_COUNTS`, `SafeSound*V3` 등록 5개. 로더 코드 변경 없음.
3. KAT (전부 통과해야 1단계 시작):
   - **v3 로더에서 AudioSet 행을 뺀 집합 = v2.1 로더와 창 단위 비트 일치** (같은 시드로 같은
     증강 결과). 샤드 링크·index 병합이 v1 쪽을 건드리지 않았다는 증거.
   - index 의 모든 `yt:` fsid 가 external_v1 영상 ID 와 겹치지 않음 (3절을 빌드 단계에서 다시).
   - 창 수가 2절 표와 일치 (다르면 규칙 구현이 다른 것).
   - 채움 베드가 전부 train_v2 배경에서 왔는지 (note 의 출처 clip_id 로 확인).
   - 청취용 wav 클래스별 10개 (사용자 청취는 선택 — 하지 않으면 10절에 "청취 미검증" 유지).

## 10. 한계 (결과와 무관하게 적는다)

0. **AudioSet 출처 창에도 배경 혼합 증강이 같은 규칙으로 걸린다** (사전 등록 3). v2.1 의
   `_mix_noise()` 는 출처를 가리지 않는다 — AudioSet 이벤트·배경 창도 확률 0.5, SNR 0~+20 dB 로
   같은 split 의 train 배경(v1 FSD50K 배경 **과** AudioSet 배경이 한 풀)과 섞인다. 즉
   유튜브 창 위에 FSD50K 배경이, FSD50K 창 위에 유튜브 배경이 얹힐 수 있다 (최종 풀 9,274창). 규칙을 출처별로
   바꾸지 않았다 (바꾸면 v2.1 과의 차이가 데이터 하나가 아니게 된다). 결과 보고에 학습 창의
   재현율을 **출처별(v1 계열 / AudioSet)** 로 나눈 표를 넣어 한쪽 출처만 외우는지 본다
   (`tools/eval_v3.py --train-by-source`).

1. **외부 세트가 더 이상 출처 이동을 재지 않는다** (4절). v3 뒤에는 학습에 쓰지 않은 출처의
   평가 세트가 없다. 출처 이동 일반화에 대한 주장은 v1·v2.1 의 외부 결과로만 할 수 있고,
   v3 의 외부 결과와 같은 축에 놓지 않는다.
2. **AudioSet 라벨은 청취 검증 전이다.** v1 은 PANNs 태거 + 청취로 걸렀다 (glass 정답률 72%
   등). v3 의 AudioSet 부분은 strong 라벨의 시각 경계만 믿는다. 라벨 노이즈가 v1 부분보다 클
   수 있다.
3. **scream 의 56% 가 Yell·Shout** 이고 군중 동반 비명 110구간은 v1 규칙대로 배경이다.
   비명·환호 경계(CLAUDE.md 8장 한계 1)가 AudioSet 쪽에도 그대로 있다.
4. **dog_bark 46구간(14%)은 하한 규칙으로 전부 탈락**했다 — 조용한 원거리 개 짖음은 v1 기준으로
   학습에 들어가지 않는다. 외부 dog_bark 의 조용한 창(10/87 이 0 비율 > 0.5)과 같은 유형이다.
5. **배경 하드 네거티브 농도가 39% → 약 33% 로 내려간다** (AudioSet 배경은 무작위 추출).
   시험셋 오경보(조건 C·D)로 지킨다.
6. **유튜브 손실 압축이 학습에 들어간다.** 외부 세트의 코덱 차이 한계(external-set.md 9.1)가
   사라지는 것이 아니라 학습·평가 양쪽에 같은 코덱이 있는 조건으로 바뀐다. 실기기 마이크
   입력은 어느 쪽 코덱도 아니다.
7. **오디오 재배포 금지** — 재현은 "영상 ID 목록 + 각자 다운로드" 다. 삭제 영상(유효율 84%)
   때문에 같은 목록으로 같은 집합을 다시 만들 수 없다. MANIFEST 에 유효 구간 ID 를 남긴다.
8. **3시드**라 +0.05 미만의 외부 향상은 가릴 수 없다 (6.1).
9. webm 54개의 오프셋은 external_v1 의 51건 검증을 **옮겨 쓴 것**이다 (1.4).
10. 집계 스크립트는 일회용이었다. 2절·3절·7절 수치는 9절의 빌더가 같은 규칙으로 다시 내며,
    다르면 빌더가 아니라 이 문서를 고친다.
