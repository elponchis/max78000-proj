[조용]` 48창 25% 는 표본이 모자라 해석하지 않는다.

## 3. D-1 vs B — LR·스케줄은 같지만 **초기화만 다른 것은 아니다**

⚠️ 앞서 이 비교를 "초기화만 다르다" 고 적었는데 **틀렸다. 세 가지가 다르다.**

| | B kws20(ft) | D-1 fb(abs) |
|---|---|---|
| 초기화 | KWS20 v3 사전학습 (conv 8층) | 멜 대역통과 FIR 50밴드 (첫 층만) |
| **첫 층 활성화** | ReLU (기준선과 같다) | **`Abs`** |
| **bias** | **True** (체크포인트의 conv bias 를 받기 위해) | False (기준선과 같다) |
| LR / 스케줄 | 0.0003 / `..._ft.yaml` | 0.0003 / `..._ft.yaml` ← 같다 |

같은 것은 LR·스케줄·에폭·QAT 시점이고, 다른 것은
**초기화 방식 + 첫 층 활성화 + bias** 다.

    D-1 0.498  −  B 0.457  =  +0.041

**이 +0.041 을 결론으로 쓰지 않는다.** 이유 둘.
1. 위 표대로 세 가지가 함께 다르므로 "초기화 방식의 차이" 로 귀속할 수 없다
2. **시드 잡음과 장치 차이의 크기를 아직 모른다.** D-1 은 CPU, B 는 GPU 학습이고
   양쪽 다 단일 시드다. +0.041 이 그 변동 안일 수 있다

→ 지금 측정 중인 것이 정확히 그 눈금이다 (`TASKS.md`):
`④ 시드 1 CPU`(GPU 판과 비교 → **장치 차이**), `④ 시드 2 CPU`(→ **시드 잡음**),
`D-1 시드 2 CPU`. 세 값이 나온 뒤에 +0.041 과 +0.111 을 해석한다.

# 부록 A. 해상도 곡선 — 첫 층 커널 k = 1 / 2 / 4 (2026-09-29 착수)

## A.1 왜 하는가

D-1 의 첫 층은 `k=1` 이라 **128탭 FIR** 이다(8ms). ① 로그 멜은 `n_fft = 512`
(32ms) 를 쓴다. **"① 과의 격차가 주파수 해상도 때문인가"** 에 답하려면 같은
창 길이를 줘 보면 된다.

입력 채널 축이 프레임 내 잔 시간축이므로(`x[r][c] = sample[c*128 + r]`),
커널 위치 `j` 는 **프레임 하나(=128샘플)만큼 떨어진 구간**을 본다.

```
out[o][c] = Σ_r Σ_j W[o][r][j] · x[r][c+j]
          = Σ_t W'[o][t] · sample[c*128 + t],     t = j*128 + r
```

→ **탭 수 = k × 128**, 홉은 128 그대로(겹침이 생긴다).

| k | FIR 길이 | 시간 | 분해능 (Hann 메인로브) | 비고 |
|---:|---:|---:|---:|---|
| 1 | 128탭 | 8.0ms | 약 500Hz | 현재 D-1 |
| 2 | 256탭 | 16.0ms | 약 250Hz | |
| **4** | **512탭** | **32.0ms** | **약 125Hz** | **① 멜 `n_fft=512` 와 창 길이 동일** |

세 점으로 **해상도–성능 곡선**을 만든다. k=4 가 ① 에 가까워지면 격차의
상당 부분이 해상도이고, 그대로면 해상도가 아니라 **로그 압축·멜 스케일·
2D 이웃 구조** 쪽이다.

## A.2 패딩 결정

`pad = (k-1)//2` → k=1/2/4 에서 **0 / 0 / 1**, 출력 길이 **128 / 127 / 127**.

이 선택의 이유는 **뒤쪽이 전부 같아지기 때문**이다. 이후 층의 풀링·컨볼루션
내림 연산을 타고 내려가면 세 경우 모두 꼬리가 `4 × 64` 로 같고, **FC 입력이
256 으로 동일**하다. 즉 바뀌는 것이 `voice_conv1` 하나뿐이다.

`pad = k//2`(0/1/2, 길이 128/128/129) 로 하면 k=4 에서 뒤쪽 차원이 달라져
FC 크기까지 바뀐다 — 그러면 "커널만 바꿨다" 가 성립하지 않는다.

이게 조용히 틀어지는 것을 막으려고 `AI85SafeSoundNet._flatten_len()` 이
**0 텐서를 conv 스택에 한 번 흘려 FC 입력 길이를 실제로 구한다.** 하드코딩된
`4*64` 였다면 shape 오류로 죽거나, 더 나쁘게는 죽지 않고 다른 모델이 된다.

## A.3 파라미터 수

`tools/kat_entrypoints.py` 실측 (`train.py` 인자 규약 그대로 생성):

| 진입점 | k | conv1 가중치 | 전체 params | 442,368B 대비 |
|---|---:|---:|---:|---:|
| `ai85safesoundnet_fb` | 1 | 12,800 | **165,457** | 36.6% |
| `ai85safesoundnet_fb_k2` | 2 | 25,600 | **178,257** | 39.4% |

## A.4 학습 전 톤 검산 — 탭이 커널 위치별로 올바르게 나뉘는가

`to_conv_weight()` 가 `(out, k*128)` FIR 을 `(out, 128, k)` 로 재배치한다.
`t = j*128 + r` 이 맞는지는 **단일 톤을 넣어 기대 밴드가 켜지는지**로 검산한다.
배치가 틀리면 톤이 엉뚱한 밴드에 실린다.

`bash data/logs-local/tone_all.sh` 결과 — **7개 톤 × 3개 커널 = 21/21 전부
기대 밴드 적중.** 값은 최대 밴드와 **다른 중심 주파수** 채널 최대의 비
(같은 밴드의 cos/sin 짝은 제외) 를 dB 로 나타낸 **인접 분리도**다.

| 톤 | k=1 (128탭, 500Hz) | k=2 (256탭, 250Hz) | k=4 (512탭, 125Hz) |
|---:|---:|---:|---:|
| 125Hz | 1.0 dB | 2.1 dB | **9.5 dB** |
| 200Hz | 0.2 | 2.0 | **8.4** |
| 300Hz | 0.5 | 1.8 | **7.7** |
| 400Hz | 0.4 | 1.5 | **6.3** |
| 1000Hz | 1.5 | 6.5 | **36.8** |
| 3000Hz | 9.1 | 31.3 | **54.6** |
| 6000Hz | 32.1 | 48.8 | 52.4 |

- k=1 은 **500Hz 아래 9개 밴드가 서로 분리되지 않는다** (분리도 0.2~1.0dB —
  사실상 구분이 없다). 저역에서 밴드가 겹쳐 초기화된다.
- k=2 는 250Hz 아래 4개 밴드가 미분리.
- **k=4 는 "모든 밴드가 분해능(125Hz) 위에 있다"** — 미분리 밴드 0개.
  저역 분리도가 6~9dB, 중역은 37~55dB.

→ 초기화가 의도대로 들어간다는 것과, **해상도가 실제로 개선된다**는 것을
학습 전에 확인했다. 성능이 안 오르면 "초기화가 잘못 들어가서" 가 아니다.
