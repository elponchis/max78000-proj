# B 사전 확인 — STFT 를 NPU 고정 Conv1d 로 옮기기 (2026-10-02)

> **재학습 없이** 답할 수 있는 것만 본 사전 확인이다. STFT 층의 **합성**까지
> 했고(5절) 보드 측정은 하지 않았다. 5절의 시간·에너지는 **추정**이다.
> **판정: B 는 구현하지 않고 분석 결과로만 싣는다 (5절).**

## 구성 B 의 정의 (이 문서의 해석)

```
int8 파형 ─▶ [NPU] 고정 Conv1d (DFT 기저 × Hann, 정수 가중치, 활성화 없음, 32bit 출력)
          ─▶ [CPU] re² + im² → 멜 64 → 로그 → int8
          ─▶ [NPU] 기존 ①′ 2D CNN
```

프레임 정의는 ①′ (hop 250, 패딩 없음, 끝 정렬). ①′ 의 CPU 전처리 중
**프레임 구성 + rfft** (① 실측에서 68%)를 NPU 로 옮기는 것이다.
⚠️ A·B 는 레포에 정의·실행 기록이 없었다 — 위는 지시문의 한 줄
("고정 STFT Conv1d → int32 → CPU 파워·멜·로그 → 기존 ① 체크포인트 평가")을
이 세션이 구체화한 것이다. A(STFT 로그 멜 × 1D 뒷단 3시드)는 **실행하지 않았다.**

## 1. 하드웨어 수용 (계산, `tools/b_precheck.py`)

| 항목 | 값 |
|---|---|
| 입력 배치 | 채널 250 (hop 한 칸의 샘플) × 시간. 프레임 = 연속 3칸 (750 ≥ 512) |
| 층 | Conv1d(in 250, out 510 = re/im × 255빈, k=3), 활성화 없음, 32bit 출력 |
| 3번째 탭 | 12샘플만 쓴다 — 나머지 가중치는 0 (그래도 저장된다) |
| 32bit 출력 | **마지막 층에서만** 가능 → STFT 층이 독립 네트워크, ①′ 모델과 함께 적재 ((c) 와 같은 방식) |
| MAC | 64프레임 전부 24.48M (① 모델 18.9M 의 1.29배) / 증분 16프레임 6.12M |
| 출력 데이터 | 510ch × 64 × 4 B = 130,560 B (512KB 의 24.9%) |

| STFT 층 가중치 | STFT 층 | + ①′ 모델 (157,472 B) | 442KB 대비 | |
|---|---:|---:|---:|---|
| **8bit** | 382,500 B | 539,972 B | **122.1%** | **초과 — 들어가지 않는다** |
| 4bit | 191,250 B | 348,722 B | 78.8% | 들어간다 |
| 2bit | 95,625 B | 253,097 B | 57.2% | 들어간다 |

## 2. 특징 차이 — 정수 기저 대 float FFT (시험셋 500창, int8 로그 멜)

| 기저 | 불일치 | >1 LSB | >2 LSB | 최대 | 평균 \|차\| |
|---|---:|---:|---:|---:|---:|
| 8bit | 20.72% | 6.28% | 3.77% | 39 LSB | 0.43 LSB |
| 4bit | 68.28% | 49.43% | 40.79% | 130 LSB | 9.26 LSB |

누산은 정확한 정수라 이 시뮬레이션이 곧 기기 값이다 (2의 거듭제곱 스케일 제외).
차이는 **기저의 양자화 오차**에서 온다 — 조용한 빈에서 누설이 로그 바닥을 올린다.

## 3. 정확도 — **같은 ①′ 체크포인트**, 특징만 교체 (재학습 없음, @300/h macro-F1)

| | s1 | s2 | s3 | 평균±sd | ①′ 대비 | Welch 95% CI |
|---|---:|---:|---:|---:|---:|---|
| ①′ (float FFT, CPU) | 0.6622 | 0.6745 | 0.6716 | 0.6694±0.0064 | — | — |
| **B 8bit 기저** | 0.6645 | 0.6763 | 0.6732 | 0.6713±0.0061 | **+0.0019** | [−0.0144, +0.0182] |
| B 4bit 기저 | 0.6479 | 0.6483 | 0.6616 | 0.6526±0.0078 | **−0.0168** | [−0.0354, +0.0017] |

⚠️ 세 시드는 **같은 체크포인트의 짝**이다. 짝 차이는 8bit +0.0023 / +0.0018 /
+0.0016, 4bit −0.0143 / −0.0262 / −0.0100 으로 방향이 일정하다 — Welch(독립
가정)는 여기서 보수적이다. 4bit 는 "CI 가 0 을 포함" 이지만 **세 시드 모두 낮다.**

## 4. 판정

- **8bit 기저는 특징으로서 충분하다** (재학습 없이 ①′ 와 차이 +0.002) —
  그러나 **442KB 에 들어가지 않는다** (122%).
- **4bit 기저는 들어가지만** 재학습 없이는 −0.017 이다. 4bit 특징으로 **재학습**
  하면 회복될 수 있다 (미확인).
- 8bit 로 넣으려면 구조를 바꿔야 한다 (전부 **미검증**, 재학습 필요):
  n_fft 256 (in 250, out 254, k=2 → 127,000 B, 합계 64.3%) / 쓰는 빈 축소 /
  ①′ 모델 축소.
- B 가 줄일 수 있는 것은 ①′ CPU 전처리 11.53 ms 중 프레임 구성 + rfft 몫이다
  (① 단계 실측 비중 68% → 약 7.8 ms, **추정**). 남는 CPU 몫(파워·멜·로그)은
  약 3.7 ms (**추정**). NPU 쪽 STFT 층 지연은 합성 전이라 `TBD`.

## 5. 비용 — 합성으로 본 NPU 사이클 (2026-10-02, 학습·구현 없음)

4bit STFT 층을 `ai8xize.py` 로 합성했다 (`tools/b_stft_synth.py`,
`data/logs-local/synth_b_stft.sh`, 프로세서 64개 × 4패스).

| | 64프레임 전부 | **증분 16프레임** |
|---|---:|---:|
| 입력 | 250ch × 66 | 250ch × 18 |
| MAC | 24,480,000 | 6,120,000 |
| **NPU 사이클 (합성 로그)** | **131,603** | **32,915** |
| 50 MHz 환산 | 2.63 ms | **0.66 ms** |
| 가중치 메모리 | 191,250 B (43.2%) | 같다 |

①′ 모델(35.6%)과 합쳐 **78.8%** — 두 네트워크가 함께 들어간다.
382,500 가중치 중 0 이 아닌 것은 186,889개(49%)다 (세 번째 탭과 창 가장자리).

### B 대 ①′ — 판단당 전처리 시간·에너지 (**전부 추정**)

실측인 것: ①′ 전처리 11.53 ms, 링 버퍼 풀기 0.25 ms, ① 의 단계별 사이클.
**나머지는 추정**이다 — 가정을 아래에 적는다.

| 항목 | ①′ (CPU 전부) | B 증분 (추정) | B 64프레임 (추정) | 가정 |
|---|---:|---:|---:|---|
| CPU 프레임 구성 + rfft | 약 7.8 ms | — | — | ① 단계 비중 68% |
| NPU 입력 적재 | — | 0.30 ms | 1.10 ms | 26.3 사이클/워드 (④ 적재 실측 107,832 ÷ 4,096), 4채널/워드 |
| NPU STFT | — | 0.66 ms | 2.63 ms | 합성 사이클 ÷ 50 MHz |
| int32 출력 읽기 (510ch × 프레임) | — | 2.15 ms | 8.59 ms | 같은 26.3 사이클/워드 |
| CPU 파워 + 멜 + 로그 | 약 3.5 ms | 3.86 ms | 15.45 ms | ① 단계 실측 24,133 사이클/프레임 |
| 링 버퍼 풀기 | 0.25 ms | 0.25 ms | — | 실측 |
| 네트워크 전환 (2회) | — | 0.2 ms | 0.2 ms | (c) 의 레지스터 쓰기 413회 × 26 사이클 |
| **전처리 합계** | **11.53 ms (실측)** | **약 7.4 ms** | 약 28.0 ms | |
| **판단 1회** (+ 적재·추론·출력 5.17 ms) | **16.70 ms** | **약 12.6 ms (−25%)** | 약 33.1 ms (+98%) | |
| 에너지 (가) 데이터시트 | 약 281 µJ | 약 282 µJ (**+0.1%**) | — | CPU 구간 11.26 mW (CNN 켜짐), NPU 40.79 mW |
| 에너지 (나) 선행연구 | 약 606 µJ | 약 535 µJ (−12%) | — | CPU 24.8 mW, NPU 71.7 mW |

- **시간은 약 25% 준다 (추정)**. rfft 를 NPU 로 옮긴 이득(약 7.8 ms)의 절반 가까이를
  **int32 출력 읽기(2.15 ms)** 가 되가져간다 — NPU 메모리 접근이 워드당 26 사이클이다.
- **에너지는 줄지 않을 수 있다**: 데이터시트 전력으로는 **+0.1%** (CPU 가 쉬는
  동안 NPU 가 더 높은 전력으로 돈다), 선행연구 전력으로는 −12%.
- 64프레임을 전부 NPU 에서 다시 계산하는 판은 ①′ 증분보다 **느리다**.
- 여기에 **정확도 비용**이 붙는다: 4bit 기저는 재학습 없이 −0.017 (3절).

### 판정 (사전에 정한 규칙: 이득 10% 미만이거나 에너지가 늘면 구현하지 않는다)

시간 이득은 10% 를 넘지만(약 25%, 추정) **데이터시트 기준 에너지는 늘지도
줄지도 않는다 (+0.1%)**. 규칙의 "에너지가 늘면" 에 걸리는 경계 사례다.
→ **B 는 구현하지 않고 "분석 결과" 로만 싣는다.** 근거: (1) 에너지 이득이
출처에 따라 +0.1% ~ −12% 로 불확실하다, (2) 4bit 기저의 정확도 비용(−0.017)을
재학습으로 회복해야 한다, (3) 추정의 절반(출력 읽기·전환)이 미측정이다.
논문에는 **"FFT 를 NPU 로 옮기면 연산은 0.66 ms 로 줄지만 int32 결과를 CPU 로
되가져오는 비용이 이득의 절반을 상쇄한다"** 로 쓴다.
