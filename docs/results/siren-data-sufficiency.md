# `siren` 데이터 충분성 점검 (V-4)

`siren` 은 여러 실험에서 **매번 먼저 무너지는 클래스**다.

| 실험 | siren 변화 | 다른 클래스 |
|---|---:|---|
| 제곱근 가중치 (파형) | **−4.7pp** | glass·dog_bark 상승 |
| 음량 정규화 (b1) | **−8~−11pp** | glass 상승 |
| PANNs 상한 대비 (@300/h) | **−59.2pp** | glass 는 ①이 **이긴다** (+13.1pp) |

공통점은 **고유 원본이 202개(train 137)뿐**이라는 것이다 (CLAUDE.md 4장).
이 문서는 그 가설을 검증할 세 갈래를 정리한다.

---

## 1. 학습 곡선 (설계 — 실행 대기)

**목적**: 100% 지점에서도 기울기가 남아 있으면 **데이터 부족**이 근거가 된다.
평평해지면 데이터가 아니라 다른 것이 병목이다.

| 항목 | 값 |
|---|---|
| 축소 단위 | **원본 ID(fsid) 단위** — 창 단위로 줄이면 같은 원본이 흩어져 누수와 같은 효과 |
| 비율 | 25 / 50 / 75 / 100% (train 137 → 34 / 68 / 103 / 137) |
| 다른 클래스 | **그대로** (siren 만 줄인다) |
| 모델 | ① log-mel, 각 1회 (시드 1) |
| 지표 | 테스트 `siren` F1·recall @300/h, 그리고 macro-F1 |
| 비용 | ① 실행당 약 81분 × 4 = **약 5.4시간** (WSL CPU) |

⚠️ **클래스 가중치를 고정해야 한다.** `class_weights()` 가 실측 수량에서
나오므로, siren 을 줄이면 가중치가 자동으로 올라가 **두 가지가 동시에**
바뀐다. 실험은 **v1 상수 가중치를 그대로 쓴다** — 그래야 "원본 수" 만의
효과가 된다.

⚠️ 축소는 **train 만**이다. test 65원본은 고정해야 네 점이 비교된다.

### ★ 판정 규칙 — **학습 전에 박는다** (2026-09-30)

> **75% → 100% 구간의 상승이 그 지점 CI 폭보다 크면 "데이터 추가 가치 있음".**

- 대상 지표: 테스트 `siren` 의 **@300/h recall 과 F1** (argmax 아님).
- CI: **원본 단위 부트스트랩 95%** (n_boot 2,000). 테스트 siren 원본이
  **54개**뿐이라 1회 값만으로는 판정할 수 없다 (창 단위 평가 기준 —
  아래 부록 "원본 수 기준"). 창 단위로 내면 같은 녹음의
  창을 독립 표본으로 세어 구간이 실제보다 좁아진다 (5장 규칙 1).
- ⚠️ **25→50→75 가 오르는 것만으로는 부족하다.** 어떤 학습 곡선이든 초반에는
  오른다. **끝 구간(75→100)의 기울기**가 판정 대상이다.
- 평평하면(상승 ≤ CI 폭) 원본 수가 병목이 아니고 **2·3·4번이 무의미**해진다.

### 구현 (완료)

| 항목 | 구현 |
|---|---|
| 부분집합 | `datasets/safesound.py` 의 `subset_frac={cls: frac}` |
| 단위 | **fsid**. `_fsid_unit()` = blake2b 앞 8바이트 → [0,1) |
| 포함 관계 | 해시값 < frac 인 것만 남긴다 → **25 ⊂ 50 ⊂ 75 ⊂ 100 보장** |
| 실측 | siren 원본 **26 / 57 / 91 / 128** (train), 포함 관계 확인 |
| 적용 범위 | **train 만**. test 를 줄이면 네 점이 다른 테스트셋을 본다 |
| 클래스 가중치 | **v1 상수 고정** (`class_weights()` 기본값) — 등록된 네 데이터셋의 weight 가 동일함을 확인 |
| 데이터셋 | `SafeSoundMelSiren25/50/75` + 기존 `SafeSoundMel`(=100%) |
| 평가 | `tools/siren_curve.py` |

⚠️ 무작위 표본추출이 아니라 **결정적 해시**를 쓰는 이유: 점마다 다른 원본이
뽑히면 곡선이 "원본 수" 가 아니라 "어떤 원본을 뽑았나" 와 섞인다.

## 2. 원본 확보 후보 — **조사만** (다운로드 전)

### 2.1 ★ 기존 소스는 **고갈됐다**

| 소스 | siren 총량 | 고유 원본 | 우리가 쓴 원본 | 미사용 |
|---|---:|---:|---:|---:|
| FSD50K (`Siren` 라벨) | 132클립 | 132 | 132 | **0** |
| UrbanSound8K | 929슬라이스 | 74 | 54 | 20 |
| ESC-50 | 40클립 | 28 | 19 | 9 |

⚠️ **US8K 20 + ESC-50 9 = 29 는 "미사용" 이 아니다.** 확인해 보니 **전부
이미 매니페스트에 FSD50K 출처로 들어 있다** — 같은 Freesound 원본을 세
데이터셋이 공유하기 때문이다(CLAUDE.md 12장: 2개 이상 데이터셋에 등장하는
원본 1,002개). 교차 데이터셋 중복 규칙이 이미 처리했다.

> **즉 세 소스에서 더 뽑을 것이 없다. 202 가 진짜 상한이다.**

### 2.2 FSD50K 에는 구체 사이렌 라벨이 **없다**

FSD50K 200라벨 어휘 실측:

| 라벨 | FSD50K |
|---|---|
| `Siren` | **있음** |
| `Civil_defense_siren` | 없음 |
| `Police_car_(siren)` | 없음 |
| `Ambulance_(siren)` | 없음 |
| `Fire_engine,_fire_truck_(siren)` | 없음 |
| `Emergency_vehicle` | 없음 |

`alarm` 클래스를 제외했던 것과 **똑같은 구조**다 (CLAUDE.md 4장).
FSD50K 로는 사이렌을 더 세분하거나 더 모을 수 없다.

### 2.3 후보 소스 두 갈래

#### (A) Freesound 직접 검색 — **권장**

- 우리 데이터의 **원 플랫폼**이다. CC 라이선스, 직접 다운로드 가능, 품질·길이
  분포가 기존 데이터와 같은 계열.
- 검색어: `siren`, `ambulance`, `police siren`, `fire truck`, `emergency`.
- **중복 제거 기준은 자명하다 — Freesound ID**. 기존 202개 fsid 와
  대조만 하면 되고, 5장 규칙 1(원본 ID 단위 전역 분할)이 그대로 적용된다.
- ⚠️ 라벨이 사용자 태그라 품질이 고르지 않다 → **청취 검증 필수**
  (`listening-verification.md` 절차 재사용).
- 예상 추가 고유 원본: **TBD** — API 검색 결과 수를 세야 안다. 검색 자체는
  네트워크 접근이므로 **승인 후** 진행한다.

#### (B) AudioSet — 구체 라벨은 여기에만 있다

- `Police_car_(siren)`·`Ambulance_(siren)`·`Fire_engine` 등 구체 라벨이
  **AudioSet 온톨로지에만** 있다.
- **중복 제거가 필요 없다**: AudioSet 은 **YouTube ID + 구간**이고 우리
  데이터는 **Freesound ID** 다. 두 플랫폼이라 원본이 겹치지 않는다
  (→ 확보하는 클립이 전부 새 원본이다).
- ⚠️ 위험 셋:
  1. **다운로드가 YouTube 의존**이다 (`yt-dlp`). 삭제·지역제한된 영상이
     상당수이고 재현성이 떨어진다 — 논문의 "재현 절차" 에 불리하다.
  2. **약라벨 10초 구간**이라 우리 1초 창 규약에 맞추려면 추가 선별이 필요하다.
  3. **라이선스가 CC 가 아니다** (YouTube 표준 라이선스 다수).
- 조사 절차 (다운로드 전, 메타데이터만):
  `balanced_train_segments.csv` / `unbalanced_train_segments.csv` /
  `eval_segments.csv` 를 받아 사이렌 계열 mid 별 클립 수를 센다.
  세 파일 합계 약 25MB 텍스트다. **이것도 네트워크 접근이므로 승인 후.**

### 2.4 권장

> **(A) Freesound 우선.** 라이선스·재현성·도메인 일치가 전부 낫고,
> 중복 제거가 fsid 하나로 끝난다. (B) 는 (A) 로 목표(예: train 원본 300)를
> 못 채울 때만 검토한다.

## 3. 증강 후보 — **설계만**

목표: 원본 수를 못 늘리는 동안 **원본당 다양성**을 늘린다.
현재 siren 증강은 shift ±200ms + 게인 ±12dB 다 (CLAUDE.md 5장 규칙 6).

### 3.1 후보와 입력 분포 영향

| 증강 | 범위 | int8 고정 스케일을 깨는가 | 비고 |
|---|---|---|---|
| **pitch shift** | ±2반음 | **아니오** — 스펙트럼만 옮긴다. 진폭 포락은 유지 | 사이렌 음높이 궤적이 클래스 단서라 **과하면 해롭다** |
| **time-stretch** | 0.9~1.1 | **아니오** | 사이렌 변조 주기(0.5~2초)가 바뀐다 — 역시 과하면 해롭다 |
| **배경 믹싱** | SNR 0~20dB | **주의** — 합성 후 피크가 풀스케일을 넘을 수 있다 | `_rand_gain` 과 같은 규칙: 넘는 만큼만 되돌린다 (인위적 클리핑 금지) |

**세 가지 공통 제약** (전부 기존 규칙의 재적용이다):

1. **피크 초과는 되돌린다, 자르지 않는다** — `_rand_gain` 과 같은 처리.
2. **`--floor-zero` 를 증강 **후**에 다시 검사**한다. 통과 못 하면 다시 뽑는다.
3. **배경 믹싱 풀은 같은 split** 에서만 (`FillerPool` 규약). test 배경을
   train 증강에 쓰면 누수다.

### 3.2 ⚠️ int8 샤드 위에서 하면 **두 번 깎인다**

pitch·stretch 는 **리샘플링**이라 보간이 들어간다. 우리 샤드는 int8 이므로
`int8 → 보간(float) → int8` 로 **반올림이 한 번 더** 걸린다. 보간 오차는
약 0.5 LSB 수준이라 치명적이진 않지만, 라운드 6 (b) 에서 같은 이유로
**2단계(int16 샤드)** 를 남겨 뒀다 (`g8-round6-design.md` b.2.5).

> **pitch·stretch 증강은 int16 샤드(v2)에서 하는 것이 맞다.**
> int8 위에서 먼저 해 보는 것은 **하한 측정**으로만 의미가 있다.

### 3.3 ★ 저장 여유 검산 — 한 조합이 **초과한다**

샤드는 창 16,384 + 양옆 여유 1,600씩 = **19,584 샘플**(1.224초)이다.
stretch `s`, pitch `p` 반음이면 필요한 원천 길이는 `16384 · s · 2^(p/12)`.

| stretch | pitch | 필요 샘플 | 19,584 대비 |
|---:|---:|---:|---|
| 0.9 | −2 | 13,137 | OK |
| 1.0 | 0 | 16,384 | OK |
| 1.0 | +2 | 18,390 | OK |
| 1.1 | 0 | 18,022 | OK |
| **1.1** | **+2** | **20,229** | **초과 (+645)** |

→ **stretch 1.1 과 pitch +2반음을 동시에 걸 수 없다.**

**결정 (2026-09-30)**: v1 은 **조합 상한 `stretch · 2^(pitch/12) ≤ 1.195`**
로 처리한다 (지금 여유 19.5%). 샤드 1.4초 확장은 **v2 의 int16 전환과 묶어서**
한 번에 재집계한다 — 재집계를 두 번 할 이유가 없다.

참고로 검토했던 세 가지:

1. 조합 상한을 두어 `s · 2^(p/12) ≤ 1.195` 로 제한 (지금 여유 19.5%)
2. 시간축 shift 여유를 줄여 증강에 쓴다 (shift ±200ms 와 상충)
3. **v2 에서 샤드 여유를 늘린다** — 1.224초 → 1.4초면 `s·2^(p/12) ≤ 1.37`
   까지 된다. int16 전환과 함께 하면 재집계가 한 번으로 끝난다

### 3.4 우선순위

| # | 항목 | 비용 | 선행 |
|---|---|---|---|
| 1 | **1절 학습 곡선** | 5.4시간 | 없음 — **먼저 이것부터** |
| 2 | 2.3(A) Freesound 검색 (조사) | 짧음 | **네트워크 접근 승인** |
| 3 | 3절 증강 (int8 위, 하한) | 25분 × 2 | 없음 |
| 4 | v2 int16 + 여유 1.4초 재집계 | TBD | 1·3 결과 |

**1번을 먼저 하는 이유**: 학습 곡선이 100% 에서 평평하면 2·3·4 가 **전부
무의미**하다. 가장 싼 판정이 먼저다.

## 부록 — **원본 수 기준** (문서마다 달라 혼선이 있었다)

`siren` 을 예로, 세는 **단계**가 다르면 값이 다르다. 전부 맞는 숫자다.

| 기호 | 세는 것 | siren | 쓰는 곳 |
|---|---|---:|---|
| A | 매니페스트 test **클립** | 75 | 데이터셋 구성 보고 |
| B | 그 클립들의 **고유 fsid** | 65 | 원본 단위 분할 (5장 규칙 1) |
| C | 테스트 **창** | 147 | 창 수 보고 |
| **D** | **그 창들의 고유 fsid** | **54** | **창 단위 평가의 부트스트랩 단위** |
| E | 빈틈없이 스캔된 클립의 고유 fsid | 64 | **이벤트 단위 평가** |

- **A → B**: 같은 Freesound 원본에서 여러 클립이 나온다.
- **B → D**: 에너지 필터(`--floor-zero`)에서 창이 하나도 안 남은 원본이 빠진다.
- **B → E**: 1초 미만 클립은 프레임이 만들어지지 않아 빠진다 (74클립/64원본).

**규약**
- 창 단위 지표(`eval_confusion`·`eval_threshold`·`siren_curve`)의 신뢰구간은
  **D** 로 낸다.
- 이벤트 단위 지표(`event_eval`)의 recall 분모는 **E** 다.
- 데이터셋 규모를 말할 때는 **B**(고유 원본)를 쓰고, A·C 는 괄호로 병기한다.

전 클래스 E 기준 (빈틈없이 스캔된 test 원본):

| 클래스 | 클립 | 고유 원본 |
|---|---:|---:|
| `siren` | 74 | **64** |
| `glass` | 132 | 132 |
| `scream` | 174 | 174 |
| `dog_bark` | 399 | 310 |
| `background` | 1,541 | 1,541 |
