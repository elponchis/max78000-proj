# 외부 검증 세트 평가 (AudioSet strong eval, 재학습 없음)

작성 2026-10-05. 세트 설명·한계는 `external-set.md` (보조 세션). 이 문서는 **PC
평가**만 다룬다 — 온디바이스 값이 아니다. 표는 `tools/ext_report.py` 가
`data/external_eval/external_eval.json` 에서 그대로 뽑은 것이다.

## 0. 요약

1. **모든 구성이 외부 세트에서 크게 떨어진다.** 시험셋 @300/h 문턱값을 그대로
   썼을 때 macro-F1 이 ④ 0.533 → **0.269**, ①′ 0.669 → **0.378** (v1 정의).
   낙폭은 구성에 따라 0.23~0.31 이고, 클래스별 recall 은 **6~36%** 다.
2. **문턱값은 옮겨졌다.** 같은 문턱값에서 외부 배경의 오경보가 164~345회/h 로
   목표(300회/h) 근처다 (외부 배경 1창 = 54.5회/h 라 3~6창 차이). 떨어진 것은
   오경보 쪽이 아니라 **이벤트 재현율**이다.
3. **구성 순위는 유지됐다.** v1 정의에서 9개 구성의 순위가 시험셋과 **완전히
   같다** (Spearman 1.000). 실사용 정의에서는 0.967 — 인접한 두 쌍(간격 400 ↔
   다, 간격 500 ↔ 간격 500+멜 32)이 자리를 바꿨고 그 차이는 CI 폭의 1/10
   수준이다. **로그 멜 계열 > 원본 파형 계열**은 두 정의 모두에서 유지된다
   (①′ CI 하한 0.336 > ④ CI 상한 0.302. ⚠️ 대응 검정이 아니라 CI 비교다).
4. **사전 등록대로 외부 세트로 구성을 고르지 않는다.** 로그 멜 변형들 사이의
   차이는 전부 서로의 CI 안이다 — 이 세트로는 가를 수 없다.

⚠️ **낙폭의 원인은 분리하지 않았다.** 후보: (가) 출처 차이(유튜브 영상 대
Freesound), (나) 손실 압축, (다) 라벨 — 외부 세트는 **청취 검증을 하지 않았다**
(v1 은 했다), (라) 다른 소리가 섞인 창이 많다(음악·말소리 동반). 평가 경로의
오류 가능성은 1절의 세 점검으로 줄였다. "모델이 실환경에서 이만큼 나쁘다" 로도
"세트가 잘못됐다" 로도 쓰지 말 것 — **지금은 둘을 가를 근거가 없다.**

## 1. 방법

- 대상: 9개 구성 × 전 시드 = 체크포인트 29개. 재학습 없음.
- **평가 경로**: 외부 창 758개를 우리 샤드 형식으로 감싸
  (`data/external_eval/`, git 제외) 기존 `eval_confusion.collect_logits` 를
  **그대로** 불렀다 (`tools/eval_external.py`). 모델 적재(`load_model` →
  `ai8x.update_model`)·특징 계산·텐서 변환이 시험셋 평가와 같은 코드다.
- **점검 셋** (전부 통과):
  1. 샤드로 감싼 창 758개가 `windows_int8.npy` 와 비트 단위로 같고 순서가
     `meta.csv` 와 같다 (`eval_external.py --self-check`, 불일치 0).
  2. 평가 로더 회귀 테스트를 **이번에 쓴 구성 전부**로 넓혔다
     (`kat_evalpath.py --external`): 우리 로더와 `train.py --evaluate` 의
     argmax macro-F1 이 9개 구성 모두 소수 5자리까지 같다. 기존 사례는
     ④·D-1·① 뿐이라 `dimensions`·`pool6`·`width_mult` 가 다른 구성을 덮지 못했다.
  3. 시험셋을 같은 도구로 다시 채점한 @300/h 값이 기존 보고와 일치한다
     (예: ④ 0.5211 / 0.5079 / 0.5627 / 0.5191 / 0.5536).
- **문턱값**: 체크포인트마다 **기존 시험셋의 @300/h 마진 문턱값**을 고정해
  외부 세트에 적용했다. 외부 세트로 다시 맞추지 않았다. 외부 배경 기준
  @300/h 지점(264창 중 5창 허용)은 **병기만** 한다.
- **정의** (external-set.md 6절): 양성은 v1 = `v1_class == 그룹`, 실사용 =
  `real_primary == 1`. 음성은 두 정의 모두 `background` 그룹 264창. 그 정의에서
  양성이 아닌 클래스 그룹 구간은 채점에서 뺐다. (scream 그룹 1개는 v1 라벨이
  dog_bark 라 v1 채점에서 빠진다.)
- **지표**: 5클래스 macro-F1 (시험셋과 같은 함수), 클래스별 recall. 값은
  **시드 평균**. 신뢰구간은 **구간(= 영상, 758개가 전부 다른 영상) 단위**
  부트스트랩 2000회의 95% 백분위 — 재표본마다 시드 평균을 다시 계산했다.
  ⚠️ 시드 간 변동은 CI 에 들어 있지 않다 (구간 표본 변동만).
- ⚠️ **macro-F1 의 절대값은 시험셋과 직접 비교되지 않는다.** 배경 비율이
  다르다 (시험셋 배경 3,838 / 이벤트 1,369, 외부 264 / 약 330). 낙폭은
  recall 표를 함께 볼 것.

## 3. 읽는 법과 관찰

**정의 차이의 영향은 작다.** v1 과 실사용 정의의 macro-F1 차이는 구성마다
0.000~0.020 이고 낙폭(0.23~0.31)에 비해 작다. 낙폭은 정의 문제가 아니다.

**외부 배경 기준 @300/h 지점.** 문턱값을 외부 배경에 다시 맞추면 로그 멜
계열이 0.37~0.43 으로 0.00~0.06 오르지만 여전히 시험셋보다 0.24 이상 낮다.
즉 **문턱값 이동으로는 낙폭이 설명되지 않는다.** 이 지점은 264창 중 5창으로
정해져 분해능이 거칠다 — 구성 비교에 쓰지 않는다.

**argmax 지점(참고).** 문턱값 없이 보면 recall 낙폭이 더 작다: ④ siren
70.7 → 40.2%, glass 64.1 → 35.4%, scream 69.9 → 33.2%, dog_bark 81.3 → 67.4%
(실사용 정의, 시드 평균). 배경을 배경으로 맞히는 비율은 거의 같다 (④ 70.9 →
68.3%, ①′ 92.1 → 93.7%). **이벤트 창의 점수가 통째로 내려가** 고정 오경보
문턱값 위로 올라오는 창이 줄어든 모양이다.

**레벨은 원인이 아니다.** 외부 이벤트 창이 시험셋보다 조용하지 않다 (RMS 중앙
siren −15.7 대 −17.2 dBFS, glass −19.0 대 −24.5, scream −15.2 대 −16.8,
dog_bark −21.9 대 −23.9). 오히려 int8 0 비율이 훨씬 낮다 (glass 0.053 대
0.423) — **외부 창은 이벤트 주변이 다른 소리로 차 있다.**

**siren 하위 종류.** 하위 종류만 있고 `Siren` 라벨이 없는 37개(v1 에서 음성)의
recall 이 `Siren` 포함 84개와 **비슷하다** (로그 멜 계열 12.6~18.0% 대
11.1~17.1%). 원본 파형 계열은 하위 종류만일 때 더 낮다 (2.7~5.4% 대
6.3~9.0%). 종류별 n 이 4~12 라 종류 간 비교는 하지 않는다. Civil defense
siren 은 전 구성에서 낮다 (0~8%, n=12).

**scream 하위 라벨.**
- `Screaming` 만 (22개): 로그 멜 계열 12~24%, 원본 파형 7~11%.
- `Screaming` + 군중·음악·웃음 (27개, v1 에서 음성): 7~14% — 낮지만 0 이 아니다.
- `Shout` 만 (**92개** = scream 그룹 55 + def_gap 37): scream 으로 **6.5~14.5%**.
  두 묶음은 **같은 모집단의 무작위 추출**로 확인됐으므로 (수집 세션,
  2026-10-05) 합쳐서 읽는다. 위 표의 두 열(55 / 37)은 원자료로 남기되 **따로
  해석하지 않는다.**

  (55개와 37개의 시드 평균 발화율을 창 수로 가중 평균한 값이다. 새 추론 없음.)

**def_gap 발화율** (v1 에서는 양성, 실사용 정의에서는 배경).
- `Dog` 만 (45개): dog_bark 로 6~13%. 같은 구성의 `Bark` recall(17~36%)의
  약 1/3 이다 — 모델은 `Bark` 없는 개 소리에 덜 발화한다.
- `Yell`·`Shout` 만: def_gap 의 37개는 scream 그룹의 55개와 같은 모집단이다 —
  합친 92개의 발화율(6.5~14.5%)은 위 "scream 하위 라벨" 표를 볼 것.
- `v1_floor_excluded` 는 1창(def_gap dog_bark)뿐이라 제외해도 0.3pp 안에서 같다.
- 실사용 정의에서 이 발화를 오경보로 세면 배경 발화율(1.1~2.4%)보다 높다
  (`Dog` 만 6~13%, `Shout` 만 6.5~14.5%). 표의 실사용 macro-F1 에는 def_gap 이
  들어 있지 않다.

**bg_near_silent (8창).** 전 구성·전 시드에서 **한 번도 발화하지 않았다.**
제외하면 macro-F1 이 0.0014~0.0015 내려간다 (맞힌 배경이 빠져서). 조용한 방
오탐 우려와 반대 방향이다. n=8 이다.

**webm_origin (41~42창).** 제외하면 macro-F1 이 −0.001~+0.008 움직인다. 순위에
영향이 없다. webm 출신 배경 21창의 발화율은 0~3.2% 로 전체(1.1~2.4%)와 같은
범위다.

## 4. 순위 유지 (사전 등록 항목)

> 사전 등록: 시험셋 순위와 외부 세트 순위의 **일치 여부만** 보고한다. 외부
> 세트로 구성을 고르지 않는다.

- v1 정의: **완전 일치** (9개 구성).
- 실사용 정의: 9개 중 5개가 같은 자리, 인접 두 쌍 교환. Spearman 0.967.
- 유지되는 것: **①′ 가 1위, 원본 파형 계열(④, ④ 0.5×)이 8·9위, 2차 후보
  가·나가 6·7위.**
- 유지되지 않는다고 볼 근거가 없는 것: 로그 멜 변형 사이의 순서. 외부 세트의
  CI 폭(약 ±0.04)이 변형 간 차이(0.00~0.06)와 같은 크기라 **이 세트는 변형
  사이를 가를 해상도가 없다.**

## 5. 한계

1. 외부 세트 라벨은 청취 검증 전이다 (external-set.md 9절 6항). recall 의
   분모에 라벨 오류가 섞여 있을 수 있고 그 크기를 모른다.
2. 낙폭의 원인(출처·코덱·라벨·혼합음)을 분리하지 않았다.
3. 창이 이벤트 중심에 놓여 있고 이벤트가 창보다 짧다 (dog_bark 중앙 0.6초).
   시험셋은 RMS 최대 지점 기준이다 — 창 배치 규칙이 다르다.
4. CI 는 구간 표본 변동만 담는다. 시드 변동은 따로다 (구성당 3~5시드).
5. PC 평가다. 온디바이스 값이 아니다.
6. 클래스당 74~87창이라 recall CI 폭이 ±7~9pp 다.
