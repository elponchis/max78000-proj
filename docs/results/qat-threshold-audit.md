# QAT 활성화 문턱 감사 — 전 구성 분류기 층별 포화율 (2026-10-25)

`tools/qat_threshold_audit.py`. 배경·질문은 `npu-readback-design.md` 7.1 (다). 시험 창 256개(testL-S3 균등 간격), 체크포인트 qat_best, 보드·학습 없음 (사용자 지시 2026-10-24: 기존 체크포인트로만 계산).

**포화** = 층 출력 |·| ≥ 127/128 (int8 잘림) 비율, **0** = 출력이 정확히 0 인 비율. **thr** = 저장된 `activation_threshold` (출력에 2^(−thr); 음수면 출력을 2^|thr| 배 키운다).
wide 층(int32 출력)은 포화 개념이 없고(값은 참고), 마지막 fc 는 로짓이라 포화가 정상이다 — 둘은 판정에서 뺀다.

**구조적 판단.** `apply_scales` 의 '이전 층 보상' 이 틀리려면 두 ai8x conv 사이에 **스케일을 지우는 비-ai8x 연산**이 있어야 한다. CPU log-mel 계열은 p1 이 모델 밖(CPU)이라 연결이 없고, ④·(a) 는 층 사이가 ReLU·풀링·구간선형(모두 ai8x)이라 보상이 맞다. 따라서 결함 (다) 는 **②′ 계열에만** 생길 수 있다 — 아래 표가 그것을 실측으로 확인한다.
