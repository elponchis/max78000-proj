# 데이터셋 v4 + PANNs 증류 — 설계안 (2026-10-09, 실행 전)

> ⚠️ 원래 요구사항("지난 프롬프트의 2번") 원문은 이 세션에 도착하지 않았다. 아래는 `label-audit.md` 1~7절,
> `g8-c-distillation.md`(접은 ① 교사 증류)의 교훈, 2026-10-09 지시에서 구성했다. 원문과 다른 부분은 고쳐 달라.
> **청취 결과(`eval-baseline-change.md`)가 나오기 전까지 실행하지 않는다.** 학습은 돌리지 않았다.

## 1. 무엇을 하려는가

두 가지를 **단계로 나눠** 넣는다 — 한꺼번에 넣으면 어느 것이 효과였는지 갈리지 않는다.

| 단계 | 내용 | 가르는 것 |
|---|---|---|
| **v4 (정리)** | v3.1 에서 glass·scream 의 PANNs 점수 < 0.02 창 제외, 아기 울음 구간 → 배경 | 라벨 정리만의 효과 |
| **v4+D (증류)** | v4 위에 PANNs 를 교사로 한 지식 증류 | 교사 지식의 효과 |

근거: PANNs 는 외부 세트에서 F1 0.72 / mAP 0.88, 우리 간격 400 은 0.49 / 0.81 (`label-audit.md` 1절). siren·dog_bark
는 데이터가 정상인데 우리 모델이 못 듣는다 (c). 즉 **들을 수 있는 소리를 못 듣는 것**이고, 그 소리를 듣는 교사가 있다.

## 2. v4 학습 데이터 (정리 규칙, `label-audit.md` 7.2)

v3.1 (`data/processed/safesound_v31`) 에서 출발한다. 바꾸는 것은 셋뿐이다.

1. **glass 창 제외**: PANNs `Shatter`·`Breaking`·`Smash, crash` 묶음 최대 확률 < 0.02 인 창 — FSD50K 계열 240 +
   AudioSet 152 = **392창 제외** (970 → 578).
2. **scream 창 제외**: PANNs `Screaming` < 0.02 — FSD50K 계열 56 + AudioSet(v3.1 규칙 후) 110 = **166창 제외** (725 → 559).
3. **아기 울음 → 배경**: AudioSet `DaMvU_MSjoo_20000`, `e4wSf2mkCLw_230000` 의 scream 창 4개 → background 로 이동
   (2번 제외분과 겹치면 제외가 우선). 외부 세트는 평가 쪽에서 처리한다.

제외한 창은 버린다 (배경으로 옮기지 않는다 — 무슨 소리인지 모른다). 시험셋은 거르지 않는다.
siren·dog_bark·background 는 손대지 않는다 (감사에서 규칙에 안 걸렸다).

| 클래스 | v1 | v3.1 | **v4 (예정)** | 가중치 v3.1 → v4 |
|---|---:|---:|---:|---|
| siren | 528 | 1,195 | 1,195 | 2.883 → 2.789 |
| glass | 477 | 970 | **578** | 3.551 → **5.766** |
| scream | 491 | 725 | **559** (−아기 울음 창 ≤ 4) | 4.751 → **5.962** |
| dog_bark | 1,934 | 2,366 | 2,366 | 1.456 → 1.409 |
| background | 11,967 | 11,967 | 11,967 (+≤ 4) | 0.288 → 0.279 |
| 합계 | 15,397 | 17,223 | **16,665** | |

⚠️ glass·scream 가중치가 5.8~6.0 으로 커진다 (v1 glass 의 2배 이상). 창이 줄어 가중치가 오르는 것은 공식(`N/(K·n_c)`)
의 결과이고 바꾸지 않지만, **오경보가 늘 수 있다** — 조건 D·E 가 그것을 잡는다.
PANNs 점수는 `data/label_audit/panns_*.npz` (이미 계산됨, 창 단위 키 = (clip_id, start_sample)). 빌더는
`build_v3_windows.py` 에 `--exclude-list` 를 더해 v3.1 과 같은 경로로 만들고, 태그 `dataset-v4`. KAT 는 `kat_v3.py --edition v4`
(제외분을 뺀 v1 행 비트 일치, 창 수 = MANIFEST = `V4_TRAIN_COUNTS`, 분리, 베드, test 링크, 혼합 풀).

**증강은 v2.1 그대로** (게인 ±12 dB, shift, 배경 혼합). 증강 규칙은 바꾸지 않는다.

## 3. 증류 설계 (v4+D)

### 3.1 교사

**PANNs CNN14 16 kHz** (`Cnn14_16k_mAP=0.438.pth`) — 같은 체크포인트. 교사 출력을 5클래스로 만드는 방법 두 가지 중
**(가) 선형 프로브**를 권고한다.

| 방식 | 5클래스 점수 | 장점 | 단점 |
|---|---|---|---|
| (가) **선형 프로브** (`ceiling_check.py --mode probe`, 2048 임베딩 고정 + 선형층, v4 학습셋 라벨로 학습) | 로짓 5개, 소프트맥스 | 우리 정의(군중 제외, 하드 네거티브)를 배운 교사. 로짓 스케일이 자연스럽다 | 교사도 우리 라벨을 본다 — 라벨 오류가 있으면 같이 배운다 (v4 정리가 그래서 먼저다) |
| (나) 제로샷 (`zeroshot` 점수: 묶음 최대, 배경 = 1 − max) | 확률 비슷한 값 5개 | 라벨 독립 | 분포가 아니라 각 클래스 sigmoid 최대라 합이 1이 아니고, Yell·Shout·Dog 가 우리 정의와 어긋난다 (`label-audit.md` 1절 real31 오경보) |

선형 프로브는 `ceiling_check.py --mode probe` 에 자리만 있고 **구현 전**이다 (`ceiling-check.md` 2.5). 3단계에서 구현한다 —
임베딩 2048 → 선형 5, v4 학습셋 라벨·클래스 가중치로 학습, 시험셋 @300/h 로 교사 자체 성능을 먼저 적는다.
교사 로짓은 **v4 학습 창(무증강)에 대해 한 번 계산해 캐시**한다 (`data/processed/safesound_v4/teacher/<cls>/shard_NNNN.npy`,
창당 float32 5개). PANNs 는 22 ms/창이라 17k 창에 6분이다.

### 3.2 학생과 손실

- 학생: **간격 400** 과 **④** (사전 등록 대상과 같다), 3시드.
- 손실 = (1 − α)·CE(하드 라벨, 클래스 가중치) + α·T²·KL(softmax(교사/T) ‖ softmax(학생/T)).
  α = 0.5, T = 2 로 시작한다 (g8-c 의 0.7 / 4 는 교사 로짓 스케일 문제와 얽혀 있었다). ai8x-training 의
  `--kd-teacher` 경로는 교사 모델을 온라인으로 돌리므로 쓰지 않고, **캐시된 로짓을 Dataset 이 같이 내는 방식**으로
  (`SafeSoundV4D` 로더가 `(x, (y, t_logits))` 를 내고 손실 래퍼가 받는다). `wrap_teacher.py`·`calib_teacher.py` 의
  검사(유효 클래스 수, 스케일)를 그대로 쓴다.
- ⚠️ **증강 불일치**: 교사 로짓은 무증강 창에서 계산한 것인데 학생은 증강(게인·shift·배경 혼합)된 창을 본다. 게인·shift
  는 교사 판단을 거의 바꾸지 않지만 **배경 혼합(mix_prob)은 바꿀 수 있다**. 1차는 그대로 가고, 혼합된 창에서는
  α 를 0 으로 (하드 라벨만) 두는 변형을 2차 후보로 적어 둔다. 온라인 교사(에폭마다 PANNs)는 17k × 22 ms ≈ 6 분/에폭
  × 150 = 15 시간이라 하지 않는다.
- QAT 정책·스케줄·옵티마이저·에폭(150)은 그대로.

### 3.3 g8-c 에서 배운 것 (적용)

1. 교사 로짓 스케일을 **전역 상수 하나**로 보정하고 유효 클래스 수를 적는다 (`calib_teacher.py`). 1.0 = one-hot 이면
   증류가 아니다.
2. **입력 표현이 다른 교사→학생은 해로울 수 있다** (① 멜 교사 → ④ raw 학생 −0.074). PANNs 도 멜 입력이다. 그래서
   간격 400(멜 학생)에서 먼저 보고, ④ 는 같이 돌리되 해로우면 그대로 보고한다 — ④ 에서 해로운 것은 예측된 결과다.
3. 증류 체크포인트는 `kat_teacher.py` 가 보는 교사 일관성 검사를 통과해야 한다.

## 4. 평가와 성공 기준 (사전 등록 — 청취 확정 라벨이 나온 뒤 수치를 고정한다)

비교는 **v4 − v3.1**, **v4+D − v4**, 같은 시드 1~3, Welch 95% CI. 라벨은 `eval-baseline-change.md` 의 청취 확정 라벨
(`testL`, `real31L` 주 / `v1eqL` 보조). **기준값(v3.1 의 새 라벨 수치)은 재채점이 끝난 뒤 적고, 그 전에 조건을 고정한다.**

| # | 조건 | 통과 기준 (v3 A~F 와 같은 형식) |
|---|---|---|
| A | 외부 macro-F1 (real31L, 시험셋 @300/h 문턱값) | CI 하한 > 0 |
| B | 외부 mAP (real31L) | CI 하한 > 0 |
| C | 기존 시험셋 macro-F1 @300/h (testL) | 점 추정 ≥ −0.02 |
| D | 외부 배경(264창) 발화 창 수 | 시드 평균 ≤ 기준 + 2창 |
| E | 배경+배경 혼합 창 발화율 | ≤ 2.6% |
| F | 기존 시험셋 scream recall (testL) | 점 추정 ≥ −5 pp |
| **G** | 기존 시험셋 glass recall (testL) | 점 추정 ≥ −5 pp (glass 창을 40% 뺐으므로 glass 가 무너지지 않는지) |

"해결" 기준은 v3 6.3 그대로(격차 절반, scream·siren +10 pp, glass·dog ≥ −3 pp, mAP +0.04). 단계 규칙: **v4 가 A~G 를
둘 다(④·간격 400) 통과해야 v4+D 로 간다.** v4+D 는 ④ 에서 해로워도 간격 400 이 통과하면 보고한다 (3.3-2).
어느 단계든 통과·미통과와 무관하게 **보고하고 멈춘다** — 다음 단계는 사용자가 연다.

## 5. 순서와 예상 시간 (실행은 청취 결과 뒤)

| 단계 | 내용 | 시간 |
|---|---|---|
| 0 | 청취 결과 → 라벨 확정 → 전 판 재채점 (`eval-baseline-change.md` 4절) | 1시간 (채점만) |
| 1 | v4 빌드 + KAT + 사전 등록 커밋 (창 수·가중치 확정) | 20분 |
| 2 | v4 1단계: ④ ×3 → 간격 400 ×3 (`run_chain28.sh`) | ④ 35~40분, 간격 400 75분 → 약 5.5시간 |
| 3 | 교사 로짓 캐시 (프로브 학습 포함) | 20분 |
| 4 | v4+D: ④ ×3 → 간격 400 ×3 (`run_chain29.sh`) | 약 5.5시간 |
| 5 | 채점·보고 (`eval_v3.py --v4 / --v4d`) | 30분 |

시작 전 MemAvailable ≥ 4,000 MB, 다운로드 프로세스 없음, 끝나면 `audit_runs.py`. 지연·에너지·비트 일치는 가중치만 바뀌므로
다시 재지 않고, 채택 후 시드 1 체크포인트로 비트 일치만 확인한다.

## 6. 바꾸지 않는 것 / 한계

- 외부 세트를 보고 정의·규칙·문턱값을 고치지 않는다. 청취 확정은 모델 출력을 보지 않고 한다.
- PANNs 0.02 제외는 **학습용**에만 쓴다. 시험 정답은 청취다. 둘을 섞으면 "PANNs 식 정답에 PANNs 교사로 맞춘" 순환이 된다 —
  시험 정답에 PANNs 가 전혀 안 들어가는 것이 이 설계의 전제다. (단 기존 시험셋 siren·scream·dog_bark 창은 v1 선별 때
  PANNs 묶음 필터를 통과한 창이라는 역사적 편향이 남는다 — 한계에 적는다.)
- 증류 교사의 소리 정의가 AudioSet 이다. 우리 정의(군중 제외 등)와 다른 곳은 (가) 프로브가 흡수하지만 완전하지 않다.
- 청취 판정자 1인. 대조 창의 O 비율로 청취 기준을 점검한다.
