# 데이터셋 v3.1 — v3 에서 비명 정의만 고침 (사전 등록 2026-10-08 → 1단계 결과 7절)

> **1단계 판정 (2026-10-08 21:12 종료): 미통과 → 2단계 없음.** ④ 는 조건 A(외부 F1 CI 하한 > 0) 미충족,
> 간격 400 은 조건 F(시험셋 scream recall ≥ −5 pp) 미충족 (−6.1 pp [−7.6, −4.5]). 둘 다 "해결" 아님. 7절.

> **v3 1단계(`dataset-v3-design.md` 12절)의 판정과 중단은 승인됐다. v3 2단계는 돌리지 않는다.** v3.1 은
> 변경 하나(1절)만 넣은 1단계 재실행이다. 설계·규칙·KAT·채점기는 v3 문서의 것을 그대로 쓰고, 이 문서는
> 차이와 사전 등록만 적는다.

## 1. 변경은 하나

**AudioSet 구간 중 Yell·Shout 만 있고 `Screaming` 이 없는 구간을 학습에서 제외한다** — 양성으로도 배경으로도
쓰지 않는다. 군중 동반 비명(Screaming·Yell·Shout + v1 군중 목록)은 v1 규칙 그대로 배경 하드 네거티브
`scream_crowd` 다. 나머지(사이렌 = `Siren` + 하위 4종, 창 상한 2, 겹침 규칙, 하한, 채움, webm 포함, 증강
v2.1 그대로, 시드 1~3)는 v3 과 같다. 구현: `build_v3_windows.py --scream-screaming-only --out
data/processed/safesound_v31` (MANIFEST tag `dataset-v3.1`), 로더 `SafeSoundV31` / `SafeSoundMel*V31`
(루트 `SafeSoundV31`), 가중치 `V31_TRAIN_COUNTS`.

## 2. 근거 — 학습셋과 기존 시험셋에서 나온 것이지 외부 세트 결과가 아니다

v3 1단계(12절)에서:

1. **AudioSet 비명 창의 학습 재현율**이 가장 낮았다 — ④ **7.9%**, 간격 400 69.3% (v1 계열 비명은 37.1 /
   90.4%). 모델이 AudioSet 비명 창을 "scream" 으로 배우지 못했다 (12.4).
2. **기존 시험셋(FSD50K) 비명 재현율이 내려갔다** — ④ 32.6 → 21.6 (**−11.0 [−21.0, −0.9] pp**), 간격 400
   58.2 → 49.2 (−9.0 [−22.0, +3.9]) (12.3). v3 의 비용은 scream 에 몰려 있다.
3. **AudioSet 비명 양성의 56% 가 Yell·Shout** 였다 (v3 1.2: 402구간 중 Yell·Shout 만 246, Screaming 156).
   FSD50K 의 v1 scream 은 `Screaming`/`Yell`/`Shout` 라벨을 같이 썼지만 PANNs 태거(`scream` 0.025)와
   청취로 걸렀고, AudioSet strong 은 청취 없이 라벨 그대로다. Yell·Shout 1초 창은 비명보다 발화에 가까운
   것이 많다.

이 세 가지는 **학습 창 재현율과 기존 시험셋**에서 본 것이다. 외부 세트의 scream 결과(불변)는 보긴 했지만
정의 변경의 근거로 쓰지 않았고, 외부 세트로 문턱값·규칙을 맞추지 않는다 (v3 6.4 그대로).

## 4. 평가 — 외부 세트 두 정의, 주 기준은 **실사용 정의**

| 정의 | 양성 | 음성 | 쓰임 |
|---|---|---|---|
| **실사용 (`real31`, 주 기준)** | `real_primary=1` 이고 그 클래스: siren 87 · glass 74 · scream 74 (`Screaming`) · dog_bark 87 | **402** = 배경 264 + scream 그룹의 Yell·Shout 만 56 + def_gap 82 (Yell·Shout 만 37, `Dog` 만 45) | 조건 A·B, "해결" |

- 실사용 정의를 주 기준으로 쓰는 이유: v3.1 의 변경이 "Yell·Shout 는 비명이 아니다" 이므로, 평가도 Shout 만
  있는 구간을 **음성**으로 보는 정의여야 일관된다 (사용자 권고). def_gap 의 `Dog` 만 구간도 실사용 정의에서
  배경이므로 같은 규칙으로 음성에 넣었다 — 정의를 반만 적용하지 않기 위해서다.
- ⚠️ 실사용 정의의 scream 양성(74)은 **군중 동반 비명을 포함**한다. 학습은 v1 규칙대로 그것을 배경으로
  보낸다. 이 불일치는 v3 과 같고, 결과 해석에 적는다.
- 조건 D(외부 배경 발화 창 수)와 "맞춤" 지점은 v3 과 같이 **배경 264창** 기준이다 (음성 402 가 아니다 —
  v2.1·v3 수치와 이어지게).
- 기존 시험셋·배경+배경·혼합 시험셋·출처별 학습 재현율은 v3 과 같은 채점 (`eval_v3.py --v31`,
  `--v31 --train-by-source`).

v3.1 − v2.1, 시드 1~3, Welch 95% CI. A·B 는 실사용 정의(real31)로 판정하고 v1eq 값은 병기한다.

같이 계산한다 (캐시 로짓).

**대상·순서**: ④ ×3 → 간격 400 ×3 (`scripts/run_chain27.sh`). **둘 다** A~F 를 충족해도 **2단계로 이어서

`audit_runs.py`.

  scream recall 하락은 절반만 되돌렸다** (간격 400 −9.0 → −6.1 pp, ④ −11.0 → −4.3 pp). F 의 기준 −5 pp 를
  간격 400 이 넘지 못했다.
- 외부 세트에서 v3.1 은 v3 과 같은 그림이다: 간격 400 의 glass·siren 이 크게 오르고 scream 은 오르지 않는다.
  외부 scream 양성(real31 74창 — `Screaming` 보유, 군중 동반 포함)의 recall 은 ④ 7.2 / 간격 400 18.5% 로
  v2.1 과 같거나 낮다. Yell·Shout 구간을 뺀 것이 외부 비명 재현율로 이어지지 않았다.
- 시험셋 scream 하락이 남는 이유는 이 실험으로 가리지 못한다. 후보는 (가) 남은 AudioSet scream 156구간
  (234창) 자체의 영향, (나) 다른 AudioSet 클래스·배경 4,000여 창이 scream 결정 경계를 미는 효과,
  (다) 가중치 변화 (scream 3.37 → 4.75) — 전부 **확인하지 않은 추정**이다.
- 사전 등록대로 **본 표는 v2.1 그대로**이고 v3·v3.1 은 부록이다. 2단계(후보 가·다·①′)는 돌리지 않았다.
  간격 400 하나로, 또는 F 를 빼고 v3.1 을 채택하려면 사전 등록을 사후에 바꾸는 것이므로 하지 않는다 —
  하려면 사용자가 별도로 결정하고 일탈로 적는다.

### 7.6 한계 (v3 12.6 에 더해)

- F 는 점 추정 기준인데 간격 400 은 CI 로도 걸렸고, ④ 는 점 추정 −4.3 으로 통과했으나 CI 가 [−14.9, +6.3]
  으로 넓다 — ④ 의 F 통과는 "하락이 확인되지 않음" 이지 "하락이 없음" 이 아니다.
