# 에너지 추정 — 실측 지연 × 공개 전력 (2026-10-02 방침 확정)

> ## ⚠️ 이 문서의 에너지 값은 전부 **추정(실측 지연 × 공개 전력)** 이다.
> **직접 에너지 계측은 하지 않았다.** 문서·논문 초안 어디에도 "측정" 으로
> 쓰지 않는다. 논문 한계 절에 "직접 에너지 계측 미수행, 향후 과제" 를 적는다.

## 1. 방법

구성별 판단 1회 에너지를 구간 합으로 추정한다.

```
E = Σ ( 구간별 실측 시간 × 그 구간 모드의 전력 )
```

| 구간 | 모드 | 시간 출처 |
|---|---|---|
| 입력 적재 | CPU 활성 (CNN 켜짐·대기) | 보드 실측 (SysTick, POR 직후, 1000회) |
| 추론 | NPU 동작 + CPU 바쁜 대기 | 〃 |
| 전처리 (구성 ① 만) | CPU 활성 | 〃 (C 구현 후) |
| 출력 (unload + softmax) | CPU 활성 | 〃 |
| M4 소프트웨어 추론 (대조군) | CPU 활성, NPU 꺼짐 | 〃 (구현 후) |

전력은 **출처 2종을 나란히** 쓰고 두 값의 **범위**를 보고한다.
- **(가) 데이터시트** — MAX78000 Electrical Characteristics (문서명·페이지·조건 인용)
- **(나) 동일 칩 실측 선행연구** — 보고된 에너지·시간에서 역산한 평균 전력

## 2. 가정 표 (논문에 그대로 싣는다)

| 항목 | 값 | 근거 |
|---|---|---|
| 코어 클럭 | 100 MHz (IPO) | 펌웨어 시리얼 `SystemCoreClock 100000000 Hz` |
| CNN 클럭 | 50 MHz (PCLK ÷ 1) | `cnn_enable(PCLK, DIV1)` |
| 공급 전압 | 출처별로 다르다 — 아래 3절 | (가) 는 레일별 전압, (나) 는 각 논문의 공급 조건 |
| 추론 대기 | **바쁜 대기** (슬립 아님) | `while (cnn_time == 0) {}` |
| 슬립·유휴 구간 | **포함하지 않는다** | 판단 1회의 능동 구간만. hop 250 ms 의 나머지는 계산에 없다 |
| 가중치 적재 | 포함하지 않는다 | 부팅 시 1회 (상시 동작에서 반복되지 않는다) |
| 마이크·코덱·PMIC·LED | 포함하지 않는다 | 칩 전력만. 보드 수준 전력이 아니다 |

### 표 설명 (논문에 함께 싣는다)

**"①/④ 비" 는 같은 전력 상수 쌍을 두 구성에 똑같이 적용해 계산한 에너지
비다.** 전력 출처를 바꾸면 절대값은 약 2배(상한 행까지 넣으면 3.6배) 범위로
달라지지만, 비는 **2.2~2.75** 로 훨씬 좁게 움직인다.

⚠️ **정확한 진술**: 비는 전력의 **절대 크기에는 의존하지 않는다** — 두 상수에
같은 배수를 곱해도 비가 그대로다. 의존하는 것은 **실측 시간**과
**두 모드의 전력 비(P_추론 / P_적재·출력) 하나**다. "실측 시간에만 의존한다"
가 문자 그대로 성립하는 것은 전 구간 전력을 같게 본 마지막 행(2.04)뿐이고,
NPU 전력이 CPU 전력보다 클수록 추론 시간이 긴 ①이 불리해져 비가 커진다
(2.04 → 2.75). 논문에는 **비의 범위와 시간 비를 함께** 적는다.

### 교차 확인 — 연산량 기준 (시간과 무관한 경로)

데이터시트 E_J_CNN = 4.02 pJ/MAC (max power network 조건) × 합성 로그의 MAC 수:
④ 8,341,248 MAC → **약 34 µJ**, ① 18,942,464 MAC → **약 76 µJ** (NPU 연산분만,
CPU 대기·적재 제외). 비 2.27. 위 표의 추론 구간 추정((가) 기준 ④ 59 µJ,
① 167 µJ)과 같은 자릿수다 — **추정끼리의 일관성 확인이지 검증이 아니다.**

## 4.1 ① 종단간 — CPU 전처리 포함 (2026-10-02 추가)

전처리 실측 **47.87 ms** (POR 직후, 1000회 최악, 코어 100 MHz, NPU 꺼짐,
최적화 전 첫 구현 — `synthesis-check.md` 10절).

**전부 추정(실측 지연 × 공개 전력)이다.**

| 전력 상수 (P_전처리 / P_적재·출력 / P_추론) | ④ | ① 전처리 | ① NPU 쪽 | **① 합계** | **①/④ 비** |
|---|---:|---:|---:|---:|---:|
| (가) 데이터시트: 8.89 / 11.26 / 40.79 mW | 약 71 µJ | 약 426 µJ | 약 179 µJ | **약 604 µJ** | **8.5** |
| (나) Moss 24.8 / 24.8 / Ulkar & Okman 71.7 mW | 약 130 µJ | 약 1,187 µJ | 약 320 µJ | **약 1,507 µJ** | **11.6** |
| [참고] 전 구간 같은 전력 (시간 비) | — | — | — | — | **20.9** |

- P_전처리: (가)는 CNN 을 끈 CPU 활성 전력(8.89 mW). (나)에는 **CNN 을 끈 CPU
  연산 전력이 없어** Moss 의 "CNN 켜짐" 전류(24.8 mW)를 그대로 썼다 — 과대일
  수 있다.
- 비가 시간 비(20.9)보다 훨씬 작은 이유: ①의 시간은 대부분 **전력이 낮은
  CPU 구간**이다. 그래서 여기서는 비가 **모드 전력 비에 크게 의존**한다
  (8.5~11.6). 4절의 설명대로, 비가 시간에만 의존하는 것은 전 구간 전력을 같게
  볼 때뿐이다.
- 참고 대조: Ulkar & Okman 은 MFCC 전처리를 **826 µJ** 로 보고했다 (다른 특징·
  다른 프레임 구성). 우리 전처리 추정 426~1,187 µJ 와 같은 자릿수다.

## 4.2 M4 대조군 — NPU 효과 (2026-10-02 추가)

M4 소프트웨어 추론 실측 **863.8 ms** + 적재 0.27 ms (POR 직후, 1000회 최악,
코어 100 MHz, NPU 꺼짐. **단순 C 참조 구현(-O2), CMSIS-NN 아님** —
`synthesis-check.md` 11절).

**전부 추정(실측 지연 × 공개 전력)이다.**

| 전력 상수 | ④ NPU | M4 소프트웨어 | **M4/NPU 비** |
|---|---:|---:|---:|
| (가) 데이터시트: P_cpu 8.89 mW (M4) / 11.26·40.79 mW (NPU) | 약 71 µJ | **약 7,680 µJ** | **108** |

| [참고] 전 구간 같은 전력 (시간 비) | — | — | **341** |

- **NPU 는 M4 보다 판단당 시간이 341배 짧고, 에너지는 약 80~160배 적다
  (추정).** 추론 중 NPU 전력이 CPU 전력보다 높아도 시간이 압도적으로 짧아
  에너지가 함께 줄어든다 — 시간과 전력의 맞교환이 아니다 (CLAUDE.md 2장).
- 비가 시간 비(341)보다 작은 것은 NPU 구간의 전력을 더 높게 잡았기 때문이다.
  즉 **에너지 비의 범위는 P_추론/P_cpu 가정에서 온다.**
- ⚠️ M4 쪽은 **최적화하지 않은 참조 구현**이다. CMSIS-NN 으로 k배 빨라지면
  위 비도 k 로 나눠진다.
- 참고: Ulkar & Okman 은 M4F 소프트웨어 추론을 11,200 µJ (다른 모델)로
  보고했다. 우리 추정 7,680~21,430 µJ 와 같은 자릿수다.

## 4.4 한 표로 — 구성별 구간 내역과 비 (2026-10-02)

**모든 에너지 값은 추정(실측 지연 × 공개 전력)이다. 측정값이 아니다.**
시간은 POR 직후·1000회 최악·코어 100 MHz·CNN 50 MHz·바쁜 대기 (슬립 미포함).

전력 상수 — (가) 데이터시트 19-100868 Rev 1: 전처리·M4 추론 8.89 mW / 적재·출력
