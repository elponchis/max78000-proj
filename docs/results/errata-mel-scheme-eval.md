# 정정 — 멜 압축 법칙 실험이 **로그 특징으로 평가**되어 있었다 (2026-10-02)

## 한 줄 요약

> **"격차의 주원인은 로그 압축이다 (`log72 − cbrt = +0.267`)" 는 평가 버그의
> 산물이었다.** 올바른 특징으로 평가하면 `log72 − cbrt = −0.015` 다.
> **로그를 쓰지 않는 멜(세제곱근 압축)도 0.657 로 ① 로그 멜(0.671)과 0.014
> 차이**다. CLAUDE.md 2장의 "★ 확정된 핵심 주장" 은 **철회**한다.

## 무엇이 틀렸나

`tools/eval_confusion.py` 의 `collect_logits` 는 구성(`--config`)으로 Dataset 을
만드는데, 압축 법칙 실험(`1 lin` / `1 cbrt` / `1 log72`)을 전부 config **`mel`**
로 평가했다 (`data/logs-local/cmp_all.sh`). 그 경로는 `SafeSoundMel` 을 기본
인자(`scheme="log"`)로 만든다.

→ 진폭 선형·세제곱근·log72 로 **학습한** 모델에 **① 의 로그 특징**을 넣어
평가했다. 학습(train.py)은 각자의 법칙으로 했으므로 학습 로그의 값은 맞다.

2026-10-02 에 고친 "1단계 음량 정규화" 버그와 **같은 종류**다 — 전처리가
Dataset 생성 인자로 들어가는 구성을 평가 경로가 기본 인자로 만들었다.
그때 `CONFIG_DATA` 를 만들면서 멜 법칙 쪽을 같이 점검하지 않았다.

## 고친 것

- `tools/eval_confusion.py`: config `mel_lin` / `mel_cbrt` / `mel_log72` 추가,
  `CONFIG_DATA` 에 법칙을 명시
- `data/logs-local/cmp_all.sh`: 세 실행의 config 를 위 이름으로
- `tools/kat_evalpath.py`: `①-cbrt` 사례 추가 — **train.py --evaluate 와 일치**
  (argmax macro-F1 0.6999 = 0.6999). ① 로그 멜도 그대로 통과 (0.7210)

## 결론이 어떻게 바뀌나

| 주장 | 정정 전 | 정정 후 |
|---|---|---|
| **로그 압축이 ①−④ 격차의 주원인** | 확정 (`+0.267`) | **철회.** 로그를 뺀 멜도 0.617~0.657 이다 |
| **"로그는 NPU 로 옮길 수 없으므로 격차가 남는다"** | 핵심 주장 | **근거 상실.** 격차는 로그 유무로 갈리지 않는다 |
| 로그의 음량 불변성이 격차를 만든다 | 설명 | **근거 상실** (int8 표현 변화 IQR 실측 자체는 유효하나, 그것이 성능 격차의 원인이라는 연결이 끊겼다) |
| ①-lin ≈ D-1 (같은 양을 계산) | "붕괴" (0.302 vs 0.507) | **반대 방향**: ①-lin 0.617 이 D-1 0.507 보다 **0.11 높다** |
| ① ≫ 파형 계열 (+0.138) | 확정 | **유지** (이 버그와 무관 — 양쪽 다 기본 인자가 맞는 구성) |
| 범위를 넓히면 해상도를 잃는다 (70 → 72.2 dB, −0.03~−0.04) | 확정 | 유지 (−0.031, 단일 시드) |

**새로 생긴 질문**: 압축 법칙이 아니라면 ①−④ 격차(0.138)는 어디서 오는가.
남는 후보는 **앞단 자체**다 — 512점 STFT 의 파워(|X|² = re²+im²) + 멜 적분 +
2D CNN 대(對) NPU 의 128탭 conv + Abs(|re|, |im| 따로) + 1D CNN.
①-lin(0.617) − D-1(0.507) = 0.11 이 그 크기의 첫 추정이다 (단일 시드 대 3시드).
(c)′ 의 사전 등록 조건 2("격차는 log 위치가 아니라 앞단 표현에서 온다")가
이 방향과 같은 결론이었다.
