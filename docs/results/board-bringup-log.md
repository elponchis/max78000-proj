## 2. ★★ `kws20_demo` 실측 — **NPU 추론 1.849 ms**

25초간 영어 키워드를 말해 받은 결과
(`docs/results/board-logs/kws20-live-20261002.log`, 168행).

```
Word starts from index 14976 to 7552, padded with 3584 zeros, avg:418 > 350
3130240: Starts CNN: 5
3130240: Completes CNN: 5
CNN Time: 1849 us
Min: -32,   Max: 13
-----------------------------------------
Detected word: LEFT (99.8%)
```

### 2.1 인식 결과 — 21회 추론 중 15회 인식

| 인식 | 신뢰도 |
|---|---|
| LEFT / RIGHT | 99.8% / 100.0% |
| OFF ×2 | 96.4% / 100.0% |
| YES / NO | 100.0% / 99.6% |
| ZERO·ONE·TWO·THREE·FOUR | 100 / 99.6 / 100 / 99.9 / 100% |
| FIVE·SIX·SEVEN·EIGHT | 99.9 / 100 / 100 / 100% |
| **Unknown ×6** | — |

`Unknown` 6건은 전부 **진폭이 작은 창**이다 (`Min/Max` 가 −8~3, −11~5 등).
무음 임계(`avg > 350`)는 넘었지만 내용이 없던 경우 — 정상 동작이다.

### 2.2 ★ `CNN Time: 1849 us` — 21회 **전부 동일**

| | 값 |
|---|---:|
| **NPU 추론** | **1.849 ms** |
| hop 주기 (우리 설계) | 250 ms |
| **hop 대비** | **0.74%** |

KWS20 v3 는 우리 백본과 **층 구성·채널 수가 같다**(CLAUDE.md 0장). 따라서
이 값은 우리 ④ 구성 추론 시간의 좋은 근사다.

**G2 목표("추론 지연 ≤ hop 의 10%")를 0.74% 로 크게 만족한다.**

그리고 (c) 설계안의 CPU 로그 추정 **~1.28 ms** 와 나란히 놓으면:

> **전처리 하나(정수 로그)가 NPU 추론 전체의 69%** 다.

"가속기 친화적이지 않은 연산은 하나만 남아도 파이프라인을 지배한다"
(G8 의 주장)의 **첫 실측 근거**다.

⚠️ 한계를 함께 적는다.
- 이것은 **데모의 자체 출력**이고 DWT 1000회 최악값이 아니다. 21회가
  전부 같은 값이라 **분해능이 거칠다**(1 µs 단위로 보이지만 실제 변동을
  담지 못한다). G2 용 정식 측정은 따로 한다.
- CPU 1.28 ms 는 **손계산 추정**이다. 두 값을 비교해 결론을 내기 전에
  **같은 방식(DWT)으로 둘 다 재야 한다.**

## 3. 랩어라운드 — **예비 증거가 보인다** (확정은 아직)

CLAUDE.md 7장이 예측한 것: `micBuff[i] = sample * SAMPLE_SCALE_FACTOR / 256`
에 클램프가 없어 **큰 양의 피크가 큰 음수로 뒤집힌다** (MSDK main.c:1229).

실측 (21창의 `Min` / `Max`):

| | 값 |
|---|---:|
| `Min` 중앙값 | **−25** (최소 **−65**) |
| `Max` 중앙값 | **+15** (최대 +31) |
| **\|Min\| / Max 중앙값** | **1.69** |

**모든 창에서 음의 최솟값이 양의 최댓값보다 크다.** 마이크 파형은 대칭이
기대되므로, 이 치우침은 **양의 피크가 음수로 뒤집혀 `Min` 을 끌어내리고
`Max` 를 깎은 것**과 정합적이다.

⚠️ **아직 확정이 아니다.** 대안 설명이 둘 있다.
1. HPF 의 과도응답이나 마이크 자체의 비대칭
2. 말소리 자체가 비대칭 (성문 펄스는 실제로 비대칭이다)

→ **확정 조건**: 큰 소리(박수 등)를 넣어 `Min` 이 −128 쪽에 붙고 `Max` 가
작게 남는지 본다. 랩어라운드면 int8 범위를 넘는 순간 부호가 뒤집히므로
**`Max` 가 오히려 줄어드는** 역전이 보여야 한다.
`SAMPLE_SCALE_FACTOR=4` 에서는 마이크 FS 대비 −12.1dB 만 넘으면 발생한다.

**미수행 — 시간대 때문에 큰 소음을 낼 수 없어 보류** (2026-10-02 00:30).
`TASKS.md` 에 남긴다.

## 4. 사고 기록 — **SWD 리셋은 클럭 설정을 되돌리지 않는다**

### 증상

`kws20_demo` 를 올린 뒤 시리얼이 **`*` 만 167바이트** 나왔다. 그 다음
**`Hello_World` 를 다시 올려도 똑같이 `*` 만** 나왔다 — 처음에는 멀쩡히
`count : N` 이 나왔던 바이너리다.

### 헛짚은 것

- 보율 14종(14400~921600)을 리셋과 함께 훑었다 → **전부 `*`, 영문자 0개**.
  보율 불일치라면 다양한 쓰레기가 나와야 하므로 이 가설은 약했다
- `cdc_acm` 모듈 재로드 → 효과 없음
- OpenOCD 로 `GCR->RST0` SYS 비트 쓰기 → `Failed to write memory` 로 거부

### 원인

**`kws20_demo` 가 시스템 클럭을 IPO 로 바꾸고(main.c:332, `CLOCK_SOURCE 0`),
SWD `reset run` 은 클럭 컨트롤러를 되돌리지 않는다.** 그 뒤 올린
`Hello_World` 는 BSP 기본 클럭을 가정해 UART 분주를 계산하므로 전부 깨진다.

**USB 를 뽑았다 꽂아 POR 을 걸자 즉시 정상이 됐다.** 그리고 같은 세션에서
`kws20_demo` 를 다시 올리니 이번엔 깨끗하게 떴다 — 자기 클럭과 자기 UART
설정이 일관되기 때문이다.

```
ANALOG DEVICES
Keyword Spotting Demo
Ver. 3.2.3 (5/05/23)
***** Init *****
pChunkBuff: 128
pAI85Buffer: 16384
*** I2S & Mic Init ***
*** READY ***
```

아까 보였던 `*` 들이 바로 이 `*****` / `***` 였다 — **글자만 깨져 나오고
있었다.**

### → 규칙

> **예제·펌웨어를 바꿔 올릴 때는 POR(USB 재인가)을 거친다.**
> SWD 리셋만으로는 부족하다. 특히 **클럭 소스를 바꾸는 펌웨어**
> (`kws20_demo` 는 IPO) 다음에는 반드시.

POR 뒤에는 Windows 쪽에서 `usbipd attach --wsl --busid 1-3` 를, WSL 쪽에서
`modprobe usbhid` (필요시 `cdc_acm`) 를 다시 해야 한다.

⚠️ 이 사고는 **우리 펌웨어 설계에도 영향이 있다.** 우리도 CNN 가속기를
쓰려면 클럭을 올릴 것이고, `MEASURE_BUILD` / `DEMO_BUILD` 를 번갈아
플래싱하게 된다. **빌드를 바꿀 때마다 POR 을 거치는 것을 측정 절차에
넣는다** — 안 그러면 UART 가 깨져 측정이 날아간다.
