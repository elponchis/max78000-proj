## 3. 결과를 어떻게 읽는가

`glass`·`scream`·`dog_bark` 의 +35~43p 는 단일 시드의 표본 변동으로 설명되지
않는 크기다. `siren` 의 +2.1p 는 **설명된다** (4.2).

셋의 공통점은 **시간-주파수 구조가 판별 단서**라는 것이다.
- `glass` — 0.3초 광대역 과도음. 파형에서는 짧은 스파이크지만 스펙트로그램에서는
  전 주파수에 걸친 수직선이다
- `dog_bark` — 짧은 유성 파열의 반복. 하모닉 구조가 멜 축에 뜬다
- `scream` — 고주파 하모닉이 지속된다

반면 `siren` 은 ④에서도 가장 잘 되던 클래스이고(33.3%), ①에서 거의 그대로다.

→ **가설**: raw 파형 + KWS20 의 (128,128) 접기는 **광대역 과도음과 하모닉
구조에 특히 불리하고**, 주기적 변조음(사이렌)에는 상대적으로 덜 불리하다.
확정하려면 4.1 의 대조 실험이 필요하다.

## 4. 한계 — 이 표만으로 "전처리 위치의 효과" 를 주장할 수 없다

### 4.1 ★ 표현과 구조가 **동시에** 달라져 있다 (가장 큰 문제)

두 구성은 입력 표현만 다른 것이 아니다. **아키텍처도 다르다.**

| | ④ | ① |
|---|---|---|
| 구조 | Conv1d(k=1/3/6) 8층 — **KWS20 v3 파생** | Conv2d(3×3/1×1) 6층 — 본 연구 설계 |
| 출처 | 음성 키워드 인식(21단어) 토폴로지 | 없음 (새로 설계) |

④의 백본은 **음성용**이고, raw 파형 16,384샘플을 (128,128)로 접어 "128개 연속
샘플을 채널로" 취급한다. 1초 음성에는 맞는 편향이지만 광대역 과도음·주파수
변조음에는 나쁜 편향일 수 있다.

**즉 0.286 의 격차 중 얼마가 "표현" 이고 얼마가 "구조" 인지 분리되지 않는다.**
심사에서 "단지 2D CNN 이 더 좋은 것 아닌가" 라는 질문에 답할 수 없다.

→ **필요한 대조 실험 하나 (`wave2D`)**: ①의 2D CNN 에 ④와 같은 **(1, 128, 128)
raw 파형**을 넣는다. 학습 1회로 세 점이 생긴다.

| 비교 | 분리되는 것 |
|---|---|
| ①mel vs ④wave1D | 표현 + 구조 (지금 가진 것) |
| ①mel vs wave2D | 표현 (구조·풀링 고정) |
| wave2D vs ④wave1D | **구조 변경 (선행 풀링 포함)** |

구현했다 (`datasets/safesound_wave2d.py` + `ai85safesoundwave2dnet`). 파라미터
**157,535 로 ①과 정확히 같다.**

### 4.1.1 wave2D 의 이름표를 과장하면 안 된다

"표현만 다르다" 는 **과장**이다. 세 가지가 함께 달라진다.

1. **선행 2×2 AvgPool 이 붙는다.** 피할 수 없다 — 아래 4.1.2.
   이 풀링이 (128,128) 접기의 **행(연속 샘플) 축에서 2탭 저역통과 + 2배
   데시메이션**을 하므로 **4kHz 이상을 버린다.** 유리 파손처럼 광대역 과도음인
   클래스에 특히 불리하다. 열(8ms 간격 프레임) 축에서는 떨어진 두 값을 섞는다.
   → 즉 wave2D 가 ④보다 나빠도 "구조 탓" 이라고 말할 수 없고, 좋아도 그 이득에
   풀링의 영향이 섞여 있다
2. `(128,128)` 접기는 스펙트로그램이 아니다. 행은 연속 샘플, 열은 8ms 간격이라
   3×3 conv 가 보는 이웃이 물리적으로 인접한 시간·주파수가 아니다
3. 1D conv(k=1/3/6) 대 2D conv(3×3/1×1) 라는 연산 자체의 차이

**풀링은 MaxPool 이 아니라 AvgPool 이다** (2026-09-27 수정). 이 풀링만은 ReLU
이전의 **부호 있는 파형**에 걸리므로 MaxPool 이면 양의 피크만 골라 파형의 부호
구조를 망친다. conv2~conv6 의 MaxPool 은 ReLU 이후(비음수)라 그대로 둔다.

### 4.1.2 왜 풀링을 피할 수 없나 — 채널당 8,192픽셀

데이터 메모리는 **32KiB 인스턴스 16개 = 512KiB** 이고, 제약은 총량이 아니라
**채널 하나가 한 인스턴스 안에 들어가야 한다**는 것이다
(`ai8x-synthesis/README.md:1085`).

| 형식 | 한 인스턴스를 나눠 쓰는 채널 수 | 채널당 한계 |
|---|---:|---:|
| CHW (1층 입력) | 1 | 32,768 픽셀 (181×181) |
| **HWC (모든 층 출력)** | 4 | **8,192 픽셀 (약 90×90)** |

- 입력 `1×128×128` = 16,384 픽셀 → CHW 라 **들어간다**
- 1층 출력이 `128×128` = 16,384 픽셀 → HWC 라 **초과한다.**
  **채널 수와 무관하다** — 1층을 16채널로 줄여도 채널당 픽셀 수는 그대로다
  (16×128×128 은 총 262,144B = 512KB 의 50% 지만, 그게 기준이 아니다)
- 풀링 후 `64×64` = 4,096 픽셀 → 들어간다 ✅

**정보를 버리지 않는 대안이 있다 — `ai8x.fold(2)`.** 입력을 인터레이스로 접어
`1×128×128` → `4×64×64` 로 만든다 (ADI 의 Data Folding, `ai8x.py:42`,
README 참조). 버리는 것이 없고 4개 위상 오프셋이 채널로 분리된다. 그때 1층은
`Conv2d(4→32, 3×3)` 이고 파라미터가 288 → 1,152 으로 늘어 총 158,399 (①의
+0.5%) 가 된다. **wave2D 재실행 시 이쪽이 더 나은 기본값이다.** 지금 구현된
버전(AvgPool)을 먼저 돌려 보고, 결과 해석이 풀링 때문에 막히면 fold 판으로
다시 돌린다.

### 4.2 단일 시드 — `siren` 차이는 잡음 안이다

시드 1 한 번씩이다. test 고유 **원본** 수가 `siren` 75 / `glass` 155 /
`scream` 191 / `dog_bark` 447 이고(5장 규칙 1 — 신뢰구간은 원본 수로 계산한다),
`siren` 은 원본 75개에서 재현율 35% 근처이므로 95% 구간이 대략 ±11%p 다.

→ **`siren` +2.1p 로 "siren 은 개선되지 않았다" 고 말할 수 없다.** 반대로
`glass`·`scream`·`dog_bark` 의 +35~43p 는 이 폭으로 설명되지 않는다.
→ 시드 2, 3 을 추가해 총 3회씩 돌리고 평균±편차로 다시 적는다 (`TASKS.md`).

### 4.3 ④가 단지 덜 학습됐을 가능성을 배제하지 못한다

argmax 오경보가 ④ 4,896 vs ① 1,167회/h 다. 동작점 차이를 넘는 폭이고, 같은
LR 스케줄이 두 아키텍처에 똑같이 좋을 이유가 없다.

고정 오경보 비교는 **동작점은 중화하지만 "학습이 덜 됐다" 는 중화하지 못한다.**
④쪽 학습률·에폭을 따로 조정해 최선을 뽑은 뒤 비교하는 것이 원칙적으로 맞지만,
그러면 "같은 설정" 이라는 전제가 깨진다. 논문에는 **양쪽 다** 보고하는 것이
정직하다 — 동일 설정 비교와 각자 최선 비교 (7장 OrangePi 절의 원칙과 같다).

### 4.4 창 단위·이 테스트셋 구성에 의존한다

- 창 단위 수치다. 논문 오경보는 `tools/stream_eval.py`(빈틈없는 스트리밍)와
  보드 8시간 구동에서 얻는다
- 테스트 배경음의 **49.9%가 하드 네거티브**다(규칙 3-1 대로 일부러 헷갈리는
  소리만 모은 것). 실배치 구성이 아니므로 절대값은 부풀려져 있다.
  `eval_threshold.py` 가 "일반 배경음만 기준" 을 함께 낸다

### 4.5 지연·에너지가 없다 — G8 의 절반이다

이 문서는 G8 의 **정확도 축**만 채운다. ①은 M4 가 STFT+멜+로그를 매 250ms 마다
해야 하므로 지연·에너지 비용이 있고, 그것이 없으면 "전처리 위치" 의 트레이드
오프가 성립하지 않는다. **보드 확보 후 Phase 5** 다.

⚠️ 현재 방향이 유지되면 결론이 **"환경음에서는 CPU 프론트엔드를 유지하고 지연
비용을 감수하라"** 가 될 수 있다. 정당한 발견이지만 제목의 무게중심이 이동하므로
지도교수와 맞춰 둘 것.
