# ②′ 의 NPU 전처리 곡선 — 변형 b64 / f31 / b64f31 (사전 등록, 2026-10-17 저녁)

**학습 시작 전에 쓴다. 결과를 본 뒤 2·5·6절을 바꾸지 않는다.** 실행: `data/logs-local/run_chain33.sh` (chain33).

## 1. 질문

그림 1 에서 CPU log-mel 전처리는 점 4개(간격 62.5 / 50 / 25 / 16 ms)로 곡선을 이루는데
NPU 전처리는 ②′ 한 점뿐이다. ②′ 의 대역 수와 프레임 수를 늘린 변형을 같은 설계·같은 학습
설정으로 학습하면 NPU 전처리 쪽 곡선이 생기고, 두 곡선을 겹치면 **"같은 에너지에서 어느 쪽이
더 정확한가"** 를 구간별로 비교할 수 있다. 연구 질문(전처리 위치 ↔ 정확도·에너지)에 가장 직접적인
그림이다.

지금까지 NPU 쪽 시도 여섯 번(D-1, (a), (c), ②′ 등)이 전부 CPU log-mel 아래였으므로 NPU 곡선이
CPU 곡선을 넘을 가능성은 낮다. 넘지 못해도 "저에너지 구간은 NPU, 그 위는 CPU" 라는 경계가
어디인지(②′ 한 점인지, 더 넓은지)를 보일 수 있다.

## 2. 변형 (`models/ai85net-safesound-fe.py` VARIANTS)

접기 64·512탭 Gabor 초기값·k=8·적분 8 위치(60 ms)·로그단(SCALE_SH 14, SPAN 70 dB)·분류기
구조(가 의 2D CNN, 풀링 4단)는 ②′ 와 전부 같다. 바꾸는 것은 대역 수와 프레임 격자뿐이다.

| 변형 | 대역 | 프레임 (홉) | p1 | 분류기 입력 | FC 입력 | p1 가중치 | LO_Q8 | 진입점 |
|---|---:|---|---|---|---:|---:|---:|---|
| fe (②′) | 32 | 16 (64 ms) | Conv1d 64→64 | 1×32×16 | 256 | 32 KiB | 1279 | `ai85safesoundfe` |
| **b64** | 64 | 16 (64 ms) | Conv1d 64→128 | 1×64×16 | 512 | 64 KiB | 1627 | `ai85safesoundfe_b64` |
| **f31** | 32 | 31 (32 ms) | Conv1d 64→64 | 1×32×31 | 256 | 32 KiB | 1279 | `ai85safesoundfe_f31` |
| **b64f31** | 64 | 31 (32 ms) | Conv1d 64→128 | 1×64×31 | 512 | 64 KiB | 1627 | `ai85safesoundfe_b64f31` |

- 파라미터: p2 156,255 (32 대역) / 157,535 (64 대역, FC 만 다름). p1 은 ai8x 양자화 파라미터 포함 32,777 / 65,545.
- **31 프레임인 이유**: 유효 위치 249 안에서 8 위치 홉·8 위치 적분이면 8·30+8 = 248 이 한계다. 32 프레임은
  패딩이 필요해 피했다. 창은 992 ms (②′ 1,024 ms).
- **LO_Q8** 은 ②′ 와 같은 규칙으로 정했다 — 학습셋 400창(시드 0) E 분포의 p99 에 창 위끝을 맞추고 70 dB 폭
  (`tools/init_fe_fb.py --variant`). 64 대역은 p99 가 17.98 (32 대역 16.62) 이라 LO 가 1627 이다. 그 창에서
  아래 포화가 9.4 % (32 대역 3.6 %) — 규칙이 준 값이므로 그대로 쓴다. 시험셋은 보지 않았다.
- **검산 (2026-10-17 19:2x)**: 네 변형 모두 접기 검산(상대 오차 ≤ 3.9e−7), 톤 검산(6 톤 전부 기대 밴드), 모델
  bucketize 대 정수 경로(불일치 0~2 / 40만~79만, 전부 x.5 경계값) 통과. 역전파가 p1 까지 흐른다.
- **64 대역의 알려진 한계**: 512 탭(31 Hz 분해능)으로는 300 Hz 아래 멜 밴드를 못 가른다 — 톤 검산 인접비가
  60~300 Hz 에서 0.6~1.1 dB (32 대역은 3.8~24 dB). 저역은 학습이 보정하지 못하면 대역이 늘어도 정보가 늘지 않는다.
  이건 설계 한계이지 버그가 아니며, 결과 해석에 미리 적어 둔다.

## 4. 지연·에너지 예측 (실측 전 — 결과표에 쓰지 않는다)

②′ 보드 실측 구간(`fe-design.md` 8절: load1 0.282 / cfg1 0.023 / infer1 0.080 / cpu 0.840 / load2 0.134 /
cfg2 0.086 / infer2 0.532 / unload 0.006 ms)을 데이터량 비례로 늘린 값. CPU 구간은 가속기 메모리에서 읽는
int32 워드 수(②′ 2,048 = 64 채널 × 4 프레임 × 8 위치)에, infer2 는 p2 입력 픽셀 수에, load2 는 p2 입력
워드 수에 비례한다고 가정했다. 에너지는 논문과 같은 식 (CPU 구간 P_load, 데이터시트 전력).

| 구성 | 읽는 워드 | p2 픽셀 | 판단 1회 (ms) | 에너지 µJ (데이터시트) | 같은 자리 CPU 점 |
|---|---:|---:|---:|---:|---|
| ②′ 실측 | 2,048 | 512 | 1.98 | 40 | 가 43 µJ (0.754) |
| b64 예측 | 4,096 | 1,024 | ≈ 3.6 | ≈ 76 | ④ 71 (0.669) · 다 54 (0.758) |
| f31 예측 | 4,096 | 992 | ≈ 3.5 | ≈ 72 | 〃 |
| b64f31 예측 | 8,192 | 1,984 | ≈ 6.5 | ≈ 140 | 간격 400 167 µJ (0.820) |

→ 변형은 에너지가 ④ 근처(b64·f31)와 간격 400 아래(b64f31)에 올 것이다. 파레토 앞면에 오르려면
b64·f31 은 다(0.758)·④(0.669)를, b64f31 은 간격 400 아래 모든 점(최대 다 0.758)을 시험 macro-F1 에서
넘어야 한다. 비용의 지배항은 로그가 아니라 **가속기 메모리 int32 읽기**다 (②′ 실측에서 확인).

## 5. 판정 기준 (사전 등록 — 결과를 본 뒤 바꾸지 않는다)

채점은 chain32 와 같다: 시드 1~3, 정답 testL-S3 / real31L, 오경보 300회/h 문턱값(시험셋 배경),
`tools/scream_listened_test.py --score` → `tools/fe_ext_eval.py` 와 같은 경로로 외부 mAP, Welch 95 % CI
(`tools/eval_v2.welch`, 같은 시드끼리). 비교 대상은 v4+D 의 ④·가·다·간격 400 과 ②′ (`docs/paper/numbers.json`).

| | 기준 | 뜻 |
|---|---|---|
| A | 변형 X 가 **지배되지 않는다**: 추정 에너지(데이터시트) 가 X 이하인 기존 점(④·②′·가·다·간격 400·①′) 중 시험 macro-F1 점추정이 X 이상인 것이 없다 | 파레토 앞면에 오른다 (그림 1 의 `pareto_front` 와 같은 규칙) |
| B | A 를 만족하는 X 에 대해, 에너지가 X 이하이면서 F1 이 가장 높은 기존 점과의 차이 Welch CI 하한 > 0 | 앞면 등극이 시드 잡음이 아니다 |
| C | X − ②′ 의 시험 macro-F1 CI 하한 > 0 | 대역·프레임을 늘린 것이 NPU 쪽 정확도를 올린다 |
| D | 같은 에너지에서의 격차: X 의 에너지에서 CPU 곡선(가-다-간격 400-①′ 선형 보간)의 F1 − X 의 F1 | 보고용 수치 (판정 아님) |

**결과의 사용 (미리 정한다):**

1. **A ∧ B 를 만족하는 변형이 하나라도 있으면** — 그림 1 에 NPU 전처리 곡선(②′ + 변형 3, 점선)을 CPU 곡선과
   겹쳐 그리고 파레토 앞면 표시를 자산 생성기가 다시 계산한다. 표 1 에 그 변형 행을 넣고, 4절에 "NPU 전처리는
   … µJ 까지 앞면" 문단을 쓴다. 결론의 "앞면은 전처리를 나눈 중간 구성" 문장은 그대로 성립한다.
2. **전부 지배되면 (예상)** — 그림 1 에 NPU 곡선을 점선으로 겹쳐 그려 두 곡선을 보이고, 4절에 한 문단: "대역·
   프레임을 늘려도 NPU 전처리 곡선은 CPU 곡선 아래에 머문다(같은 에너지에서 −x~−y). 경계는 ②′ 한 점(40 µJ
   아래)이다." C 가 성립하면 "늘리면 NPU 쪽 정확도는 오르지만 에너지가 더 빨리 오른다", C 가 불성립이면
   "늘려도 정확도가 오르지 않는다 — 512 탭 분해능 한계(2절)" 로 쓴다. 표 1 은 지면(3쪽 상한)이 허락하면
   3행을 넣고, 넘치면 표 대신 본문 수치로만 적는다.
3. **일부 시드만 완주하면** — 완주한 시드 수(n)를 밝히고 n ≥ 2 인 변형만 Welch 를 쓴다. n = 1 은 점만 찍고
   판정하지 않는다.
4. **보드 실측 전에는 논문 그림·표에 넣지 않는다** (현재 논문의 규칙: 모든 점이 보드 실측). 실측 전까지는
   이 문서와 STATUS 에만 적는다. 실측은 ②′ 와 같은 절차(시드 1 체크포인트 → `fe_board_prep.py` → 두 네트워크
   펌웨어 → KAT 비트 일치 → 1000회 최악값). f31·b64f31 은 p1 입력을 청크 64 위치 + 직전 7 위치(448 샘플)로
   넣어야 8 프레임이 전부 유효하다 — 펌웨어 `FE_P1_IN_WORDS` 가 64 → 71 로 바뀐다.

**바꾸지 않는 것**: ②′ 의 사전 등록 판정(미통과)과 STATUS 본 표, 데이터·증강·학습 설정, 전력 상수.
