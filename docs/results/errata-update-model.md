# 정오표 — 평가 로더에서 `ai8x.update_model()` 누락 (2026-09-30)

**이전에 보고한 고정 오경보 수치가 전부 틀렸다.** 원인·검증·영향·정정값을
한곳에 모은다. 이전 수치는 지우지 않고 "정정 전" 으로 표기해 남긴다.

---

## 1. 무엇이 잘못됐나

`tools/eval_confusion.py` 의 `load_model()` 이 체크포인트를 얹은 뒤
**`ai8x.update_model(model)` 을 부르지 않았다.**

`ai8x-training/train.py:415` 가 체크포인트 로드 직후 반드시 부르는 것이다.
이 함수는 모든 `QuantizationAwareModule` 에 `set_functions()` 를 다시 걸어,
**로드된 `weight_bits` / `bias_bits` / `output_shift` 에 맞는 양자화 함수**를
설치한다.

부르지 않으면 모델은 생성 시점의 설정(`weight_bits=None`, 즉 양자화 없음)을
그대로 쓴다. 결과적으로 **QAT 체크포인트를 fake-quantization 없이 순수 float
로 평가**하게 된다. 학습 중 forward 에는 그 양자화가 들어갔으므로, 평가
경로가 **학습·하드웨어와 달랐다.**

```python
# tools/eval_confusion.py  load_model()
missing, unexpected = model.load_state_dict(sd, strict=False)
...
ai8x.update_model(model)      # ← 이 줄이 없었다
```

⚠️ `strict=False` 로드가 **경고를 내지 않았다** — 키는 전부 맞았기 때문이다.
"불일치 수를 보고한다" 는 기존 안전장치가 이 종류의 오류를 못 잡는다.

## 3. 영향 범위

`load_model()` 을 쓰는 모든 도구가 영향을 받는다.

| 도구 | 영향 | 상태 |
|---|---|---|
| `eval_confusion.py` / `eval_threshold.py` | 모든 고정 오경보·혼동행렬 수치 | **재측정** |
| `compare_runs.py` (`cmp_all.sh`) | 비교표 전체, 계열 잡음 | **재측정 완료** |
| `ceiling_table.py --dump` | ①·D-1(√) 칸 | 재측정 필요 |
| `event_eval.py --scan` | 이벤트 단위 로짓 캐시 | **재스캔 필요** |
| `fa_analysis.py` | 오경보 분해·청취 목록 (동작점이 바뀐다) | 재생성 필요 |
| `sim_late_log.py` | (a)/(c) 판정 | 재실행 필요 |
| `stream_eval.py` | 스트리밍 오탐 | 미실행 |

**영향받지 않는 것**
- **학습 자체** — `train.py` 는 `update_model` 을 부른다. 체크포인트는 유효하다.
- **`qat_best` 선택** — 학습 중 `initiate_qat`(train.py:627)이 양자화를
  켠 상태에서 검증하므로 선택 기준이 옳다.
- **합성 결과** (`synthesis-check.md`, (a) 합성) — `ai8xize.py` 는 자체
  경로를 쓴다.
- **데이터 준비·전처리 분석** (`lin-mel-range.md`, `zero_ratio_by_class.py`
  등) — 모델을 쓰지 않는다.
- **PANNs zero-shot** (`ceiling_check.py`) — ai8x 모델이 아니다.

## 5. ★ 결론이 어떻게 바뀌나

| 결론 | 정정 전 | 정정 후 | 판정 |
|---|---|---|---|
| **로그 압축이 주원인** | `log72−cbrt = +0.198` | **`+0.267`** | **유지 (강화)** |
| **① ≫ 파형 계열** | 0.673 vs 0.359 | **0.671 vs 0.515** | **유지 (격차 축소)** |
| **필터뱅크 초기화 (D-1−④)** | +0.110 | **−0.007** (시드 평균, 자 0.0211) | **효과 없음** |
| [참고] D-1−④ft | +0.080 | +0.035 (1.7배) | **근거로 쓰지 않는다** (④ft 가 더 약한 기준선) |
| **구조 무관 (wave2D−④)** | +0.004 | **−0.019** (1.4배) | **방향 반전, 크기는 여전히 작다** |
| **①-lin ≈ D-1** | 0.471 vs 0.494 | **0.302 vs 0.507** | **붕괴** |
| **제곱근 가중치 (파형)** | +0.030 (4.7배) | **+0.012** (자 0.0211 의 0.5배) | **미확정으로 후퇴** |
| 제곱근 가중치 (멜) | −0.018 | **−0.023** | 악화, 유지 |
| 해상도 무관 (k=2/4) | −0.011~−0.014 | **−0.017~−0.050** | 유지 (더 나빠짐) |
| 음량 정규화 (b1) | −0.014~−0.025 | **−0.024~−0.039** | 유지 (불채택) |
| 증류 (C′) | −0.074 | **−0.048** | 유지 (해롭다) |

### 가장 크게 무너진 것 — `g8-round5.md` 4.5절 가설

> "①-lin(로그를 뺀 멜)이 D-1(NPU 필터뱅크)과 같은 자리에 있다"

**성립하지 않는다.** 0.3022 vs 0.5072 로 0.205 차이다. 두 경로가 같은 양
(멜대역 크기)을 계산한다는 **구조적 설명은 그대로**이지만, **관찰이 사라졌다.**

→ 오히려 반대 방향의 물음이 생긴다: **같은 양을 계산하는데 왜 ①-lin 이
D-1 보다 0.205 나쁜가?** 후보는 (i) ①-lin 의 int8 양자화 손실(진폭 선형
48.1dB, 이벤트 빈 40.3% 바닥) 이 D-1 의 활성화 양자화보다 가혹하다,
(ii) 2D conv 구조가 선형 스케일 입력에 특히 나쁘다. **미확정.**

### 살아남은 핵심 주장

CLAUDE.md 2장의 확정 주장은 **유지된다** — 오히려 근거가 강해졌다.

> 주파수 분해는 NPU 첫 층으로 옮길 수 있고, 로그 압축은 옮길 수 없다.

- 로그 법칙 효과 `log72 − cbrt` = **+0.267** (정정 전 +0.198)
- 다만 "주파수 분해를 옮긴 효과(D-1−④)" 는 **−0.007 로 사라졌다.**
  → **"옮길 수 있다" 의 근거는 이제 없다.** 정확히는 **"옮겨도 손해가
  없다"** 까지만 말할 수 있다. 로그를 옮기지 못하는 것이 격차의 전부다.

## 6. 재발 방지

- `tools/eval_confusion.py` 의 `load_model()` 에 `ai8x.update_model()` 추가 +
  주석으로 이유 명시.
- **KAT 회귀 테스트** (`tools/kat_evalpath.py`): 고정 체크포인트 하나에 대해
  **평가 로더 결과 == `train.py --evaluate` 결과** 인지 확인한다.
  이 종류(평가 경로가 학습 경로와 다름)는 값이 그럴듯하게 나와서
  단위 테스트로 못 잡는다 — **외부 기준과 대조**해야만 잡힌다.

## 7. 교훈

1. **"그럴듯한 값" 은 검증이 아니다.** 정정 전 수치도 클래스별 재현율이
   합리적이었고 시드 간 일관성도 있었다. 틀렸다는 것을 알 방법은
   **독립 경로(train.py)와의 대조**뿐이었다.
2. **벤더 툴체인의 로드 절차를 그대로 따라야 한다.** `load_state_dict` 만으로
   충분하다고 가정한 것이 원인이다. train.py 가 로드 직후 무엇을 하는지
   읽었다면 막았다.
3. 이 사고는 `ai85safesoundnet_bias` 의 `setdefault` 무력화, `dimensions`
   중복 인자, 진입점 미등록, `--allow-incomplete` 전역 적용과 **같은 계열**
   이다 — 벤더 규약과 우리 코드의 접점. KAT 를 그쪽에 계속 늘린다.
