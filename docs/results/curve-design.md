# 정확도 대 에너지 곡선 채우기 — 설계와 사전 등록 (2026-10-02 승인)

> 이 문서의 시간·에너지는 **학습·보드 실측 전의 추정**이다 (NPU 사이클만 합성
> 실측). 정확도는 전부 `TBD`. 결과가 나오면 아래 "결과" 절에 적는다.

## 목적

④(싸고 낮음)와 ①′(비싸고 높음) 두 점 사이를 채운다. ①′ 의 CPU 전처리 비용을
줄인 변형 중 정확도를 유지하는 구성을 찾는다.

## 공통 조건

증분 계산 + V1 (float32 rfft + LUT 로그), 끝 정렬, 무패딩, 고정 로그 스케일
(TOP_DB 0 / SPAN 70), n_fft 512. 모델은 ①′ 와 같은 2D CNN — 입력 모양에 따라
FC 입력 길이만 달라진다 (`models/ai85net-safesound-mel.py` 가 스스로 계산).
정의: `datasets/melfeat.py` `INC_SPECS`. KAT: `tools/kat_curve.py` (모양·끝 정렬·
증분 성질·모델 forward, 전부 통과).

## 후보 (우선순위 순. 버리는 순서 4 → 3 → 2)

추정의 근거: V1 프레임당 실측 60,080 사이클 (멜 32 는 로그 절반 → 57,565),
링 버퍼 풀기 6.2 사이클/B, NPU 적재 26.3 사이클/워드. **NPU 사이클은 합성 실측**
(`tools/curve_synth_check.py` — 사이클·메모리는 가중치 값과 무관하다).
에너지는 데이터시트 전력 (8.89 / 11.26 / 40.79 mW) — **추정**.

- 네 변형 모두 **합성 통과**, 가중치 35.2~35.3%.
- **4번은 원안의 n_fft 256 을 hop 400 으로 교체했다** (2026-10-02 승인 조건:
  64×40 입력에서 모델·합성이 성립하면 교체 → 성립). h500 의 **무겹침 위험**
  (겹침 2% — Hann 창 가장자리의 샘플이 거의 0 으로 가중된다)을 직접 확인하는 후보다.
  n_fft 256 을 버린 이유: 저역 멜 필터 일부에 빈이 걸리지 않고, hop 250 에서
  같은 무겹침 문제가 생기며, rfft 256 의 비용 실측이 없다.
- m32 는 CPU 절감이 거의 없다 (멜 합 비용은 필터 수가 아니라 가중치 총수에
  비례한다). h500m32 의 효과를 hop 과 멜 수로 **분리**하는 용도다.

## 평가 — 사전 등록 (학습 전, `run_chain22.sh` 머리말과 같다)

- 3시드, @300/h macro-F1, ①′ 3시드 (0.6694 ± 0.0064)·④ 5시드 (0.5329 ± 0.0238)
  각각과 Welch 95% CI.

  CI 가 0 을 포함하지만 허용 폭을 벗어나면 "못 가른다". 유의하게 낮으면
  "정확도를 내주는 더 싼 구성" (차이·CI 병기).
- **클래스별 recall @300/h (특히 glass)** 를 ①′ 대비로 병기 — 무겹침으로
  과도음이 약해지는지.
- 그림에는 **돌린 후보 전부**를 싣는다 (선택 편향 방지). 보드 실측이 없는 점은
  빈 마커.
- **외부 검증 세트** (다른 세션이 `tools/external_set/`·`docs/results/external-set.md`
  에서 수집 중 — 이 세션은 건드리지 않는다): 준비되면 ④·①′·변형 전부를 평가해
  **테스트셋 순위와 외부 세트 순위의 일치 여부만** 보고한다. 외부 세트로 구성을
  고르지 않는다.
- ⚠️ 한계: 3시드의 CI 반폭이 약 0.015 라 실제로 0.01 낮은 변형도 통과할 수 있다.

### 보드 실측 범위 — **사전 등록 변경 (2026-10-03, 사용자 결정)**

원래 등록: "동등으로 채택된 변형만 보드 실측". 어느 후보도 동등을 통과하지 못해
