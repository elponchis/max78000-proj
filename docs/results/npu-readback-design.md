# NPU 내부 합산 + 8비트 출력 — 설계·사전 등록 (2026-10-21)

**범위.** ②′ 와 변형(b64 / f31 / b64f31)의 CPU 몫 가운데 **가속기 메모리 읽기 + |·| + 8위치 합**
(보드 실측 0.570 ms, CPU 몫의 67 %, `fe-curve-design.md` §9.1)을 NPU 층으로 옮긴다. 이번 단계는
**PC 시뮬레이션만**이고 보드는 건드리지 않는다. 논문(ksc2026)·파레토 결과는 바꾸지 않는다.
도구: `tools/npu_readback_sim.py`. 결과: `docs/results/npu-readback-sim/`.

## 0. 먼저 발견한 것 — 정수 로그가 190 사이클인 이유

`firmware/common/log2_q8.c` 의 `log2_q8_to_int8` 이 `(int64_t)(lg − lo) * 255 / span_q8` 로
**64비트 나눗셈**을 한다. Cortex-M4 로 컴파일하면(`arm-none-eabi-gcc -O2 -mcpu=cortex-m4`)
`__aeabi_ldivmod` 라이브러리 호출이 나온다 (소프트웨어 64비트 나눗셈, 수십~백여 사이클).
`lg` 는 uint32 의 Q8 로그라 ≤ 32·256 = 8,192 이고 `|lg − lo|·255 < 2^31` 이므로 **32비트**
정수 나눗셈(`sdiv`, 2~12 사이클)으로 바꿔도 **비트 동일**하다 (바닥 나눗셈 보정 포함). 이것은
특징을 바꾸지 않는 펌웨어 수정이라 재학습이 필요 없다. 사이클은 보드에서 재야 한다 — 아래 비용
표에서는 "로그 60 사이클(추정)" 으로 따로 한 행을 둔다.

## 1. 실현 가능성 — ai8x / MAX78000 제약

근거는 `ai8x-training/ai8x.py` 와 `ai8x-synthesis/izer/*.py`, 기존 합성 YAML
(`synthesis/safesound-fe-p1-hwc.yaml`)이다.

| 제약 | 근거 | 설계에 미치는 영향 |
|---|---|---|
| 층 안의 연산 순서는 **풀링 → 합성곱 → 출력 시프트 → 반올림·포화 → 활성화** | `ai8x.py` `QuantizationAwareModule.forward` (pool → op → scale → activate → quantize → clamp) | "Abs → 8위치 합" 은 **한 층에 못 넣는다**. 층 A = p1 합성곱 + Abs(8비트), 층 B = 풀링/합성곱으로 합산 |
| wide(32비트) 출력에는 활성화를 걸 수 없다 | `ai8x.py` `assert not wide or activation is None`; `izer.py:420` "`output_width` must be 8 when activation is used" | Abs 를 쓰려면 p1 출력이 **8비트**가 되어야 한다 → 동적범위 손실이 이 연구의 핵심 변수 |
| Abs 활성화는 지원 | `ai8x.py` `class Abs`, `izer/op.py` `ACT_ABS = 'Abs'` | D-1 이 이미 썼다 |
| 1D 평균 풀링: 크기 ≤ 16, 스트라이드 ≤ 16, **floor** (음수는 ceil) | `ai8x.py` Conv1d 풀링 assert; `AvgPoolFloorFunction`; `izer/compute.py pool1d` floor | 8위치 **평균**은 되지만 **합**은 아니다 → 3비트 손실. 합을 원하면 k=8 합성곱 |
| Conv1d 스트라이드는 1 뿐 | `ai8x.py` Conv1d `assert stride == 1` | k=8 "합 합성곱" 은 모든 위치를 계산한다(출력 50/57 위치). CPU 는 프레임 위치만 읽으면 된다 |
| 출력 시프트는 **층 단위** (−15..+15), 가중치는 int8 | `OutputShiftLimit` clamp(−15, 15) | 대역별 배율은 **가중치 여유**로만 (2 의 거듭제곱, 0~1비트 — 현재 가중치 최대 86/127) |
| 한 입력을 여러 층이 읽을 수 있다 | `izer/yamlcfg.py` `in_sequences` (ai85-facedet-tinierssd.yaml 등) | 안 B 의 병렬 복제 |
| 가중치 메모리 442 KB | 3장 | p1 32 KB(fe)·64 KB(b64) ×3 복제 + p2 ≈ 110 KB 도 여유 |

### 안별 층 구성 (p1 네트워크)

**공통 층 A** — `Conv1d(64 → 2n, k=8)`, 출력 **8비트**, 출력 시프트 s, 활성화 **Abs**.
가중치는 지금 p1 그대로(대역별 배율 g_b = 2^h_b 는 가중치에 곱한다, h_b 는 여유 안의 정수).
디바이스 int8 출력 = floor(y_int · 2^(s−7) + 0.5) 를 포화한 뒤 |·| (127 상한).

| 안 | 층 B (A 의 출력 위에) | p1 출력 → CPU 읽기 | CPU 가 하는 일 | 판단당 읽기 워드 (fe / b64 / f31 / b64f31) |
|---|---|---|---|---|
| **A-sum** | `Conv1d(2n → n, k=8)`, 가중치 0.5 (cos·sin 같은 대역 8탭), **wide int32**, 활성화 없음 | 프레임 위치의 int32 n×F' 개 | 정수 로그 + 시프트·배율 상수 보정 | 128 / 256 / 256 / 512 (지금 2,048 / 4,096 / 4,096 / 8,192) |
| **A-avg** | `AvgPool1d(8, stride 8)` → `Conv1d(2n → n, k=1)` 가중치 0.5, wide | n×F' int32 | 같음 (평균 floor 라 3비트 손실) | 128 / 256 / 256 / 512 |
| **B** | 층 A 를 시프트 s+4 / s / s−4 로 **3벌**(`in_sequences` 로 같은 입력) + 각각 A-sum 의 층 B | 3·n×F' int32 | 복제 선택(포화 안 된 가장 높은 배율: E < 1016) + 정수 로그 | 384 / 768 / 768 / 1,536 |
| **C** | A-avg 와 같되 층 B 출력도 **8비트**(가중치 0.5·(c+s), 시프트 0) | n×F' int8 (워드당 4) | **256칸 LUT** 한 번 + 대역 오프셋 + 포화 (정수 로그 없음) | 32 / 64 / 64 / 128 |

F' = 판단당 새 프레임 (fe·b64 4, f31·b64f31 8). p2(가 의 2D CNN)는 그대로다.
A-sum 의 "k=8 합성곱" 은 스트라이드 1 이라 출력 위치가 50(fe)·57(f31)개 나오지만 CPU 는
프레임 시작 위치(16 또는 8 간격)만 읽는다 — 읽기 수는 평균 풀링과 같고 NPU 연산만 더 든다.

### 합성기 수용 검사 (실행함, 2026-10-21 — `tools/npu_readback_synth_check.py`)

②′ 시드 1 의 q8 가중치(대역 배율 적용)에 위 층을 붙인 YAML(`synthesis/rb-{asum,aavg,c,b}-hwc.yaml`)과
가짜 정수 체크포인트로 `ai8xize.py --device MAX78000` 을 돌렸다. **네 안 모두 수용**된다
(`docs/results/npu-readback-sim/synth_check.json`, 생성물 `data/synth/out/rb_*`).

| 안 | 층 수 | 커널 길이(층별) | 비고 |
|---|---:|---|---|
| A-sum | 2 | [57, 29] | k=8 합 층의 커널 29 |
| A-avg | 2 | [57, 4] | 평균 풀링 + 1×1 |
| C | 2 | [57, 4] | 층 B 8비트 |

### 사용자 질문 "읽기를 약 32워드로" 에 대해
②′ 판단 1회는 32 대역 × **4 프레임** = 128 값이다. int32 로 읽으면 128 워드(안 A/B), int8 로
포장해 읽으면 32 워드(안 C). "32워드" 는 안 C 에서만 성립한다.

## 2. 특징 충실도 — 방법 (재학습 없음)

- 체크포인트: ②′ 시드 1~3 (`safesound-v4d-fe{,-s2,-s3}`), 변형 b64 / f31 / b64f31 각 시드 1~3.
- 정수 경로: p1 int8 가중치 W_int 는 QAT 그래프에서 뽑아 시드 1 의 q8 체크포인트
  (`data/synth/*-p1-q8.pth.tar`, 보드가 쓴 것)와 **같아야 한다** (도구가 assert).
  y_int 는 float32 conv 로 계산하되 |부분합| < 2^24 라 정확하다.
- 표본: SafeSoundV4 **학습** 창 2,048개(무증강, 클래스 교차 균등 간격). 시험·외부 창은 F1 에만 쓴다.
- 통계: 8비트 단계 값의 **포화율**(== 127), **0 비율**, 대역별 q 상관(평균·최소), 기준 q(int32 경로)
  와의 **로그 영역 RMSE**(int8 1단계 = 70/255 dB), |Δq| > 2 비율.
- ★ **출력 시프트 s 의 선택 규칙 (사전 등록)**: 안마다 s ∈ [−6, +8] 을 쓸어 학습 표본에서
  **기준 q 와의 RMSE(dB)가 최소**인 s 를 쓴다. 시험·외부 F1 로 고르지 않는다. 안 B 는 A-sum 의
  s 를 가운데 복제에 쓰고 ±4 로 복제한다.
- F1: p2 를 그대로 둔 채 안별 q 를 넣어 시험(testL-S3, 4,965창) macro-F1 과 외부(real31L, 673창)
  F1 을 **기존 채점 규칙 그대로**(시험 배경 @300/h 문턱, `eval_v4.score_ckpt` 와 같은 함수) 잰다.
  기준(안 없음)의 값이 `data/external_eval/fe_eval*.json` 기록과 0.003 안에서 같아야 한다 (도구가 assert).
- 미세조정: p2(cls) 만, **3 에폭, Adam 1e-4, 배치 128**, 손실 CE + 역빈도 클래스 가중치, 데이터
  SafeSoundV4 train 16,669창 + v4 증강(게인 ±12 dB·시프트·배경 혼합), KD 없음. **기준도 같은 조리법으로
  미세조정**해 대조군으로 삼는다 (조리법 자체가 F1 을 움직이는 몫을 분리). 마지막 에폭 값을 쓴다
  (검증 선택 없음). 원 학습은 150 에폭 KD(T=2, α=0.5) 였으므로 이 미세조정은 "짧은 적응" 이지
  재학습이 아니다.

## 4. 사전 등록 — 보드 단계로 가는 조건

보드(펌웨어 2개 네트워크 확장 + 재합성 + 1,000회 실측)로 넘어가는 것은 **다음을 만족하는 안·변형이
하나라도 있을 때**만이다.

> **G-1.** p2 미세조정 F1(시험, 3시드 평균)이 같은 조리법으로 미세조정한 기준 대비 **−0.01 이상**
> (즉 잃는 것이 시드 표준편차 안)이고, 추정 에너지(데이터시트)가 기준 ②′(40.4 μJ)보다 작다.
> **G-2.** 그 점이 그림 1 의 같은 추정 에너지에서 **CPU log-mel 곡선 위에 올라올 가능성**이 있다 —
> 구체적으로 변형 b64 / b64f31 의 미세조정 F1 이 같은 에너지 구간의 CPU 점(가 0.754 @43 μJ,
> 다 0.758 @54 μJ)보다 높거나, 95 % CI 가 겹친다.

G-1 만 만족하면 "②′ 를 더 싸게" 일 뿐 파레토 앞면은 그대로다 — 그 경우 보드 단계는 **하지 않고**
한계 절의 향후 과제로만 남긴다. G-2 까지 가야 보드 실측 가치가 있다. 둘 다 아니면 **중단**.

**로그 나눗셈 고침(§0)** 은 이 조건과 무관하게 펌웨어 수정 가치가 있으나, 논문 마감(10-28) 전에
보드 재측정을 하면 ②′ 주 값(1.982 ms)이 바뀌므로 **마감 전에는 하지 않는다**.

## 5. 재학습이 필요한 안과 비용

| 안 | 재학습 | 이유 | 비용 |
|---|---|---|---|
| A-sum / A-avg / B / C, p2 만 미세조정 | 없음 (3 에폭 미세조정) | p1 가중치 그대로, 8비트 양자화만 추가 | 변형·시드·안 하나당 CPU 약 5~10분 |
| 위 안을 **전체 QAT 재학습** (p1 도 8비트 출력에 맞춰 학습) | 필요 | 8비트 Abs 가 학습 그래프에 들어가야 p1 이 포화·0 을 피하도록 적응한다 | 150 에폭 × 약 3~4 h(WSL CPU, ②′ 기준) × 시드 3 = **9~12 h/안·변형** → 4 변형 × 2 안이면 3~4일 |

미세조정 결과가 G-1 에 가깝지만 못 미치면 전체 QAT 가 후보가 되나, 마감 전에는 불가능하다.

**읽은 것.**
- **8비트 Abs 단계가 병목이다.** 포화 5~22 %, 0 이 11~17 % 로 int8 의 42 dB 창이 70 dB 로그 창을
  못 덮는다. 동적범위를 합으로 되살리는 A-sum(RMSE 2 dB)과 복제 3벌 B(0.6 dB)만 특징이 살고,
  평균 floor·8비트 출력(A-avg, C)은 RMSE 6~7 dB 로 F1 이 0.12 무너진다 — 읽기 32워드(C)는 가장
  싸지만 쓸 수 없다.
- **B 는 특징은 지키지만 에너지가 는다** (p1 3벌 → NPU 추론 0.35 ms): ②′ 46.8 μJ > 기준 40.4.
  읽기 2,048 → 384 워드의 절약보다 NPU 연산 증가가 크다. 기준보다 싸면서 F1 을 지키는 안은 없다.
- **A-sum 은 변형에서만 성립한다.** ②′ 에서 −0.040 (G-1 미달), b64f31 에서 +0.012 (1시드) 에
  −16 μJ. 대역·프레임이 많을수록 읽기 몫이 커서 효과가 크다는 예상과 맞는다.
- **G-2 는 어디서도 성립하지 않는다.** b64f31 A-sum 0.706 @ 122 μJ(추정)는 같은 에너지 구간의
  CPU 곡선(간격 400: 0.820 @ 167 μJ, 다: 0.758 @ 54 μJ) 아래 멀리 있다. NPU 전처리 계열의
  위치(CPU 곡선 아래)는 읽기 비용을 없애도 바뀌지 않는다 — 격차는 비용이 아니라 표현(8비트 Abs 와
  선형 필터뱅크)에서 난다.
- 미세조정 조리법 자체가 기준을 **+0.045 / +0.018** 움직인다 (②′ / b64f31). 따라서 비교는 반드시
  "같은 조리법의 기준" 과 해야 하고, 위 괄호 값이 그것이다.

**판정 (사전 등록 4절).** G-1 은 b64f31 A-sum 만 1시드로 만족, G-2 는 없음 → **보드 단계는 하지
않는다.** 남은 시드·변형을 돌려도 G-2 가 뒤집힐 폭(0.05 이상)이 아니다.

**유일한 실행 가치: §0 의 32비트 나눗셈 고침** (특징 불변, ②′ 전처리 0.84 → 0.67 ms, b64f31 3.32 →
2.65 ms 추정). 마감 뒤 보드에서 사이클을 재고 ②′ 주 값을 갱신할지는 그때 결정한다.

**논문에는 넣지 않는다** (사용자 지시). 향후 과제 문장("8비트 출력에 맞춘 재학습이 필요하다")은

### 7.1 검산 중 발견 — 6절의 해석을 바꾼다

**(가) 시뮬레이션의 E = 0 결함 → 수정.** `Front.q_of` 가 시프트 상수를 로그 **뒤에** 더했다 (`log2_q8(E) + 256·(7−s)`).
`log2_q8(0) = 0` 이라 E = 0 인 (대역, 프레임) 칸이 −128 이 아니라 **−84(바닥 +12 dB)** 가 됐다. 펌웨어는 실제 정수
E′_int32 = 0 의 로그를 취해 −128 을 낸다. ②′ 시드 1 학습 표본에서 A-sum 의 칸 **9.65 %** 가 E = 0 이다. 수정(E = 0 → −128)
뒤 fe 시드 1 재실행: 그대로 A-sum 0.5387 / 0.3596 (수정 전 0.538 / 0.363), 미세조정 0.5935 / 0.4327 (수정 전 0.597 / 0.417) —
**A-sum 의 F1 은 거의 움직이지 않았다** (조용한 칸의 상수 오프셋은 p2 가 흡수한다). 6절의 표는 7.4 로 대체한다.

**(나) 사전 등록한 배율 규칙이 F1 의 나쁜 대리였다 (사후 발견).** 2절은 대역 배율 g(가중치 여유 안의 2 의 거듭제곱)와
시프트 s 를 "기준 q 와의 RMSE(dB) 최소" 로 고르게 했다. A-sum 은 g 2~4 · s 0 → 포화 10.9 % · 0 14.3 % · RMSE 1.49 dB.
배율 없이(**g = 1 · s = 0** → 포화 3.2 % · 0 20.1 % · RMSE 2.11 dB) 같은 가중치를 8비트로 내리면 **그대로 F1 0.5841 / 0.4176**
— 기준 0.5916 / 0.4252 대비 **−0.008 / −0.008** (`fe8_check.py` 3번; fe8 학습 그래프 = 정수 경로 A-sum1, 7.2). RMSE 가
더 큰 쪽이 F1 은 0.045 높다. **포화(큰 소리를 깎는 것)는 0(조용한 칸을 바닥에 붙이는 것)보다 분류기에 훨씬 해롭고**, 칸 평균
RMSE 는 그 비대칭을 보지 못한다. → 6절의 "8비트 Abs 단계가 병목 (A-sum −0.040)" 은 대부분 **배율 규칙의 산물**이다.
사후 발견이므로 시뮬레이션에 A-sum1(g = 1, s = 0 고정, "사후" 표시) 을 **추가**하고 기존 행은 그대로 둔다. 미세조정 값은 7.4.

**(다) ai8x QAT 의 활성화 문턱이 로그단을 건너 p1 → p2 를 잇는다 — ②′ 계열 전부의 학습 결함.**
ai8x-training `pre_qat` 는 QAT 시작(에폭 60)에 층별 활성화 히스토그램으로 문턱 t 를 정하고(그 층 출력에 2^(−t)),
`apply_scales` 가 torch.fx 로 그래프를 거슬러 **"이전 conv 층" 의 t 를 다음 층 문턱에서 뺀다** — 앞 층 출력이 2^(−t) 로
줄었으니 뒤 층 입력도 줄었다는 가정이다. ②′ 는 fe(p1, wide) → [|·|, 합, 정수 로그, /128] → cls.conv1 인데, fx 추적이
그 사이 연산을 전부 통과해 fe 를 conv1 의 이전 층으로 잡는다 (`fe8_check.py` 5번: fe 문턱 3 → conv1 **−3**).
**정수 로그가 스케일을 지우므로 이 보상은 틀리다**: conv1 입력(q/128)은 t_fe 와 무관한데 conv1 출력은 2^3 = **8배**가 된다.
학습된 체크포인트(시험 창 256개, p2 첫 층 cls.conv1):

| 모델 | 저장 문턱 | 출력 포화 (= 127/128) | 0 비율 | max\|w\| |
|---|---:|---:|---:|---:|
| 가 u1000 시드 1 / 2 / 3 (CPU log-mel, **같은 p2**) | 0 / 0 / 0 | **0.01 / 0.01 / 0.02 %** | 67 / 61 / 65 % | 0.56 / 0.56 / 0.50 |
| ②′ 시드 1 / 2 / 3 | −3 / −3 / −3 | **13.8 / 13.8 / 13.5 %** | 62 / 62 / 62 % | 0.42 / 0.50 / 0.48 |
| ②′ b64f31 시드 1 | −3 | **8.1 %** | 62 % | 0.48 |

wide 인 fe 자체는 문턱의 영향이 없고(float 그래프가 wide 층에 out_scale 을 걸지 않는다), 디바이스도 저장된 문턱으로 같은
시프트를 실현하므로 **학습 그래프 ≡ 펌웨어** 는 깨지지 않았다 (보드 KAT 불일치 0 이 그 증거다). 깨진 것은 **동작점**이다 —
②′ 계열(②′·b64·f31·b64f31)의 분류기 첫 층만 8배 뜨겁게 돌아 출력의 14 %(b64f31 8 %)가 잘렸고, CPU log-mel 계열(가·다·
간격 400·①′)에는 이 결함이 없다. 가중치를 1/8 로 줄여 보상할 수도 있었지만(ai8x 는 출력 시프트로 int8 정밀도를 지킨다)
학습은 그러지 않았다 (max|w| 가 가 와 비슷하다). 나머지 층(conv2~6)의 포화는 두 계열 모두 0.1~4 % 이고, 마지막 fc 의 포화
70~79 % 는 두 계열이 같다(로짓 상한, final_scale 2 — 공통 성질이라 비교를 흔들지 않는다).
**F1 비용은 미지**다 — 논문의 ②′ − 가 = −0.111 가운데 얼마가 이 결함인지는 **끊고 다시 학습해야** 안다 (7.3 의 ②′ v2).
심사 결과(11-16) 뒤 최종본(11-25)에 반영할 수 있는 종류의 결과이므로 chain34 를 fe8 보다 먼저 두었다.
끊는 법: `qat_link_cut=True` — `apply_scales` 의 fx 추적 **때만** p2 입력을 상수로 바꿔 연결을 끊는다 (실제 순전파·역전파·
평가·합성에는 들어가지 않는다; 벤더 패치 불필요). 검산: fe 문턱 3 일 때 conv1 문턱 0 (끊음) / −3 (원본); ②′ v2 2 에폭 예행
에서 fe 1, conv1 1 (자기 값).

**(라) Abs 와 반올림 순서.** ai8x-training 의 `activation="Abs"` 는 |·| 뒤 반올림, 디바이스(ai8x-synthesis `izer/simulate.py`)는
반올림·포화 뒤 |·|. 음수 v 가 정확히 k+0.5 인 자리(학습 표본의 0.35 %)에서 1 LSB 다르고, 조용한 대역(합 0~2 LSB)에서는
그 1 LSB 가 로그 뒤 q 를 최대 44 단계 움직였다 (첫 검산: q 일치 88 %). fe8 는 활성화 없는 8비트 층 + frontend 의 |·| 로
디바이스 순서를 따른다 → a 32,636,928 개 불일치 **0**, q 일치 **100 %**.
