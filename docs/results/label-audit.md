# 라벨 감사 — 데이터가 틀렸는가, 과제가 어려운가 (2026-10-08 밤)

v3·v3.1 1단계가 모두 미통과였고, 특히 **scream** 이 어느 판에서도 오르지 않았다 (외부 recall 간격 400
v2.1 23.0 → v3.1 18.5%, 시험셋 scream recall 은 v2.1 보다 내려감). 학습을 더 돌리기 전에 **데이터 쪽을
진단**한다 — 학습은 하지 않는다. 묻는 것은 셋 중 어느 쪽인가다:
**(a) 학습 데이터 라벨 문제, (b) 외부 세트 라벨 문제, (c) 둘 다 정상인데 과제가 어려움.**

도구: `tools/label_audit.py` (PANNs 실행은 시스템 python3, 채점·표·청취 표본은 같은 파일의 `--score`).
결과 캐시 `data/label_audit/` (git 제외). 청취 표본 `~/safesound-external/audit/` (저장소 밖).

## 0. 실행 전에 정한 것 (기준값 — 결과를 보기 전에 고정)

### 0.1 PANNs 조건

- **같은 체크포인트·같은 매핑**: `Cnn14_16k_mAP=0.438.pth` (16 kHz, AudioSet 527), `prepare_safesound.LABEL_SETS`
  그대로 import. 입력은 창 int8 ÷ 128 (`ceiling_check.py` 와 같다). 창 잘라내기는 무증강 경로
  (`row[MARGIN:MARGIN+WIN]`). 기존 시험셋은 `data/ceiling-panns-zs.npz` 캐시(5,207창, 같은 조건)를 재사용.
- **기준선(1절) 의 5클래스 점수**: `ceiling_check.zeroshot_logits` 와 같다 — 이벤트 = 라벨 묶음 최대 확률,
  배경 = 1 − max(이벤트 4). 문턱값은 `eval_external.thr_at` (margin 분위수) — 우리 모델과 같은 코드.
- **감사(2절) 의 클래스 점수** `s_c`: siren·glass·dog_bark 는 묶음 최대 확률. **scream 은 `Screaming` 하나**,
  고함 `s_shout` = max(`Yell`, `Shout`) 를 따로. 참고로 학습 필터가 썼던 묶음 최대 `s_scream_v1`
  (= max of Screaming·Yell·Shout·Battle cry·Children shouting) 도 병기.

### 0.2 "점수가 매우 낮은 창" 의 기준

| 구간 | 기준 | 뜻 |
|---|---|---|
| **매우 낮음** | `s_c < 0.02` | 학습 필터의 가장 낮은 임계값(scream 0.025)보다도 아래. PANNs 가 그 소리를 사실상 못 들은 창 |
| 낮음 | `s_c < 0.10` | siren·dog_bark 필터 임계값 아래 |
| 높음 | `s_c ≥ 0.50` | PANNs 가 자신 있게 그 클래스로 본 창 |

분포는 p10 / p25 / 중앙값 / p75 / p90 으로 적는다.

⚠️ **편향을 먼저 적어 둔다.** FSD50K 출처의 학습·시험 창(siren·scream·dog_bark)은 **PANNs 점수가 높은
순으로 골랐고 임계값으로 걸렀다** (3절). 따라서 그 출처의 "매우 낮음" 비율은 구조적으로 0 근처이고,
감사 대상으로서 의미가 있는 것은 **PANNs 를 쓰지 않은 출처 — 외부 세트와 AudioSet 학습분** 이다. glass 는
전 출처에서 태거를 쓰지 않았다 (임계값 0). 단 scream 의 FSD50K 필터는 **Yell·Shout 를 포함한 묶음**이었으므로,
`Screaming` 하나로 다시 보면 FSD50K 출처도 낮은 창이 나올 수 있다 — 이것이 이번 감사의 핵심 질문이다.

### 0.3 판정 규칙 (실행 전 고정)

`L(출처, c)` = 그 출처 양성 창 중 **매우 낮음** 비율.

- **(b) 외부 세트 라벨 의심**: `L(외부, c) ≥ 0.30` **이거나** PANNs 의 외부 recall@300/h(c) 가 PANNs 시험셋
  recall@300/h(c) 의 절반 미만. (PANNs 는 외부 창 선별에 쓰이지 않았으므로, 외부에서만 못 듣는다면
  라벨이 가리키는 소리가 창 안에 없다는 뜻이다.)
- **(a) 학습 데이터 라벨 의심**: `L(AudioSet 학습분, c) ≥ 0.30` 이거나 `L(FSD50K 학습, c) ≥ 0.30`
  (후자는 scream 을 `Screaming` 으로 다시 봤을 때만 실질적으로 가능).
- **(c) 둘 다 정상**: 위 어느 것도 아니고, PANNs 외부 recall 이 우리 모델보다 뚜렷이 높다 (PANNs 는 그 소리를
  듣는데 우리 모델은 못 듣는다 → 데이터가 아니라 모델·규모의 문제). PANNs 도 못 듣는다면 (c′) 과제 자체가
  어렵다로 적는다.
- 둘 이상이 동시에 걸리면 둘 다 적는다. 수치는 비율이고, 최종 확인은 4절 청취 표본으로 **사용자**가 한다.

### 0.4 청취 표본

클래스마다 "매우 낮음" 15창 + "높음" 5창, 전 출처를 합쳐 무작위(시드 78004), scream 우선. 파일명
`<클래스>_<출처>_<점수>_<n>.wav`, 정답 `answer_key.csv` 는 별도. 매우 낮음이 15 미만이면 낮음(<0.10)에서
채우고 그 사실을 적는다.

### 2.3 비명 "매우 낮음" 창은 어떤 창인가 (보조 분석, `tools/label_audit_extra.py`)

- **창이 이벤트를 덜 담아서가 아니다.** 외부 실사용 scream 74창 중 매우 낮음 41창: 창–이벤트 겹침 중앙값
  1.02 s (= 창 전체), 나머지 33창도 1.02 s. 겹침 < 0.5 s 는 매우 낮음 쪽 17% / 나머지 3% 로 약간 더 많지만
  다수는 **`Screaming` 으로 표시된 구간 한가운데** 에 있다. 이벤트 길이 중앙값도 1.55 vs 1.64 s 로 같다.
  AudioSet 학습분 `Screaming` 보유 234창도 매우 낮음 110 / 나머지 124 의 겹침 중앙값이 둘 다 1.02 s.
- **그 창에서 PANNs 가 들은 것**: 외부 매우 낮음 41창의 최상위 라벨은 `Speech` 13, `Music` 11, `Cheering` 3, 나머지
  낱개. AudioSet 학습분 `Screaming` 보유 매우 낮음 110창은 `Speech` 26, `Music` 15, `Vehicle` 11, `Animal` 11, `Cat` 7,
  `Siren` 5. 군중류 라벨 동반은 매우 낮음 24% / 나머지 6%.
- FSD50K 시험 scream 매우 낮음 30창의 최상위는 `Speech` 13, `Battle cry` 4, `Children shouting` 3, `Animal` 3 —
  묶음 필터(Battle cry·Children shouting 포함, ≥ 0.025)를 통과했지만 `Screaming` 은 낮은 창들이다.
- 정리하면: **AudioSet strong 의 `Screaming` 구간은 1초 창 단위로 보면 절반에서 PANNs 가 비명 대신 말·음악을
  듣는다.** 외부 세트와 AudioSet 학습분이 같은 비율(55 / 47%)로 그렇다 — 같은 출처·같은 주석 규칙이므로 당연하다.
  반면 FSD50K 계열의 scream 창은 PANNs 로 **골랐기 때문에** 11~13% 다.

## 3. FSD50K 출처 창의 추출 방식 (코드 확인, `scripts/prepare_safesound.py`)

`build()` 가 매니페스트의 모든 행을 **split 과 무관하게 같은 함수** (`analyze_clip` → `choose`) 로 처리하고, split 은
샤드 쓰기 대상만 가른다 (`writers[(cls_out, r["split"])]`). 따라서 **학습셋과 시험셋은 같은 방식**이다.
`MANIFEST.json` 의 설정: hop 250 ms, policy `tag`, floor_zero 0.95, rel_ratio 0.30, max_win 3, tag_thr siren 0.10 /
glass 0 / scream 0.025 / dog_bark 0.10, tag_bg_thr 0.50.

1. **후보**: 클립 전체에 250 ms 겹침 격자로 1초 창 (`starts = arange(0, len−WIN+1, hop)`).
2. **에너지 필터** (`energy_mask`): int8 0 비율 ≤ 0.95 (이벤트만) + 클립 내 최대 RMS 의 0.30 이상.
3. **PANNs 태거** (에너지 통과분만): 클래스 묶음(`LABEL_SETS`) 최대 확률.
   - siren·scream·dog_bark: **묶음 최대 확률 ≥ 임계값**인 창만 남기고, **확률 높은 순**으로 (`rank = tag`).
   - glass: 임계값 0 = 태거 미사용. `Shatter` 보유 클립만 (라벨 단계), 순위는 **onset strength** (`rank = onset_score`).
   - background: 이벤트 묶음 최대 < 0.50 인 창, 순위는 RMS 큰 순 (조용한 15% 클립은 조용한 순).
4. **선택** (`choose`): 순위 순으로 서로 겹치지 않게 클립당 최대 3창. `data_overrides.csv` 의 청취 판정이 자동 판정을
   덮는다 (keep/drop/relabel).
5. 1초 미만 클립은 배경 베드 위에 얹고, 내부 디지털 0 런은 베드로 채운다 (`prepare_audio`, `fill_zero_runs`).

즉 FSD50K 출처의 siren·scream·dog_bark 창은 **"클립 라벨이 그 클래스이고, PANNs 도 그 묶음을 들었고, 그중 PANNs 점수가
가장 높은 자리"** 다. 무작위도 에너지 최대도 아니다. scream 의 묶음은 `Screaming`·`Yell`·`Shout`·`Battle cry`·
`Children shouting` 이고 임계값이 0.025 로 가장 느슨하다. 시험셋도 같은 규칙이라 **시험셋 scream 창 역시 PANNs 가
고른 창**이다 (ceiling-check 의 편향 경고와 같은 사실).

AudioSet 출처(v3 학습분, `build_v3_windows.py`)와 외부 세트(`external-set.md` 5절)는 다르다: **strong 라벨 시각**으로
창을 놓고 (학습분: 겹침 ≥ min(0.5 s, 이벤트 길이), 세그먼트당 최대 2창, 겹침→RMS 순; 외부: 가장 긴 이벤트의 중심)
PANNs 를 쓰지 않는다.

   정한다.
2. 우리 FSD50K scream 창은 PANNs 로 골랐으므로 (3절) 모델이 배운 비명은 **PANNs 식 비명**이다. 그 모델이 외부·AudioSet

   데이터를 섞은 결과**와 맞는다. v3 에서 시험셋 scream recall 이 내려간 것도 같은 설명이다 — 정의가 다른 양성 550창이
   결정 경계를 넓혔다.
3. 그 위에 PANNs 자체도 외부 비명을 50% (real31) / 23.5% (v1eq) 만 잡는다. 즉 **PANNs 로도 쉽지 않은 세트**다 —

   음향만으로 안 갈린다)과 맞는다.

종합: **siren·dog_bark 는 (c)** — 데이터는 정상이고 PANNs 가 듣는 것을 우리 모델이 못 듣는다 (규모·표현의 문제).
**scream 은 (a)+(b) 의 형태를 띠지만 내용은 "두 출처의 비명 정의가 다르다"** 이고, 어느 정의가 맞는지는 청취 표본
15창으로 사용자가 정한다. 청취 결과가 "AudioSet 쪽도 진짜 비명" 이면 우리 FSD50K 필터(PANNs 묶음 선별)가 비명을
좁게 뽑은 것이고 (a), "말·환호" 이면 AudioSet `Screaming` 주석이 느슨한 것이다 (b). **glass 는 PANNs 로 판정 불가.**

하지 않은 것: 학습·재학습 없음, 문턱값·규칙 변경 없음, 외부 세트 파일 변경 없음. 청취 표본의 정답 판정은 쓰지 않았다
(사용자가 한다).
