# 종료 코드 버그 소급 감사 (2026-10-01)

## 무엇이 틀렸나

체인 스크립트가 쓰던 줄:

```bash
echo "=== $(date +%H:%M:%S)  종료 $1 (exit $?)"
```

**명령 치환이 먼저 실행되어 `$?` 를 `date` 의 종료 코드(항상 0)로 덮는다.**
검산:

```
$ bash -c 'false; echo "$(date +%S) exit=$?"'
46 exit=0          ← false 였는데 0
```

즉 **chain10~14 의 모든 "(exit 0)" 은 `date` 의 것**이고, 학습이 죽었어도
0 으로 찍혔다. 그 위에서 세 판정을 냈다 — chain13 (a)/④ 5시드,
chain11 학습 곡선, chain14 혼합 증강.

## 감사 방법 — 체인 로그를 믿지 않는다

`tools/audit_runs.py`. **학습 로그에서 직접** 세 가지를 본다.

| 검사 | 통과 조건 |
|---|---|
| 마지막 에폭 | 로그에 `Epoch: [149]` 가 있다 (150 에폭) |
| 최종 테스트 | `Test: [` / `--- test (` 가 있다 — distiller 는 다 끝난 뒤에만 찍는다 |
| 체크포인트 | 평가가 쓴 `*_qat_best.pth.tar` 가 실재한다 |

셋이 서로를 대신하지 못한다. `qat_best` 는 **에폭 60부터** 생기므로
파일 존재가 완주를 뜻하지 않는다.

## 고친 것

1. **chain15 부터** `local rc=$?` 로 먼저 담고, 0 이 아니면 체인을 멈춘다.
2. `tools/audit_runs.py` 를 남겨 체인이 끝날 때마다 돌린다.
3. 감사 도구는 **진행 중과 실패를 구분**한다 — `/proc` 에서 살아 있는
   `train.py` 의 `--name` 을 읽는다. 없으면 돌고 있는 체인의 멀쩡한
   실행이 "실패" 로 찍혀 **감사가 거짓 경보를 낸다.**
