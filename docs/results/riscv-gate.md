# RISC-V 상시 대기 게이트 검토 — 데이터시트 계산 (2026-10-20)

범위: **데이터시트 계산만.** 보드·원고는 건드리지 않았다. `riscv-feasibility.md` 가
"전처리를 RV32 로 옮기기" 를 다뤘고, 이 문서는 RV32 의 원래 쓰임인
**상시 대기 게이트**(RV32 가 듣고 M4·NPU 는 수면, 이벤트 후보에서만 깨움)를 다룬다.
**모든 수치는 데이터시트 기반 추정**이다 — 측정이 아니다. 전력은 **칩 전력만**이고
마이크·코덱(MAX9867)·PMIC·LED 는 어느 설계에서나 같이 켜져 있으므로 넣지 않았다
(`energy-estimate.md` 2절 가정 표와 같다).

## 0. 결론 먼저

- **판단 비용은 평균 전력의 1.3~2.0 % 다.** 가 구성 판단 1회 43.3 µJ × 초당 4회
  = **0.173 mW**. 소리를 계속 받으려면 I2S·DMA·SRAM 이 살아 있어야 하고, 그 조건의
  가장 깊은 모드(LPM 또는 SLEEP)가 **5.2~11.3 mW** 다. 판단을 **전부** 건너뛰어도
  평균 전력은 2 % 가 못 줄어든다.
- **게이트가 아니라 대기 모드가 지렛대다.** M4 SLEEP + DMA(8.6~11.3 mW)에서
  LPM + RV32 수집(5.2 mW)으로 가면 31~45 % 가 준다. 그러나 이것은 RV32 가 **DMA 관리자**로
  수집만 해도 얻는 이득이고, "후보에서만 깨움" 논리 자체의 몫은 ≤ 2.2 % 다.
- **게이트가 의미 있는 조건**: 수집 대기 전력 < 판단 비용(0.17 mW) — 즉 I2S 없이
  깰 수 있는 경로(아날로그 마이크 + 저전력 비교기, µPM 0.69 mW)가 있어야 한다.
  FTHR 의 디지털 마이크·I2S 경로에서는 성립하지 않는다.

### 1.2 소리를 계속 받으면서 들어갈 수 있는 가장 깊은 모드

데이터시트 37~39쪽 (Power Management, Table 2 Wakeup Sources), 42쪽 (I2S) 근거.
UG7456 은 원문을 받지 못해(`riscv-feasibility.md` 1.2절) 데이터시트만 쓴다.

| 모드 | I2S | DMA | 코어 | 판정 |
|---|---|---|---|---|
| ACTIVE | ○ | ○ | 둘 다 실행 | 기준 |
| **SLEEP** | ○ ("Peripherals are on") | ○ ("Standard DMA is available") | CM4·RV32 모두 수면, 어떤 주변장치 인터럽트로도 기상 | **현 구성의 수집 대기** |
| **LPM** | ○ (RV32 접근 목록에 I2S 명시; Table 2 LPM 기상원에 I2S) | ○ ("The DMA can access flash") | CM4·SRAM0/1 상태 유지, **RV32 실행** | **RV32 게이트의 대기** |
| µPM | **×** — IPO·ISO 전원 차단, 가용 주변장치는 LPUART·WWDT1·비교기만 | × | 둘 다 상태 유지 | I2S 불가 |
| STANDBY / BACKUP | × | × | — | 불가 |

→ **I2S 를 살리면 SLEEP 또는 LPM 이 바닥**이다. µPM(0.69 mW) 아래로는 아날로그
비교기(CMP, µPM 가용) 경로만 남는데 FTHR 마이크는 디지털(I2S)이다. I2S 는 "Wakeup on
FIFO status (full/empty/threshold)" 를 지원하므로(42쪽) DMA 없이 FIFO 문턱 인터럽트로
RV32 를 깨우는 구성도 가능하다.

### 1.4 판단 비용과 비율

E_판단(가, 데이터시트) = **43.3 µJ** (`numbers.json` `energy.가 u1000`) → 초당 4회
= **0.173 mW**. 깨어난 뒤 **첫** 판단은 증분 로그 멜이 아니라 창 16프레임을 다
계산해야 하므로(u1000 은 32 멜 × 16 프레임, 판단당 새 프레임 4개) 전처리 4배 →
**103.8 µJ** (가정: 프레임 수에 비례).

| 현 구성 (M4 SLEEP + DMA, 초당 4회 판단) | P_평균 | 판단 비율 |
|---|---:|---:|
| W1 + CNN 켜 둔 대기 + 판단 | 11.25 + 2.37 + 0.17 = **13.79 mW** | **1.26 %** |
| W2 + CNN 켜 둔 대기 + 판단 | 8.55 + 2.37 + 0.17 = **11.09 mW** | **1.56 %** |
| (W1 / W2 + CNN 마스크 유지 + 판단) | (11.50 / 8.80 mW) | (1.51 / 1.97 %) |

## 2. 게이트 구성 두 가지 — P_평균 (데이터시트 기반 추정)

r = 깨우는 비율(이벤트 후보로 판정되는 250 ms 블록의 비율). 깨우면 가 판단을 그대로
한다. 첫 판단의 추가 비용(103.8 − 43.3 µJ)은 **후보 블록마다 콜드 스타트**하는
최악으로 넣었다. CNN 은 켜 둔 대기(2.37 mW).

| 구성 | 대기 | r = 0 % | r = 1 % | r = 10 % |
|---|---|---:|---:|---:|
| 현 구성 (게이트 없음) | W1 / W2 | 13.79 / 11.09 | 〃 | 〃 |
| 참고: RV32 가 수집만 (LPM, M4 를 250 ms 마다 무조건 깨움) | W3 | **7.76** | 〃 | 〃 |
| **G1** RV32 60 MHz 상시 동작, 블록마다 에너지 문턱 | W3 | **7.58** | **7.59** | **7.63** |
| **G2** RV32 가 블록마다 깨어 문턱만 계산(≈0.2 ms, 듀티 0.1 %)하고 wfi | W4 ~ W3 (가정) | **4.29 ~ 7.58** | 4.30 ~ 7.59 | 4.34 ~ 7.63 |

읽는 법.
- G1 과 "수집만" 의 차이가 **게이트 논리 자체의 이득**이다: 7.76 → 7.58, **2.2 %**
  (r = 0). 현 구성 대비 31~45 % 가 줄어 보이는 것은 LPM 이 SLEEP 보다 싸기 때문이고,
  게이트 없이도 얻는다.
- G2 의 아래쪽 값(4.29)은 "RV32 가 자면 LPM 고정분만 남는다" 는 **가정**에 기댄다.
  데이터시트에는 그 행이 없고, I2S·DMA 가 도는 동적분이 빠져 있어 실제는 위쪽에
  가까울 수 있다. 보드 전류 계측 없이는 확정할 수 없다 (장비 없음).
- r 을 10 % 로 올려도 +0.05 mW 다. 거꾸로 말하면 **r 이 100 % 여도 손해가 거의 없다** —
  게이트는 해롭지 않지만 이롭지도 않다.

## 3. 게이트 이득 상한

**판단 비용을 전부 없애도(r = 0) 같은 대기 모드에서 평균 전력은 1.3~2.0 % 줄어든다
(데이터시트 기반 추정; CNN 켜 둔 대기 1.3~1.6 %, 마스크 유지 1.5~2.0 %).**

## 4. 탐지 측면의 위험

1. **짧은 소리의 시작을 놓칠 가능성.** 유리 파손은 0.3 s 과도음이다. 문턱을 250 ms
   블록 RMS 로 두면 블록 안의 짧은 어택이 희석되고, 조용한 환경의 멀리서 난 소리
   (dog_bark·scream 의 먼 녹음)는 문턱 아래라 **아예 평가되지 않는다** → 재현율
   손실. 우리 테스트셋에는 `--floor-zero` 를 통과한 조용한 이벤트 창이 있으므로
   (`energy-filter-sweep.md`), PC 에서 게이트를 모델링하면 그 손실을 수치로 볼 수 있다
   (미수행). 문턱을 낮추면 r 이 올라 이득이 더 줄지만, 2절처럼 손해는 거의 없다.
2. **깨운 뒤 1 s 창을 채우기 위한 버퍼.** 판단은 어택을 포함한 **1 s 창**이 필요하다.
   깨어난 시점부터 모으면 어택 앞 750 ms 가 비고, 학습 창은 RMS 피크 중심으로 잘라
   있어(5장 규칙 2; shift 증강 ±100 ms) 어택이 창 머리에 오는 분포는 학습에 없다.
   따라서 RV32 는 **항상 ≥ 1 s + hop 의 링 버퍼를 유지**해야 한다 — int16 20,000 샘플
   = 40 KB, int8(>>6 변환 뒤) = 20 KB. SRAM2 48 KB 에 int8 은 넉넉하고 int16 은
   가까스로 든다. 그 뒤 M4 가 SRAM2 를 읽어 판단한다 (CM4 는 전 SRAM 접근 가능, 37쪽).
   링을 유지하면 메모리·DMA 는 현 구성과 같아져 **W4 가정의 근거가 더 약해진다.**
3. **콜드 스타트.** 가 의 증분 로그 멜은 직전 12 프레임을 전제한다. 깨어나면 16 프레임을
   다 계산해야 하고(≈9 ms, 103.8 µJ 추정) 그만큼 첫 판단이 늦다. 이벤트 병합
   상태머신(2 s 유지)이 뒤따르므로 한 이벤트당 콜드 스타트는 한 번이다.
4. **r 의 환경 의존.** 하드 네거티브(교통·군중·식기)는 크다. 시끄러운 환경에서는
   r → 100 % 가 되어 게이트가 사실상 꺼진다. 에너지 손해는 거의 없지만, 게이트가
   "조용한 환경에서만 조금 이득" 인 장치가 된다.
5. **지연.** 블록 = hop(250 ms) 이면 판단 시점은 현 구성과 같고, 추가 지연은 콜드
   스타트 9 ms + LPM 복귀 9.5 µs + IPO 기동(미기재)이다.

## 5. 결론과 원고 문장 초안

**게이트가 의미 있는 조건.** 판단 비용 0.173 mW 가 지배적이 되려면
**P_수집대기 < 0.17 mW ≈ 57 µA** 여야 한다. I2S 를 살리는 어떤 모드도 (LPM 고정분만
해도 640 µA) 이보다 3.7 배 이상 크다. µPM 230 µA 조차 그보다 크고 I2S 가 없다.
따라서 **디지털 마이크 + I2S 경로에서는 상시 게이트가 평균 전력을 유의하게 줄이지
못한다.** 조건을 만족하는 길은 아날로그 마이크 + 저전력 비교기(µPM 가용, CMP0 는
STANDBY 에서도 기상원) 처럼 **I2S 없이 깨우는 경로**이고, 그 경우에도 비교기 문턱이
4번 위험(조용한 이벤트 미평가)을 그대로 안는다. 이는 본 연구 범위 밖이다.

**덤으로 드러난 것.** 평균 전력의 지렛대는 (1) 대기 모드 — M4 SLEEP(IPO 100 MHz)
11.25 → LPM 5.21 mW, (2) CNN 대기 — 켜 둔 대기 2.37 → 마스크 유지 0.08 mW 다.
둘 다 **판단 횟수와 무관**하고 게이트 없이 적용된다. 합치면 13.8 → 5.5 mW 로
60 % 다 (데이터시트 기반 추정, 보드 미검증).

**논문 5절 문장 초안** (수치는 "데이터시트 기반 추정" 표기):

> (초안 1) 판단 1회 에너지(43 µJ, 데이터시트 기반 추정)를 초당 4회로 환산하면
> 0.17 mW 로, 마이크 I2S 와 DMA 를 살린 가장 깊은 저전력 모드의 대기 전력
> (5~11 mW, 데이터시트 기반 추정)의 2 % 에 못 미친다. 따라서 RISC-V 코어를 상시
> 게이트로 두어 이벤트 후보에서만 NPU 판단을 수행하는 설계는 본 시스템의 평균 전력을
> 거의 줄이지 못하며, 지렛대는 판단 횟수가 아니라 대기 모드와 가속기 메모리 유지
> 방식에 있다.

> (초안 2) 게이트가 유효해지려면 I2S 없이 깨울 수 있는 경로(아날로그 비교기 등)가
> 필요하고, 그 경우에도 짧고 조용한 이벤트가 평가되지 않는 재현율 손실과 1 s 창을
> 채우기 위한 상시 링 버퍼가 따른다. 이를 향후 과제로 남긴다.

`riscv-feasibility.md` 의 "향후 과제 한 문장" 은 이 결과를 보고 사용자가 다시 정한다.
