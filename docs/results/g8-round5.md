## 2. 해상도 가설 — **기각**

첫 층 커널 k 를 1→2→4 로 늘리면 FIR 이 128→256→512탭이 되고 분해능이
500→250→125Hz 가 된다. **k=4 는 ① 멜의 `n_fft=512` 와 창 길이가 정확히 같다.**

| | macro-F1 @300/h | @1000/h | conv1 가중치 | 분해능 |
|---|---:|---:|---:|---:|
| k=1 | **0.4982** | **0.6305** | 12,800 B | 500Hz |
| k=2 | 0.4844 | 0.6241 | 25,600 B | 250Hz |
| k=4 | 0.4871 | 0.6216 | 51,200 B | 125Hz |

- 단조 추세가 **없고**, 셋 다 시드 잡음(0.052) 안이다.
- 학습 전 톤 검산에서 해상도가 실제로 개선됨을 확인했다 — 125Hz 톤의 인접
  밴드 분리도가 1.0 → 2.1 → **9.5dB**, 1000Hz 에서 1.5 → 6.5 → **36.8dB**,
  k=4 는 미분리 밴드 0개 (`g8-d1-filterbank.md` 부록 A.4).
  **초기화가 잘못 들어가서 안 오른 것이 아니다.**
- 파라미터는 165,457 → 178,257 → 203,857 (442KB 대비 36.6 → 39.4 → 45.0%).
  **7.7%·23.2% 를 더 쓰고 얻은 것이 없다.**

→ ①−④ 격차의 원인은 **주파수 해상도가 아니다.** 다음 가설은 로그 압축
(`config1-lin-design.md`, 학습 진행 중).

## 4.5 ★ 가설 — **주파수 분해는 NPU 로 옮겼다. 남은 격차는 거의 로그 압축이다** (미확정)

2026-09-29, ①-lin 결과를 보고 세운 것이다. **cbrt·log72 로 확정한다.**

### 관찰

`①-lin`(로그를 뺀 멜)이 `D-1`(NPU 필터뱅크)과 **사실상 같은 자리**에 있다.

| 구성 | 전처리가 어디서 | 표현 | macro-F1 @300/h |
|---|---|---|---:|
| ④ | 없음 | raw 파형 | 0.3852 |
| ④-ft | 없음 | raw 파형 (파인튜닝 설정) | 0.4183 |
| **D-1** | **NPU** (Conv1d k=1 + Abs) | **멜대역 크기** | **0.4944** (3시드) |
| **①-lin** | **CPU** (FFT + 멜 + √) | **멜대역 크기** | **0.4709** (1시드) |
| ① | CPU (FFT + 멜 + log) | 멜대역 **로그** | 0.6733 |

**D-1 − ①-lin = +0.0235** — 시드 잡음(0.052)의 절반 이하다.

### 왜 같은 자리에 있는가 — 둘은 같은 것을 계산한다

우연이 아니다. 두 경로가 **수학적으로 같은 양**을 낸다.

```
①-lin :  x → STFT → |·|² → 멜 삼각필터 → (·)^0.5  → 멜대역 **크기**
D-1   :  x → Conv1d(k=1, 128탭 멜 대역통과 FIR) → Abs → 대역 **크기**
```

- D-1 의 첫 층은 `k=1` 이라 **128탭 FIR 100개**와 같다
  (`tools/init_filterbank.py`, `g8-d1-filterbank.md`). 멜 중심 주파수의
  cos/sin 쌍으로 초기화했고, `Abs` 가 `|re|`·`|im|` 을 그대로 준다 —
  즉 **대역 크기**다. 이것이 `abs_first=True` 를 고른 원래 이유다.
- ①-lin 은 파워에 `α=0.5` 를 걸어 **대역 크기**를 만든다.

둘 다 **대역 크기까지 가고 로그를 걸지 않는다.** 하나는 CPU 의 FFT 로,
다른 하나는 NPU 의 Conv1d 로 계산할 뿐이다. 그리고 같은 성능에 도달한다.

### ⚠️ 비중 분해는 근거가 아니라 **설명용**이다

아래처럼 쪼갤 수 있다.

| 조각 | 값 |
|---|---:|
| 주파수 분해 (D-1 − ④) | +0.1092 |
| 로그 압축 (① − ①-lin) | +0.2024 |
| 중복 (D-1 − ①-lin) | −0.0235 |
| 합 | +0.2881 = ① − ④ |

**이 합이 맞는 것을 근거로 쓰면 안 된다.**
`(D-1−④) + (①−①lin) − (D-1−①lin)` 을 풀면 `① − ④` 다 — 네 값이 무엇이든
항상 성립하는 **항등식**이다. 표는 두 요인의 **상대 크기를 보여주는 용도**
로만 둔다 (로그 쪽이 주파수 쪽의 약 1.9배).

가설의 근거는 아래 둘이고, 이것뿐이다.

1. **①-lin ≈ D-1 이라는 관찰.** 0.4709 vs 0.4944, 차이 +0.0235 로 시드
   잡음(0.052)의 절반 이하다. 서로 다른 경로로 만든 두 구성이 같은 자리에 있다.
2. **둘이 같은 양을 계산한다는 구조적 설명** (바로 위). 우연한 일치가 아니라
   **왜** 같은 자리여야 하는지가 설명된다. 1번만으로는 우연일 수 있고, 2번만
   으로는 실제로 그런지 알 수 없다 — 둘이 함께여야 가설이 선다.

### 가설 문장

> **①−④ 격차는 (a) 주파수 분해와 (b) 로그 압축, 둘로 거의 전부 설명된다.
> (a) 는 NPU 지원 연산(Conv1d + Abs)으로 옮길 수 있고 D-1 이 그것을 했다.
> (b) 는 NPU 가 지원하지 않으며, 남은 격차의 대부분이 여기서 온다.**

두 요인의 상대 크기는 **로그 쪽이 주파수 분해 쪽의 약 1.9배**다 (0.202 vs 0.109). 위 ⚠️ 대로 이 분해는 설명용이다.

이것이 사실이라면 G8 의 결론이 구체적인 연산 수준으로 내려온다 —
"전처리를 가속기 친화적으로 재설계하라" 가 아니라
**"대역 분해는 옮길 수 있고, 로그는 옮길 수 없다"** 가 된다.

### 아직 가설인 이유 (확정 조건)

1. **①-lin 이 단일 시드**다. D-1 은 3시드(0.4982/0.4917/0.4932)로 촘촘하지만
   ①-lin 은 한 번이다.
2. **①-lin 은 "압축 없음" 이 아니라 α=0.5 거듭제곱**이다. 진짜 무압축(파워
   선형)은 이벤트 멜 빈의 87.3%가 int8 바닥이라 실험이 성립하지 않는다
   (`config1-lin-design.md` 2절). 즉 (b) 에는 **동적 범위 붕괴**가 섞일 수 있다.
3. D-1 과 ①-lin 은 뒤쪽 구조가 다르다(1D conv 8층 vs 2D conv 6층). wave2D 에서
   구조 효과가 +0.004 로 잡음 안이었지만(4.1.3) 0 이라는 증명은 아니다.

**확정 실험 (진행 중)** — 판정 규칙은 결과를 보기 전에 정해 두었다
(`config1-lin-design.md` 3절).

| 관찰 | 결론 |
|---|---|
| ①-log72 ≈ ①-cbrt | 중요한 것은 **동적 범위**다 → 위 가설 수정 필요 |
| ①-log72 ≫ ①-cbrt | 중요한 것은 **로그 법칙(음량 불변성)** 이다 → 가설 확정 |

### 중간 결과 — ①-cbrt (2026-09-29 15:04 완주, 시드 1)

| 구성 | 압축 | 담는 범위 | 이벤트 바닥% | @300/h | @1000/h |
|---|---|---:|---:|---:|---:|
| ① | 로그 | 70.0dB | 17.5% | **0.6733** | 0.7151 |
| ①-lin | 진폭 (α=0.5) | 48.1dB | 40.3% | 0.4709 | 0.5690 |
| **①-cbrt** | **세제곱근 (α=1/3)** | **72.2dB** | **10.8%** | **0.4328** | 0.5245 |

**범위를 넓혔는데 좋아지지 않았다.** 48.1 → 72.2dB 로 늘리고 바닥 빈을
40.3% → 10.8% 로 줄였는데 ①-lin 과 **비슷하다** (−0.038, 시드 잡음 0.052 안).
"더 나쁘다" 고 쓰지 않는다 — 단일 시드에서 잡음보다 작은 차이다.

→ 말할 수 있는 것은 **"동적 범위를 24dB 더 담아도 회복되지 않는다"** 이다.
범위가 주된 원인이었다면 cbrt 가 ① 쪽으로 눈에 띄게 올라왔어야 한다. 그러지
않았으므로 위 가설의 한계 2번(압축과 범위가 섞여 있다)이 약해진다.
남은 후보는 **로그 법칙 자체**, 즉 게인을 평행이동으로 바꾸는 성질이다
(±12dB 에서 Δq IQR: 로그 1~3 vs 세제곱근 24, `lin-mel-range.md` 3절).

⚠️ 단 클래스별 움직임이 이상하다 — ①-cbrt 는 `glass` 가 27.2 → 38.9% 로 오르고
`dog_bark` 가 30.4 → 11.9% 로 무너졌다. 단일 시드라 이 편차가 시드 탓인지
압축 법칙 탓인지 지금은 가를 수 없다. **①-log72 가 나오면 함께 본다.**

## 5. 부수 발견 — OpenBLAS 소행렬 오버헤드 (67배)

멜 계열을 CPU 에서 돌리려다 배치당 5.6초가 나왔다(1D 는 0.11초). 원인은 2D
모델이 아니라 **멜 필터뱅크 행렬곱 하나**였다.

```
(64,257) @ (257,64)  =  2 MFLOP
  기본                       23.8 ms
  OPENBLAS_NUM_THREADS=1      0.148 ms   ← 160배, 결과는 비트 단위로 동일
```

`mel_int8()` 전체가 41.5ms → **0.616ms**, 학습 배치가 5.6s → **0.34s**.
`melfeat.py` 의 "창당 약 1ms" 주석은 틀리지 않았고 환경이 문제였다.
상세는 CLAUDE.md 12장. 노트북 멜 셀 5개와 `run_chain6.sh` 에 반영했다.

→ 이 덕분에 **2D 실험도 WSL CPU 에서 돌릴 수 있게 됐다** (실행당 81분).
Colab GPU 가 소진돼도 진행이 막히지 않는다.

## 6. 실수 기록

1. **진입점을 `models` 리스트에 등록하지 않아** 첫 체인이
   `train.py: error: argument --model: invalid choice` 로 즉사했다.
   진입점/train.py 인자 규약 불일치로 죽은 것이 네 번째라
   `tools/kat_entrypoints.py` 에 등록 여부 검사를 넣었다.
2. **`cmp_all.sh` 의 `ls -d | head -1`** 이 이름 순 첫 번째를 집어, 위 1번으로
   죽은 빈 폴더를 골랐다 → D-1(√)가 표에서 통째로 빠졌다. `ls -dt` 로 고쳤다.
3. **`run_chain6.sh` 의 속도 게이트가 잘못된 CWD 에서 돌아** argparse 오류로
   4초 만에 죽었고, 게이트는 그걸 "150에폭 3분" 으로 읽어 통과시켰다.
   `cd` 를 앞으로 옮기고 종료 코드를 보도록 고쳤다 — **게이트가 실패를
   통과로 읽으면 게이트가 아니다.**
4. `kat_melcomp.py` 에서 `ai8x.normalize` 를 역산해 통계를 냈다가 평균
   −231.9(int8 범위 밖)가 나왔다. `normalize` 는 `act_mode_8bit` 에 따라
   아핀이 달라진다(`ai8x.py:36`). 변환 전 원본 int8 을 직접 보도록 고쳤다.
