## 1. 왜 이것인가 — 지금까지의 NPU 프론트엔드가 공통으로 빠뜨린 것

D-1 · (a) · (c) 는 전부 같은 뼈대였다: ④ 의 접기 (128, 128) 에 k=1 conv → **128탭 FIR 을
프레임(8 ms)마다 한 샘플 위치에서만** 평가 → |·|. 이것은 대역 통과 신호의 **순간값 하나**의
크기이고 위상에 따라 요동한다. CPU log-mel 은 512샘플 창의 파워를 대역 안에서 **적분**한다.

| 증거 | 값 | 출처 |
|---|---|---|
| CPU 멜 파워에서 로그만 뺀 ①-lin | 0.617 (v1, @300/h) vs ④ 0.533 | `errata-mel-scheme-eval.md` |
| NPU FIR+Abs 순간값 (D-1) | 0.507 ≈ ④ | `STATUS.md` 1.1 |
| 탭을 512 로 늘린 D-1 k=4 | 0.485 (더 나쁨) | `g8-d1-filterbank.md` 부록 A |
| 로그를 NPU/CPU 에 더한 (a)/(c) | ④ 와 같다 | `STATUS.md` 1.3 |

→ 로그 없이도 **적분된 밴드 에너지**면 ④ 를 넘고, 적분 없는 NPU 표현은 탭·로그·분할을 바꿔도
④ 수준이다. 적분을 NPU 프론트엔드에 넣어 본 적은 없다. 이 실험은 그 하나를 검증한다.

목표는 ④ 의 정확도 회복이 아니라 **가 와 같은 정확도를 더 적은 에너지로** 다. 가 의 CPU 전처리
2.264 ms (판단 1회의 77 %) 중 선형 부분(STFT + 멜 = 필터뱅크)을 NPU 로 옮기고, CPU 에는 비선형
(|·|, 합, 로그) 128값만 남긴다. 성공하면 정확도-에너지 전선에 **NPU 전처리 점**이 생긴다.

## 2. 설계 (`models/ai85net-safesound-fe.py`)

```
s[0..16383] (④ 와 같은 int8 창)
 ── 접기 64 ──  X[r][p] = s[64p + r]                      (64 채널 × 256 위치)
 ── NPU p1 ──   Conv1d(64→64, k=8, 활성화 없음, wide int32)  = 512탭 FIR 64개, 홉 4 ms, 유효 위치 249
 ── CPU ──      mag[b][p] = |y[2b][p]| + |y[2b+1][p]|       cos·sin 쌍 → 밴드 32
                E[b][f]   = Σ_{p=16f}^{16f+7} mag[b][p]     프레임 홉 64 ms, 적분 60 ms, 16 프레임
                q         = to_int8(log2_q8(round(E·2^14)), LO_Q8 1279, SPAN_Q8 2976)
 ── NPU p2 ──   가 의 2D CNN (ai85safesoundmelnet_p4, 1×32×16) → 로짓 5
```

- **p1 초기값**: 가 의 멜 32밴드와 같은 중심(melfeat 식, 20~8000 Hz 의 34 경계 안쪽 32)의
  밴드폭 맞춤 Gabor (Hann 창 길이 1.44·sr/반폭, 64~393탭, 512 안 가운데 정렬), L2 노름 1.
  학습 가능 (D-1 과 같다). 모델이 스스로 만들므로 체크포인트 없이 시드마다 분류기만 달라진다.
- **로그단**: (c) 의 `log2_q8`(CLZ+LUT, 펌웨어와 비트 동일) 그대로. SPAN 70 dB 고정(① 과 같은 폭),
  LO 는 학습셋 400창(시드 0) E 분포의 p99 에 위끝을 맞춤 (`tools/init_fe_fb.py`; 시험셋 미사용).
  창 [5.00, 16.62] log2 — 아래끝 v≈32 로 정수 해상도 지점(v≈30) 위. 포화 아래 3.55 % / 위 1.00 %.
  순전파 = bucketize(정수 경로에서 뽑은 경계 255개), 역전파 = STE ((c) 와 같다).
- **판단 주기**: 이 구성은 **256 ms** (4,096 샘플 = 1.024 s 창의 1/4; 프레임 경계가 1,024 의 배수).
  다른 구성의 250 ms 와 2.4 % 차이. 펌웨어는 새 4,096 샘플만 p1 에 넣고(접기 (64, 64), 유효 57 위치,
  프레임 4개) 32×16 버퍼를 민다. 학습은 창 전체를 한 번에 계산하지만 conv 가 위치 불변이라 같은 값.
- **학습 설정 = 가 v4+D (chain29) 와 동일**: 데이터 `SafeSoundV4D` (원파형 접기, ④ 와 같은 로더 +
  PANNs 프로브 교사 증류 T=2 α=0.5, 라벨 없는 창 94,024), 150 에폭, Adam lr 0.001, batch 128,
  `colab/schedule_safesound.yaml`, `colab/qat_policy_safesound.yaml`, 시드 1·2·3, WSL2 CPU.
  초기화 체크포인트 없음 (모델 내장). `data/logs-local/run_chain32.sh`.

| 구간 | ②′ | 근거 |
|---|---:|---|
| p1 입력 적재 (4,096 B) | 0.272 ms | ④ 의 16,384 B 적재 1.087 ms 를 선형 비례 (가정) |

| 출력 | 0.005 ms | 가 실측 |
| **판단 1회** | **≈ 1.22 ms** | |

E = t_cpu·P_cpu + (적재 + 출력)·P_load + NPU·P_npu (다른 구성과 같은 식, `paper_config.json`):
(가) 데이터시트 **≈ 31 μJ** (가 43), (나′) Moosmann **≈ 37 μJ** (가 78), (나) 선행연구 ≈ 59 μJ (가 98).
t_cpu 가 1.3 ms 까지 커져도 (가) 기준 가 보다 적다. 네트워크 전환 비용(레지스터 쓰기 ~400회)은 미포함.
⚠️ 보드 실측(두 네트워크 전환 펌웨어)은 이 실험의 범위 밖이며 시간이 되면 한다. 안 되면 (a) 처럼
"추정(합성 사이클)" 으로 표기한다.

## 5. 판정 기준 (사전 등록 — 결과를 본 뒤 바꾸지 않는다)

시드 1~3, 정답 testL-S3 / real31L, 오경보 300회/h 문턱값(시험셋 배경), Welch 95 % CI
(`tools/eval_v2.welch`, 같은 시드끼리). 비교 대상은 v4+D 의 ④ 와 가 (`docs/paper/numbers.json`).

| | 기준 | 뜻 |
|---|---|---|
| A | 시험 macro-F1: ②′ − ④ 의 CI 하한 > 0 | 원파형(전처리 없음)보다 유의하게 낫다 |
| B | 시험 macro-F1: ②′ − 가 의 점 추정 ≥ −0.02 | 가 와 같은 정확도 |
| C | 외부 F1 real31L: ②′ − ④ 의 CI 하한 > 0 | 외부에서도 ④ 보다 낫다 |
| D | 추정 에너지 (가) 데이터시트·(나′) Moosmann 둘 다 ②′ < 가 | 전선에 오른다 |
| E | 외부 배경 264창 발화 ≤ 가 + 2창 | 배경 오탐이 늘지 않는다 (보고만, 판정에 안 씀) |

**통과 = A ∧ B ∧ C ∧ D.** 통과하면 "전처리의 선형 부분을 NPU 로 옮기면 같은 정확도에서 에너지가
준다" 를 쓸 수 있고 ②′ 가 그림 1 의 NPU 전처리 점이 된다. 미통과면 결과를 그대로 적는다 —
"에너지 적분을 넣어도 안 됐다" 한 줄. 어느 쪽이든 본 표는 바뀌지 않는다.

n=3 이라 A·C 의 검출력은 약 +0.05 (④ sd 0.025) 이다. 가 − ④ 가 +0.085 였으므로 B 를 만족하는
결과라면 A 도 대체로 만족한다. B 가 −0.02 ~ −0.05 사이면 "가 보다 조금 낮지만 ④ 보다 낫고 에너지가
적은 중간 점" 으로 보고하되 통과로 쓰지 않는다.
