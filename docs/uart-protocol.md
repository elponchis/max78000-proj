# UART 패킷 포맷 · SD 로그 스키마 · 이벤트 병합 상태머신

TASKS.md Phase 3.5 의 세 항목을 한 문서로 묶는다. 셋이 **같은 판정 기준** 위에
서 있어야 하기 때문이다 — 펌웨어가 이벤트를 만드는 규칙, SD 에 적는 내용,
호스트가 그리는 것이 어긋나면 G6·G7 이 서로 다른 시스템을 측정하게 된다.

보드 없이 확정할 수 있는 부분이며, 구현·검증도 보드 없이 끝난다
(`host/eventmerge.py`, `host/fake_serial.py`, `host/test_eventmerge.py`).

---

## 0. 전제 — 판정은 softmax 가 아니라 **마진**이다

오프라인 평가(`tools/eval_threshold.py:58`)가 쓰는 기준을 그대로 쓴다.

```
margin = max(이벤트 로짓) − 배경음 로짓
검출   = margin > THR   →  그때의 이벤트 클래스
```

**이 선택이 펌웨어를 단순하게 만든다.**

- 최종 FC 가 `wide=True`(32bit 출력)라 NPU 가 **로짓을 그대로** 내놓는다.
  검출에 필요한 것은 **뺄셈 한 번과 비교 한 번**이다. softmax(지수·나눗셈)는
  판정 경로에 **없어도 된다.**
- softmax 는 **표시용 확신도에만** 쓴다. `DEMO_BUILD` 에서만 계산하면 되고,
  `MEASURE_BUILD` 에서는 아예 빼도 판정이 동일하다 → 측정이 오염되지 않는다.
- 문턱값 `THR` 은 오프라인에서 **고정 오경보 지점**으로 정한 값을 그대로
  내려보낸다. 즉 보드의 동작점과 논문 표의 동작점이 같아진다.

⚠️ `THR` 은 모델·데이터셋마다 다르다. 펌웨어에 상수로 박지 말고
**빌드 타임 상수 + UART 로 변경 가능**하게 둔다 (G10 hop 스윕에서 재조정한다).

## 1. UART 패킷 포맷

### 1.1 왜 텍스트인가

| | 텍스트 줄 | 바이너리 |
|---|---|---|
| 대역폭 | 4프레임/s × 약 70B = **280 B/s** | 약 100 B/s |
| 115200 8N1 여유 | 11,520 B/s 중 **2.4%** | 0.9% |
| 디버깅 | 터미널에 그냥 보인다 | 파서 필요 |
| 측정 오염 | **없다** — `MEASURE_BUILD` 는 UART 자체를 끈다 | 없다 |

대역폭이 문제되지 않고, 정량 실험은 UART 를 끈 빌드로 하므로(CLAUDE.md 6장)
**디버깅 편의가 유일하게 남는 기준**이다. 텍스트로 간다.

### 1.2 공통 규칙

```
<TYPE>|<field>|<field>|...|<CK>\n
```

- ASCII, `\n`(LF) 종단, 필드 구분자 `|`
- `TYPE` 은 대문자 1글자
- `CK` 는 **줄 시작부터 마지막 `|` 직전까지**의 바이트 XOR 을 2자리 대문자
  16진수로 쓴 것. CRC 가 아니라 XOR 인 이유는 M4 에서 한 줄이고, 우리가 막으려는
  것이 전송 오류가 아니라 **줄 잘림·재동기화 실패**이기 때문이다
- 파서는 모르는 `TYPE` 과 체크섬 불일치 줄을 **버리고 계속**한다.
  부팅 중 섞여 들어오는 부트로더 출력 때문에 반드시 필요하다

### 1.3 보드 → 호스트

| TYPE | 뜻 | 필드 |
|---|---|---|
| `B` | 부팅 배너 | `fw`, `build`(MEASURE/DEMO), `model`, `path`(NPU/CPU), `thr`, `hop_ms` |
| `F` | 프레임 결과 (매 추론) | `seq`, `t_ms`, `l0..l4`(로짓 int32), `margin`, `cls`, `lat_us`, `path` |
| `E` | **병합된 이벤트** | `t_start_ms`, `cls`, `conf`(0~100), `dur_ms`, `n_frames`, `peak_margin` |
| `S` | 상태 (1초 주기) | `up_ms`, `frames`, `drops`, `path`, `vbat_mv`, `soc_pct` |
| `L` | 로그 조회 응답 | `idx`, `n`, 그리고 SD 레코드 4필드 |
| `A` | 명령 응답 | `cmd`, `ok`(0/1), `msg` |

```
B|fw=0.1.0|build=DEMO|model=safesound-fb|path=NPU|thr=16.85|hop_ms=250|3C
F|seq=1042|t_ms=260500|l=-412,88,-55,-301,120|margin=-32|cls=4|lat_us=317|path=NPU|7A
E|t=260250|cls=1|conf=87|dur_ms=1250|n=5|peak=41|1F
S|up=260500|frames=1042|drops=0|path=NPU|vbat=3812|soc=74|55
```

`F` 는 초당 4줄이라 장시간 로깅에 부담이 없다. GUI 의 실시간 막대그래프가 이걸
쓴다. `MEASURE_BUILD` 에서는 `F`·`S` 를 내지 않는다.

### 1.4 호스트 → 보드

| TYPE | 뜻 | 필드 |
|---|---|---|
| `T` | **시각 동기화** | `epoch_s`(UTC), `tz_min` |
| `P` | 추론 경로 전환 | `path`=NPU\|CPU |
| `H` | hop 변경 (G10) | `hop_ms` |
| `R` | 문턱값 변경 | `thr` |
| `Q` | 로그 조회 | `from_s`, `to_s`, `cls`(−1=전체) |
| `Z` | 로그 삭제 | `confirm=1` |

```
T|epoch_s=1790000000|tz_min=540|2B
P|path=CPU|44
```

**시각 동기화는 필수다.** RTC 가 전원 차단 시 초기화되므로(CLAUDE.md 6장),
보드는 부팅 후 `B` 를 내보내고 **`T` 를 받기 전까지 SD 레코드의 timestamp 를
`up_ms` 기준 상대값으로 적고 `synced=0` 플래그를 남긴다.** 나중에 동기화되면
그 세션의 오프셋을 한 줄로 적어 호스트가 사후 보정할 수 있게 한다.

⚠️ **오디오는 어떤 패킷으로도 나가지 않는다.** 로짓·클래스·시각만이다
(CLAUDE.md 6장 — 설계 제약이자 논문의 프라이버시 주장 근거).

## 2. SD 로그 스키마

CLAUDE.md 6장이 정한 4필드를 그대로 쓴다.

```
timestamp | class | confidence | duration
```

| 필드 | 형식 | 정의 |
|---|---|---|
| `timestamp` | ISO8601 초, 또는 `+<up_ms>` (미동기 세션) | **이벤트 시작** 시각 |
| `class` | 문자열 (`siren`/`glass`/`scream`/`dog_bark`) | 병합된 이벤트의 클래스 |
| `confidence` | 0~100 정수 | 이벤트 구간 **최대 softmax 확률**(%) |
| `duration` | 밀리초 정수 | 마지막 검출 프레임 시각 − 시작 시각 + hop |

파일은 하루 단위로 나눈다: `/events/YYYYMMDD.csv`. 헤더 한 줄 + 레코드.
세션 경계에는 주석 줄을 넣는다:

```
# boot up_ms=0 fw=0.1.0 build=DEMO model=safesound-fb thr=16.85 hop_ms=250
# timesync up_ms=8420 epoch_s=1790000000   <- 이 줄로 사후 보정한다
timestamp,class,confidence,duration
2026-10-02T14:03:21,glass,87,1250
```

### 열려 있는 문제 — `peak_margin` 을 적을 것인가

`confidence`(softmax %)는 **판정에 쓰인 값이 아니다.** 판정은 마진으로 했다
(0절). 논문에서 "배치 중 실제 동작점" 을 되짚으려면 `peak_margin` 이 필요하다.

- 4필드 스키마는 CLAUDE.md 가 정한 것이라 **임의로 늘리지 않는다.**
- UART `E` 패킷에는 이미 `peak` 를 넣어 두었으므로, 무인 구동(G7) 중 호스트가
  붙어 있으면 거기서 얻을 수 있다.
- **제안**: SD 에도 5번째 열 `peak_margin` 을 추가. G7 은 호스트 없이 8시간
  돌리는 실험이라 UART 경로가 없다 — 그때 동작점 기록이 사라진다.
  → 승인 필요 항목으로 남긴다.

## 3. 이벤트 병합 상태머신

### 3.1 왜 필요한가

초당 4회 추론이므로 3초짜리 사이렌이 **12개 레코드**로 쪼개진다
(CLAUDE.md 6장). 병합하지 않으면 SD 로그도 GUI 타임라인도 쓸 수 없다.

### 3.2 규칙

프레임마다 `(t_ms, logits)` 가 들어온다.

```
det(frame) = argmax_{c≠bg} logit[c]          if  max_{c≠bg} logit[c] − logit[bg] > THR
           = None                            otherwise
```

상태는 둘이다.

```
        det = None
        ┌──────┐
        │ IDLE │◀───────────────────── gap ≥ GAP_FRAMES  (이벤트 확정·방출)
        └──┬───┘
           │ det = c  (START_FRAMES 연속)
           ▼
     ┌───────────┐  det = c      → 연장, gap = 0
     │ ACTIVE(c) │  det = None   → gap += 1
     └───────────┘  det = c'≠c   → gap += 1, 후보 c' 기억
```

| 상수 | 기본값 | 근거 |
|---|---:|---|
| `GAP_FRAMES` | **8** (=2.0s @hop 250ms) | CLAUDE.md 6장 "N프레임(약 2초) 이상 끊기면 종료" |
| `START_FRAMES` | **1** | `glass` 는 0.3초 과도음이라 2프레임을 요구하면 통째로 놓친다. 오탐이 문제면 올린다 — **G7 측정 후 조정할 파라미터** |
| `THR` | 오프라인 고정 오경보 지점 | 0절 |

**`gap` 은 프레임 수가 아니라 시각으로 센다.** 프레임 드롭이 있으면 프레임
수와 경과 시간이 어긋나고, 그러면 드롭이 많은 조건에서 이벤트가 더 길게 이어져
G1(프레임 드롭 0) 과 G7 이 서로를 오염시킨다.

**클래스가 바뀌면 (`det = c' ≠ c`)** 이를 `c` 의 gap 으로 세고 `c'` 를 후보로
기억한다. `c` 가 닫히는 순간 `c'` 가 아직 살아 있으면 **곧바로 새 이벤트를
연다** — 사이렌 중간에 개 짖는 소리가 한 프레임 섞였다고 사이렌이 두 개로
쪼개지지 않게 하면서, 실제로 소리가 바뀌면 놓치지 않기 위해서다.

### 3.3 방출되는 레코드

| 필드 | 계산 |
|---|---|
| `t_start_ms` | 처음 검출된 프레임의 `t_ms` |
| `cls` | 이벤트 구간에서 **검출 프레임이 가장 많았던** 클래스 (동수면 peak margin 이 큰 쪽) |
| `dur_ms` | `마지막 검출 프레임 t_ms − t_start_ms + hop_ms` |
| `n_frames` | 검출 프레임 수 (gap 프레임 제외) |
| `peak_margin` | 구간 내 최대 margin |
| `conf` | 구간 내 최대 softmax 확률 (%) |

`dur_ms` 에 `hop_ms` 를 더하는 이유: 마지막 프레임도 1초 창을 본 것이므로
시각 하나로 줄이면 이벤트가 체계적으로 짧게 기록된다. hop 을 더하는 것이
**hop 스윕(G10)에서 지속시간이 hop 에 따라 달라 보이지 않게** 한다.

### 3.4 구현과 검증

- `host/eventmerge.py` — 상태머신 본체. **펌웨어 C 이식의 기준**이다.
  부동소수·동적할당·라이브러리 호출이 없도록 정수만 쓴다.
- `host/test_eventmerge.py` — 단위 테스트. 아래를 고정한다.
  1. 연속 12프레임 사이렌 → **이벤트 1개**, `dur_ms = 11*250 + 250 = 3000`
  2. 사이 1프레임 끊김 → 여전히 1개
  3. `GAP_FRAMES` 이상 끊김 → 2개
  4. 사이렌 중 1프레임 `dog_bark` → 사이렌 1개 (쪼개지지 않는다)
  5. 사이렌 → 즉시 `dog_bark` 로 전환 → 2개, 시각이 겹치지 않는다
  6. 프레임 드롭(시각 점프) → 시각 기준으로 끊긴다
  7. `THR` 미만만 있는 구간 → 이벤트 0개
- `host/fake_serial.py` — 위 프로토콜을 그대로 뱉는 더미. 보드 없이 GUI 를
  완성하기 위한 것이며, **실기기 대신 쓰는 것이 아니다** (G4 는 실측이다).

## 4. 아직 정하지 않은 것

- **GUI 레이아웃** — TASKS.md Phase 3.5 의 항목. 프로토콜이 정해졌으므로 착수 가능.
- `peak_margin` 의 SD 기록 여부 (2절 열린 문제)
- `L`/`Q` 로그 조회의 페이지네이션 — 8시간 무인 구동이면 이벤트가 수천 개일 수
  있다. 한 번에 전송하지 말고 `idx`/`n` 으로 끊는다는 것까지만 정했다.
- 부저 패턴과 LED 색 대응 — 알림 등급(즉시/기록)에 따라 다르게. 4장 클래스 표.
